📚 Nhóm Pattern 2: STACK (LIFO)
Cùng xem 3 ứng dụng khác nhau của Stack pattern:
🌐 Browser History (Back/Forward)
Mỗi trang được push vào stack. Back = pop. Forward = pop từ future stack.
↩️ Ctrl+Z (Undo)
Mỗi action được push. Undo = pop và reverse. Redo = push vào future stack.
📂 Git checkout history
Mỗi commit là 1 state. Checkout về past = navigate stack. HEAD = top of stack.
📞 Call Stack trong code
Mỗi function call push frame. Return = pop frame. Stack overflow = quá nhiều frames.
Implementation chung cho cả 4
class HistoryManager<T> { push(state: T); undo(): T; redo(): T } — Nhận ra pattern → implement 1 lần → dùng cho browser, undo, git navigation.
🗂️ Catalog Pattern phổ biến cần nhận diện
FIFOQueue
Hàng đợi, print queue, message queue, request handling, BFS traversal
LIFOStack
Undo/redo, browser history, call stack, expression evaluation, DFS traversal

SLIDING WINDOW

🎯 Key Takeaway
  • Khi bạn nhận ra "bài này giống Queue/Stack/Graph tôi từng làm" → không cần giải lại từ đầu
  • Data Structures = patterns lưu trữ. Algorithms = patterns xử lý. Học cả hai!
  • Pattern mới = pattern cũ + biến thể nhỏ. Luyện bằng cách đọc nhiều bài toán khác nhau.

🏋️ Mini Exercises

Ex 1 3 bài toán sau dùng cùng pattern gì? Giải thích. 🟢 Dễ ▶
A. Đếm số lần xuất hiện của từng từ trong đoạn văn.
B. Kiểm tra xem có user nào đăng ký email trùng không.
C. Cache kết quả API response để không gọi lại.

Ba bài toán này có cùng pattern gì? Implement chung như thế nào?
Cùng pattern: HASH MAP (key → value lookup)
// A. Word frequency const freq = new Map<string, number>() words.forEach(w => freq.set(w, (freq.get(w) ?? 0) + 1)) // B. Email dedup const emails = new Set<string>() // Set = Map với boolean value const isDuplicate = emails.has(email) // C. API Cache const cache = new Map<string, ApiResponse>() if (cache.has(key)) return cache.get(key) // else: fetch, cache.set(key, result), return result
Tất cả đều là O(1) lookup bằng key. Nhận ra pattern → chọn đúng data structure.
Ex 2 Bài toán "phụ thuộc module" dùng pattern gì? 🟡 Trung bình ▶
NestJS cần build các module theo đúng thứ tự phụ thuộc:
DatabaseModule → UserModule → AuthModule → AppModule

Module nào cần module kia phải được build trước. Đây là pattern gì? Dùng thuật toán gì?
💡 Gợi ý: Vẽ sơ đồ với module là node, dependency là edge có hướng. Đây là loại graph gì?
Pattern: Directed Acyclic Graph (DAG) + Topological Sort

Mỗi module là node. Dependency "A cần B" = edge từ A → B. Topological sort cho thứ tự build đúng.

Các bài toán khác dùng cùng pattern:
  • • npm/yarn resolve package dependencies
  • • Makefile — build targets theo thứ tự
  • • CI/CD pipeline — jobs phụ thuộc nhau
  • • Course prerequisites — môn học nào cần học trước
Nhận ra = dùng Topological Sort, không cần tự nghĩ thuật toán mới.
