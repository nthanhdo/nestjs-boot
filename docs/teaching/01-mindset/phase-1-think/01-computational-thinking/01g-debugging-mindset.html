🔬 Debugging Mindset

Debug không phải may rủi hay mò mẫm. Đó là phương pháp khoa học áp dụng cho code — có quy trình rõ ràng và có thể học được.

← Quay lại 01f: Trade-off Thinking
🔬 6 Bước Scientific Method — Click vào từng bước
1
Quan sát
Bug xảy ra khi nào? Input gì? Error message gì?
2
Giả thuyết
"Có lẽ vì... Tôi nghĩ nguyên nhân là..."
3
Thí nghiệm
Thêm log, viết test, reproduce bug
4
Kết quả
Giả thuyết đúng hay sai? Bug xác nhận?
5
Sửa
Fix root cause, không phải symptom
6
Confirm
Test lại, check regression
❌ Anti-pattern: "Debug mò" (Cargo Cult Debugging)
"Thử thay cái này xem... không được. Thử cái kia... cũng không. Thêm console.log ở đây... ở đó..."
Không có phương pháp = mất hàng giờ cho lỗi đơn giản. Không học được gì sau khi fix.
🦆 Rubber Duck Debugging
Giải thích bug cho một con vịt cao su (hoặc bất kỳ ai/thứ gì) từ đầu đến cuối. Trong quá trình giải thích, thường bạn tự tìm ra câu trả lời.
🦆 Nói với vịt
"Hàm này nhận user object, filter theo role, rồi... à đợi, tôi quên check trường hợp role là undefined rồi!"
🧠 Tại sao nó work
Bắt buộc articulate từng assumption. Khi nói ra giả định sai → não tự nhận ra sai, không cần ai chỉ.
🔍 Binary Search Debugging — Kỹ thuật nâng cao
Khi không biết bug ở đâu trong pipeline dài, chia đôi và kiểm tra điểm giữa. Nếu điểm giữa OK → bug ở nửa sau. Nếu không OK → bug ở nửa trước.
API → DB
(10 steps)
→
Check step 5
✓ OK?
→
Check step 7-8
→ bug found!
O(log n) phép kiểm tra thay vì O(n) — tương tự binary search algorithm.
🎯 Mini Quiz: Thứ tự debug đúng là gì?
User báo "app bị lỗi khi click mua hàng". Bước đầu tiên bạn làm là gì?
A. Ngay lập tức sửa hàm processPayment vì đó thường là nơi lỗi
B. Thêm console.log vào khắp nơi trong codebase
C. Reproduce bug: hỏi user "click mua hàng khi nào? sản phẩm nào? error message gì?"
D. Restart server và hy vọng nó tự hết
🎯 Key Takeaway
  • Reproduce trước — nếu không reproduce được, chưa debug được. Đừng sửa mù quáng.
  • Thay đổi 1 biến mỗi lần — không thay nhiều thứ cùng lúc, sẽ không biết cái gì fix được bug
  • Đọc error message kỹ — thường có câu trả lời ngay trong stack trace. Line number, file name.

🏋️ Mini Exercises

Ex 1 Apply scientific method cho bug: "Authentication fails intermittently" 🟡 Trung bình ▶
Bug report: "Login đôi khi thất bại — khoảng 10% thời gian, không rõ pattern". Hãy apply 6 bước Scientific Method để debug. Viết ra từng bước bạn sẽ làm.
6 bước cho intermittent auth bug:
  1. Quan sát: Thu thập logs — user nào? thời gian? device? network? Có pattern không (cùng IP, cùng user agent)?
  2. Giả thuyết: "Có lẽ do session expiry race condition" hoặc "JWT clock skew giữa servers"
  3. Thí nghiệm: Log timestamps của token tạo vs kiểm tra. Check server time sync. Load test để reproduce 10% fail rate
  4. Kết quả: Phát hiện server time lệch 2s → JWT "exp" kiểm tra sai
  5. Sửa: Thêm clock tolerance: jwt.verify(token, secret, {'{'} clockTolerance: 30 {'}'})
  6. Confirm: Deploy, monitor 24h, confirm 0% fail rate. Thêm monitoring cho clock drift
