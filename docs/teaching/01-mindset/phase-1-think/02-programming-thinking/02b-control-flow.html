🔀 Control Flow

Branching, loops, async — ba công cụ kiểm soát luồng chương trình. Dùng đúng thì code rõ ràng; dùng sai thì tạo ra mê cung không lối thoát.

🌿 Branching — if / switch / guard clause

Branching quyết định con đường nào được đi. Vấn đề là: nesting quá sâu = Pyramid of Doom.

❌ Deep nesting — khó đọc
function processOrder(order) {
  if (order) {
    if (order.userId) {
      if (order.items.length > 0) {
        if (order.total > 0) {
          // actual logic ở đây
        }
      }
    }
  }
}
✅ Guard clauses — flat & clear
function processOrder(order) {
  if (!order) throw new Error('No order')
  if (!order.userId) throw Error('No user')
  if (!order.items.length) throw Error('Empty')
  if (order.total <= 0) throw Error('Bad total')

  // actual logic — không bị indent
  return fulfill(order)
}

Switch vs Object map

// Switch — verbose
switch(status) {
  case 'pending': return '⏳'
  case 'done':    return '✅'
  case 'failed':  return '❌'
  default:        return '❓'
}
// Object map — concise
const icons = {
  pending: '⏳',
  done:    '✅',
  failed:  '❌',
}
return icons[status] ?? '❓'

🔁 Loops — Chọn Đúng Công Cụ

for...of — iterate items

for (const item of order.items) {
  await processItem(item)
}
// Dùng khi cần index hoặc async/await

.map/.filter/.reduce

const prices = items
  .filter(i => i.inStock)
  .map(i => i.price)
  .reduce((s, p) => s + p, 0)
// Dùng khi transform data

while — condition-based

let retries = 0
while (retries < 3) {
  const ok = await tryConnect()
  if (ok) break
  retries++
}

⚠️ Avoid: nested loops O(n²)

// ❌ O(n²) — dùng Map thay thế
for (const a of listA)
  for (const b of listB)
    if (a.id === b.id) ...

// ✅ O(n) với Map lookup
const bMap = new Map(listB.map(b=>[b.id,b]))

⚡ Async Control Flow

Async là control flow đặc biệt — chương trình không dừng mà "chờ" ở background. Hiểu Promise chain và parallel execution là critical.

❌ Sequential — chậm không cần thiết
// Tổng: 300ms (100+100+100)
const user = await getUser(id)     // 100ms
const orders = await getOrders(id) // 100ms
const prefs = await getPrefs(id)   // 100ms
// chúng KHÔNG phụ thuộc nhau!
✅ Parallel — 3× nhanh hơn
// Tổng: ~100ms (chạy song song)
const [user, orders, prefs] =
  await Promise.all([
    getUser(id),
    getOrders(id),
    getPrefs(id),
  ])
// Khi không phụ thuộc → dùng all()

Promise.allSettled — khi cần biết từng kết quả

const results = await Promise.allSettled([
  sendEmail(user),
  sendSMS(user),
  pushNotify(user),
])
results.forEach((r, i) => {
  if (r.status === 'rejected')
    logger.error(`Channel ${i} failed`, r.reason)
})
// allSettled: không throw khi một cái fail → log từng cái

🧠 Mini Quiz

Đoạn code sau có tổng thời gian chạy bao nhiêu nếu mỗi API call mất 200ms?

const a = await fetchA()  // 200ms
const [b, c] = await Promise.all([fetchB(), fetchC()])  // ?
const d = await fetchD(a)  // phụ thuộc a, 200ms
A. 200ms
B. 800ms
C. 600ms (200 + 200 + 200)
D. 400ms

✅ Đúng! fetchA=200ms → b+c parallel=200ms → fetchD(a)=200ms → tổng 600ms. fetchB và fetchC chạy song song nên chỉ tốn 200ms thay vì 400ms.

💡 Key Takeaway

Guard clauses thay vì nesting sâu. Dùng Promise.all() khi tasks độc lập. Chọn loop phù hợp: for...of cho async, .map/.filter cho transform, while cho retry. Mỗi công cụ có use case — không có one-size-fits-all.
