🔧 Function Design

Function là đơn vị tư duy nhỏ nhất. Thiết kế tốt = mỗi function làm đúng 1 việc, không side effect ẩn, có thể test độc lập.

🎯 Single Responsibility — Một Hàm, Một Việc

❌ Hàm làm quá nhiều
async function handleOrder(dto) {
  // Validate
  if (!dto.userId) throw Error()
  // DB write
  const order = await db.save(dto)
  // Email
  await mailer.send(order)
  // Analytics
  await analytics.track('order', order)
  return order
  // 4 trách nhiệm trong 1 hàm!
}
✅ Tách rõ trách nhiệm
async function createOrder(dto) {
  validateOrder(dto)             // 1
  const order = await saveOrder(dto)  // 2
  await Promise.all([
    sendConfirmation(order),      // 3
    trackOrderCreated(order),     // 4
  ])
  return order
  // Mỗi step = 1 named function ✓
}

📐 Nguyên Tắc Thiết Kế Hàm

Bấm để mở rộng từng nguyên tắc.

P1 Tên hàm = động từ + tân ngữ rõ ràng

Tên xấu: process(), handle(), do() — không nói lên gì.

Tên tốt: calculateShippingCost(order), sendWelcomeEmail(user), validatePaymentToken(token).

Rule: Đọc tên xong → biết output là gì, input là gì, side effect là gì.

P2 Tối đa 3 parameters — dùng object nếu hơn
// ❌ 5 params — thứ tự khó nhớ
createUser('John', 'Doe', 'john@x.com', 25, 'vn')

// ✅ Named params — self-documenting
createUser({ firstName: 'John', lastName: 'Doe',
  email: 'john@x.com', age: 25, locale: 'vn' })
P3 Return early — tránh else sau return
// ❌ Redundant else
if (isValid) { return process() }
else { return null }

// ✅ Early return
if (!isValid) return null
return process()
P4 Không có flag parameters
// ❌ Flag param — làm gì với true/false?
getProducts(true)   // true = gì?

// ✅ Tách thành 2 hàm rõ ràng
getActiveProducts()
getAllProducts()

🧊 Pure vs Impure Functions

✅ Pure — Predictable
// Same input → always same output
// No side effects
function calcDiscount(price, pct) {
  return price * (1 - pct / 100)
}

calcDiscount(100, 20) // always 80
calcDiscount(100, 20) // still 80
⚠️ Impure — Dễ gây bug
// Depends on external state
let globalRate = 0.2

function calcDiscount(price) {
  return price * (1 - globalRate)
  // kết quả thay đổi khi globalRate đổi
  // khó test, khó predict
}

Quy tắc: Maximize pure functions. Đẩy side effects (DB write, email, logging) ra edges của hệ thống — vào entry points như controller, event handler. Business logic trong core = pure.

🧱 Function Composition

Kết hợp các hàm nhỏ thành pipeline — mỗi hàm nhận output của hàm trước.

rawInput
→
parse()
→
validate()
→
transform()
→
save()
→
Response
// Pipe helper — compose left-to-right
const pipe = (...fns) => (x) => fns.reduce((v, f) => f(v), x)

const processProduct = pipe(
  parseRawData,
  validateSchema,
  normalizePrice,
  addMetadata,
)

const result = processProduct(rawInput)
// Dễ thêm/bớt bước mà không sửa logic
💡 Key Takeaway

Function tốt = làm 1 việc, tên tự mô tả, tối đa 3 params, không flag params, return early, ưu tiên pure. Đây là building blocks để compose thành hệ thống lớn mà vẫn dễ hiểu, dễ test.

Thiết kế function pipeline

  • Compose chúng thành 1 pipeline
