📦 Module & Dependency

Module là cách tổ chức code theo boundary rõ ràng. Dependency là cách các module nói chuyện với nhau. Kiến trúc tốt = low coupling, high cohesion.

📦 Module là gì?

High Cohesion

Các thứ liên quan đến nhau nằm cùng module. OrderModule chứa order controller, service, schema, DTO — không chứa user logic.

Low Coupling

Module nói chuyện với nhau qua interface/contract, không phụ thuộc implementation cụ thể. Thay đổi 1 module không làm vỡ module khác.

👤
UserModule
exports: UserService
→
🛒
OrderModule
imports: UserService
exports: OrderService
→
💳
PaymentModule
imports: OrderService

Click vào module để highlight. Dependency flows một chiều: UserModule ← OrderModule ← PaymentModule

🏗️ NestJS Module Pattern

// order.module.ts — module tự chứa mọi thứ cần
@Module({
  imports: [
    MongooseModule.forFeature([{ name: Order.name, schema: OrderSchema }]),
    UserModule,          // import UserService từ UserModule
    PaymentModule,       // import PaymentService
  ],
  controllers: [OrderController],
  providers: [OrderService, OrderRepository],
  exports: [OrderService],  // share ra ngoài nếu cần
})
export class OrderModule {}

Rule: Không circular dependency

// ❌ Circular — BAD
// OrderModule imports UserModule
// UserModule imports OrderModule
// → NestJS sẽ fail hoặc undefined
// ✅ Extract shared logic
// OrderModule imports SharedModule
// UserModule imports SharedModule
// → No circular!

💉 Dependency Injection — Đừng new() Trực Tiếp

❌ Hard-coded dependency
class OrderService {
  private mailer = new SendGridMailer()
  // Gắn chặt với SendGrid
  // Không thể test (sẽ gửi email thật)
  // Không thể swap provider
}
✅ Injected dependency
class OrderService {
  constructor(
    private readonly mailer: IMailer
    // interface, không phải class cụ thể
  ) {}
  // Test: inject MockMailer
  // Prod: inject SendGridMailer
}

🏛️ Layered Architecture

Dependency chỉ đi từ trên xuống dưới. Layer trên phụ thuộc layer dưới — không bao giờ ngược lại.

🎮 Presentation Layer Controller, Resolver, Guard, Pipe
⚙️ Application Layer Service, UseCase, DTO
🧠 Domain Layer Entity, Value Object, Domain Service
🔧 Infrastructure Layer Repository, Mailer, Queue, Cache

Quy tắc: Domain layer KHÔNG được import anything từ Infrastructure. Domain là pure business logic. Infrastructure biết Domain, không phải ngược lại. Đây là Dependency Inversion (DIP trong SOLID).

💡 Key Takeaway

Module = boundary của trách nhiệm. Dependency Injection = đừng bao giờ new() một service trực tiếp — inject interface, nhận implementation từ bên ngoài. Dependency chỉ một chiều, không circular. Layer trên phụ thuộc layer dưới, không bao giờ ngược.

🏋️ Bài Tập

Thiết kế module graph

Cho e-commerce có: User, Product, Cart, Order, Payment, Notification. Vẽ module graph với:

  • Mỗi module exports gì, imports gì
  • Không có circular dependency
  • Notification module nhận events từ Order/Payment — không import trực tiếp (gợi ý: dùng Event Emitter)
