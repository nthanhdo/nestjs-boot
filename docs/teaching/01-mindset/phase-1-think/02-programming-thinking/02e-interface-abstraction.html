🔌 Interface & Abstraction

Interface = contract. Định nghĩa cái gì trước như thế nào. Tư duy interface-first giúp tách design khỏi implementation.

🔌 Interface là gì?

Interface là một contract — cam kết rằng bất kỳ class nào implement nó đều phải cung cấp những method/property nhất định. Caller chỉ biết interface, không biết implementation cụ thể.

✍️ Interface-First Design

// Step 1: Định nghĩa interface TRƯỚC
interface INotificationService {
  sendEmail(userId: string, template: EmailTemplate): Promise<void>
  sendSMS(phone: string, message: string): Promise<void>
  sendPush(deviceToken: string, payload: PushPayload): Promise<void>
}

// Step 2: Service dùng interface, không biết implementation
class OrderService {
  constructor(private notify: INotificationService) {}

  async completeOrder(order: Order) {
    await this.notify.sendEmail(order.userId, 'order-complete')
    // OrderService không biết email được gửi bằng gì
  }
}

// Step 3: Implementation riêng
class SendGridNotificationService implements INotificationService {
  async sendEmail(userId, template) { /* SendGrid logic */ }
  async sendSMS(phone, msg) { /* Twilio logic */ }
  async sendPush(token, payload) { /* FCM logic */ }
}

🏛️ Interface vs Abstract Class

Interface — pure contract
interface IRepository<T> {
  findById(id: string): Promise<T>
  save(entity: T): Promise<T>
  delete(id: string): Promise<void>
}
// Dùng khi: chỉ cần contract
// Multiple classes implement cùng interface
Abstract Class — contract + shared logic
abstract class BaseRepository<T> {
  abstract findById(id: string): Promise<T>

  async findOrThrow(id: string) {
    const r = await this.findById(id)
    if (!r) throw new NotFoundException()
    return r  // shared logic ✓
  }
}

Rule: Dùng interface khi chỉ cần contract, nhiều implementations không liên quan. Dùng abstract class khi có shared logic cần tái sử dụng mà vẫn muốn force subclass implement abstract methods.

⚠️ Leaky Abstraction — Khi Abstraction Bị "Lộ"

❌ Leaky — expose internal details
interface IProductRepo {
  // Lộ MongoDB query syntax!
  find(filter: MongoFilterQuery): Promise<Product[]>
}
// Caller phải biết MongoDB để dùng repo
// Swap sang PostgreSQL → break mọi caller
✅ Clean — domain language only
interface IProductRepo {
  // Domain language, không có DB details
  findByCategory(cat: string): Promise<Product[]>
  findInPriceRange(min: number, max: number): Promise<Product[]>
}
// Caller không biết DB → swap DB dễ dàng
💡 Key Takeaway

Design interface trước implementation. Interface phải nói ngôn ngữ domain, không lộ implementation details (không có MongoQuery, không có HttpRequest trong repository interface). Caller chỉ biết cái gì, không biết như thế nào. Đây là core của Dependency Inversion và Testability.
