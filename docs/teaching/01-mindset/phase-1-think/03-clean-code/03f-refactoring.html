🔧 Refactoring Từng Bước

Refactoring = thay đổi cấu trúc code mà không thay đổi behavior. Làm từng bước nhỏ, test sau mỗi bước, không refactor và thêm feature cùng lúc.

📖 Refactoring Là Gì?

✅ Refactoring
  • Rename variable/function
  • Extract method
  • Move code to correct location
  • Remove duplication
  • Simplify complex condition
❌ Không phải Refactoring
  • Thêm feature mới
  • Fix bug (đổi behavior)
  • Performance optimization
  • Rewrite từ đầu

🪜 Refactor Từng Bước — Click để xem

❌ Code gốc — messy
function a(u) {
  if (!u.email || !u.email.includes('@')) return false
  if (!u.password || u.password.length < 8) return false
  db.save({ email: u.email.trim().toLowerCase(),
    password: hash(u.password), createdAt: new Date() })
  mail(u.email, 'Welcome!', '...')
  return true
}

Vấn đề: tên hàm vô nghĩa, mixed validation + DB + email, logic khó test.

🔧 Bước 1: Extract method — tách validation ra
function isValidEmail(email) {
  return !!email && email.includes('@')
}
function isValidPassword(pw) {
  return !!pw && pw.length >= 8
}
function a(u) {  // tên vẫn xấu, fix bước sau
  if (!isValidEmail(u.email)) return false
  if (!isValidPassword(u.password)) return false
  ...
}

Test mỗi hàm nhỏ riêng lẻ trước khi tiếp tục.

🏷️ Bước 2: Rename + Separate concerns
function registerUser(userData) {  // tên rõ ràng
  if (!isValidEmail(userData.email)) return false
  if (!isValidPassword(userData.password)) return false
  const user = buildUserRecord(userData)  // extract
  db.save(user)
  sendWelcomeEmail(user.email)  // extract
  return true
}

Run tests lại. Behavior không thay đổi, nhưng code đọc được hơn nhiều.

✅ Bước 3: Final — clean, readable, testable
// Mỗi hàm 1 việc, tên rõ ràng
async function registerUser(userData: CreateUserDto) {
  validateRegistrationData(userData)
  const user = await userService.create(userData)
  await mailService.sendWelcome(user)
  return user
}
// Đọc xong 4 dòng hiểu toàn bộ flow ✓

Test coverage đầy đủ, mỗi hàm nhỏ test riêng được.

📜 Quy Tắc Refactoring An Toàn

  • 🧪
    Có test coverage TRƯỚC khi refactor — tests là safety net. Không có tests → refactor mù.
  • 🪜
    Từng bước nhỏ — mỗi bước chỉ làm 1 thay đổi, test lại, rồi bước tiếp.
  • 🚫
    Không refactor + thêm feature cùng lúc — hai việc này cùng nhau = nguy hiểm. Commit riêng.
  • 💬
    Commit message rõ ràng — "refactor: extract validateRegistration()" giúp team biết không có behavior change.
  • 👀
    Code review — người khác nhìn thấy vấn đề bạn không thấy sau khi quen với code.
💡 Key Takeaway

Refactor từng bước nhỏ, test sau mỗi bước. Không thêm feature cùng lúc. Có tests trước khi refactor — đây là safety net. Commit riêng cho refactoring vs feature. "Code đọc được" > "code thông minh".
