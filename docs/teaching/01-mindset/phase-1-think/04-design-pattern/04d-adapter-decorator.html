🔌 Adapter & Decorator

Adapter: kết nối hai interfaces không tương thích. Decorator: thêm behavior mà không sửa class gốc. Cả hai bọc object để mở rộng khả năng.

🔌 Adapter — Bộ Chuyển Đổi Interface

Giống bộ chuyển đổi ổ điện khi đi nước ngoài. Cho phép hai interfaces không tương thích làm việc với nhau mà không cần sửa code gốc.

Interface mới / expected
// Thư viện bên ngoài — không sửa được
class LegacyPaymentGateway {
  processPayment(amount: number, currency: string, cardNum: string) { /* ... */ }
}

// Interface mà system của bạn expect
interface IPaymentService {
  charge(order: OrderDto): Promise<PaymentResult>
}

// Adapter: bọc Legacy, expose interface mới
class LegacyPaymentAdapter implements IPaymentService {
  constructor(private legacy: LegacyPaymentGateway) {}

  async charge(order: OrderDto): Promise<PaymentResult> {
    // Convert OrderDto → (amount, currency, cardNum)
    const result = this.legacy.processPayment(
      order.totalCents / 100,
      order.currency,
      order.card.number
    )
    return { success: result.ok, transactionId: result.id }
  }
}

📍 Real-World Adapters trong NestJS

  • Wrapping Stripe SDK → IPaymentService (swap Stripe → Braintree dễ dàng)
  • Wrapping AWS S3 → IStorageService (swap S3 → GCS không ảnh hưởng caller)
  • Wrapping Twilio → ISmsService (3rd-party SMS → unified interface)
  • Repository Adapter: Mongoose document → Domain Entity (infrastructure → domain)

🎀 Decorator — Thêm Behavior Từng Lớp

Bọc object bằng một object khác cùng interface, thêm behavior trước/sau khi delegate sang object gốc. Không sửa class gốc.

🪵 LoggingDecorator (log time + error)
↓ wraps
⚡ CachingDecorator (Redis cache)
↓ wraps
🔐 AuthDecorator (check permission)
↓ wraps
🏠 UserService (core logic)

Mỗi lớp thêm 1 concern — UserService chỉ biết business logic

interface IUserService {
  getUser(id: string): Promise<User>
}

// Core service — chỉ làm business logic
class UserService implements IUserService {
  async getUser(id: string) { return this.repo.findById(id) }
}

// Decorator thêm logging — cùng interface!
class LoggingUserService implements IUserService {
  constructor(private inner: IUserService) {}

  async getUser(id: string) {
    console.log(`[LOG] getUser(${id})`)
    const start = Date.now()
    try {
      const result = await this.inner.getUser(id)
      console.log(`[LOG] done in ${Date.now()-start}ms`)
      return result
    } catch(e) {
      console.error(`[LOG] error: ${e.message}`)
      throw e
    }
  }
}

// Compose: logging wraps caching wraps real service
const svc = new LoggingUserService(
  new CachingUserService(
    new UserService(repo)
  )
)

🎀 NestJS TypeScript Decorator ≠ GoF Decorator

TypeScript decorators (@Controller(), @Injectable(), @UseGuards()) là metadata annotations — khác với GoF Decorator pattern. Nhưng @UseInterceptors() trong NestJS chính là GoF Decorator — interceptors wrap request/response pipeline theo đúng pattern. ClassSerializerInterceptor, CacheInterceptor = decorator layers.

⚖️ Adapter vs Decorator — Khi Nào Dùng?

🔌 Adapter
  • 2 interfaces không tương thích
  • Wrapping 3rd-party library
  • Tách infrastructure khỏi domain
  • Target interface khác source
🎀 Decorator
  • Muốn thêm behavior không sửa class
  • Cùng interface, thêm cross-cutting concern
  • Logging, caching, auth, retry
  • Compose nhiều behaviors
💡 Key Takeaway

Adapter: chuyển đổi interface A → interface B — dùng khi tích hợp thư viện bên ngoài hoặc tách infrastructure. Decorator: thêm behavior vào object mà không sửa class gốc — cùng interface, bọc từng lớp. NestJS Interceptors = GoF Decorator pattern. Cả hai đều wrapping — khác ở mục đích: Adapter = compatibility, Decorator = extensibility.
