Clean & Hexagonal

Clean Architecture của Robert Martin và Hexagonal (Ports & Adapters) của Alistair Cockburn cùng một triết lý: domain logic hoàn toàn độc lập với framework, DB, UI.

Clean Architecture — Vòng tròn đồng tâm

Dependency rule tuyệt đối: code ở vòng ngoài phụ thuộc vào vòng trong, không bao giờ ngược lại. Bấm vào từng vòng:

🌐 Frameworks & DriversExpress, NestJS, MongoDB
🔌 Interface AdaptersControllers, Repositories
⚙️ Use CasesApplication Logic
🏛️ EntitiesBusiness Rules
← Bấm vào từng vòng để xem trách nhiệm.

Quy tắc vàng: phụ thuộc chỉ đi vào trong. Entity không bao giờ import NestJS hay Mongoose.

Hexagonal Architecture — Ports & Adapters

Core domain ở trung tâm, giao tiếp ra ngoài qua Ports (interfaces). Adapter implement Port — swap adapter mà không đụng core.

Core chỉ biết Port — không biết MongoDB hay Redis cụ thể là gì.

Dependency Inversion Principle (DIP)

High-level modules không phụ thuộc low-level modules — cả hai phụ thuộc vào abstractions.

❌ Service biết MongoProductRepo
class ProductService { constructor() { // hardcoded MongoDB! this.repo = new MongoProductRepo(); } }
✅ Service phụ thuộc Interface
interface IProductRepository { findById(id): Promise<Product>; } class ProductService { constructor( private repo: IProductRepository ) {} // injected! }

Kết quả: test dễ (inject MockRepo), production dùng MongoRepo. Swap PostgreSQL? Tạo PgProductRepo implements IProductRepository.

Khi nào dùng Clean / Hexagonal?

✅ Nên dùng khi:

  • • Domain phức tạp, nhiều business rules
  • • Team lớn, cần testability cao
  • • DB/framework có thể thay đổi
  • • Long-lived project (2+ năm)

⚠️ Over-engineering khi:

  • • MVP / prototype, deadline gấp
  • • Solo developer, đơn giản
  • • CRUD-heavy, ít business logic
  • • Short-lived (script, tools)

Rule: start với Layered Architecture (06a). Migrate sang Clean/Hex khi domain phức tạp lên và team cần isolation.

🛠 Bài tập — Interface Abstraction

  • 1Chọn 1 Service trong project. Tạo interface IXxxRepository với các methods cần thiết.
  • 2Rename Repository hiện tại thành MongoXxxRepository implements IXxxRepository.
  • 3Tạo MockXxxRepository implements IXxxRepository với data in-memory. Dùng cho unit test.
  • 4Verify Service không import Mongoose trực tiếp — chỉ thấy Interface type.
  • 5Câu hỏi tư duy: nếu phải switch từ MongoDB sang PostgreSQL, bao nhiêu file phải thay đổi với approach này vs approach cũ?

Key Takeaways

  • Clean Arch: dependency đi vào trong — Entity không biết Framework. Không bao giờ ngược lại.
  • Hexagonal: Core domain giao tiếp qua Ports (Interfaces). Adapter implement Port từ bên ngoài.
  • DIP: High-level modules phụ thuộc abstractions, không phụ thuộc concrete implementations.
  • Lợi ích thực tế: testability, swappability, isolation. Chi phí: nhiều code hơn, learning curve cao.
  • Start đơn giản (Layered) → evolve khi cần. Don't over-engineer MVP.
