Database Normalization

Normalization = loại bỏ data redundancy. Unnormalized data → update anomalies, delete anomalies, insert anomalies. 3NF giải quyết 95% vấn đề thực tế.

3 Loại Anomaly — Vì sao cần Normalize?

❌ Update Anomaly

Địa chỉ supplier lưu trong mỗi order row. Đổi địa chỉ phải update N rows — miss 1 row → inconsistent data.

❌ Delete Anomaly

Xóa order cuối cùng của supplier → mất luôn info của supplier (vì không có bảng riêng).

❌ Insert Anomaly

Không thể thêm supplier mới nếu chưa có order — vì supplier info chỉ nằm trong order table.

Quy tắc 3 Normal Forms

1NF — Atomic Values

Mỗi cell chứa 1 giá trị (không phải list/array). Có PK. Không có repeating groups.

2NF — No Partial Dependency

Áp dụng khi có composite PK. Mọi non-key attribute phải phụ thuộc TOÀN BỘ composite PK, không phải 1 phần.

3NF — No Transitive Dependency

Mọi attribute phụ thuộc TRỰC TIẾP vào PK. Không phụ thuộc qua non-key attribute khác (A → B → C thay vì A → C).

Khi nào Denormalize?

Normalization = tốt cho write integrity. Đôi khi cần denormalize cho read performance:

✅ Giữ normalized khi:

  • • Data thay đổi thường xuyên
  • • Write-heavy workload
  • • Data integrity quan trọng

⚠️ Denormalize khi:

  • • Read-heavy, JOIN chậm (N tables)
  • • Analytics/reporting queries
  • • MongoDB document model (embed)

🛠 Bài tập — Normalize a Table

  • 1Cho bảng sau (unnormalized): StudentCourses(studentId, studentName, courseIds, courseName, instructorName, instructorEmail). Identify violations.
  • 2Áp dụng 1NF: tách courseIds thành 1 row per course.
  • 3Áp dụng 2NF: tìm partial dependencies với composite PK (studentId, courseId).
  • 4Áp dụng 3NF: tìm transitive dependency (instructorEmail phụ thuộc instructorName, không phụ thuộc PK).
  • 5Kết quả: list các bảng sau 3NF. Verify: update instructor email → chỉ 1 row thay đổi.

Key Takeaways

  • Unnormalized data → 3 anomalies: update, delete, insert. Normalization giải quyết cả 3.
  • 1NF: atomic values, 2NF: no partial dep (composite PK), 3NF: no transitive dep.
  • 3NF giải quyết 95% vấn đề thực tế. BCNF/4NF/5NF cho edge cases phức tạp hơn.
  • Denormalize có chủ đích cho read performance — không phải "lười normalize".
  • MongoDB: embed (denormalized) khi data luôn access together, reference (normalized) khi data access độc lập.
