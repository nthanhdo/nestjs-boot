Index & Optimization

Index đúng chỗ biến query từ O(n) full scan thành O(log n) tree search. Sai chỗ → write chậm, storage bloat. Biết khi nào cần index là kỹ năng quan trọng.

Các loại Index trong MongoDB

Single Field

Index trên 1 field. Phổ biến nhất.

{ email: 1 } // 1=asc, -1=desc

Compound

Index trên nhiều fields. ESR rule: Equality → Sort → Range.

{ userId: 1, createdAt: -1 }

Unique

Enforce uniqueness. Implicit cho _id.

{ email: 1 }, { unique: true }

Sparse

Chỉ index documents có field đó. Tiết kiệm space khi field optional.

{ phoneNumber: 1 }, { sparse: true }

TTL

Auto-delete documents sau X giây. Cho sessions, caches.

{ createdAt: 1 }, { expireAfterSeconds: 3600 }

Text

Full-text search. Tokenizes, stems words.

{ name: 'text', desc: 'text' }

ESR Rule — Compound Index Order

Equality → Sort → Range. Thứ tự fields trong compound index ảnh hưởng lớn đến hiệu quả:

❌ Sai thứ tự
// Query: userId=X, date range, sort by date // Index: { createdAt:1, userId:1 } // → Không dùng index hiệu quả! // Range field trước Equality
✅ ESR Rule
// Index: { userId:1, createdAt:-1 } // Equality (userId) first // Sort/Range (createdAt) last // → Index sử dụng tối đa!

Khai báo Index trong Mongoose

// Method 1: @Prop decorator (NestJS) @Prop({ index: true }) // single field email: string; @Prop({ unique: true, sparse: true }) phoneNumber?: string; // Method 2: @Schema decorator compound index @Schema({ timestamps: true }) @Index({ userId: 1, createdAt: -1 }) // ESR: E first, S last @Index({ createdAt: 1 }, { expireAfterSeconds: 86400 }) // TTL export class Order {} // Method 3: Check existing indexes db.orders.getIndexes() // MongoDB shell db.orders.explain("executionStats").find({userId: "xxx"})

Over-Indexing — Chi phí ẩn

✅ Index giúp

  • • Query tìm kiếm (find, where)
  • • Sort operations
  • • Aggregation pipelines
  • • Enforce uniqueness

❌ Index tốn kém

  • • Disk space (index cũng chiếm dung lượng)
  • • Write operations chậm hơn (phải update index)
  • • RAM để cache index
  • • Unused indexes = pure overhead

Rule: index những field thường xuất hiện trong find(), sort(), $match. Drop indexes không dùng.

🛠 Bài tập — Index Audit

  • 1Chạy db.collection.getIndexes() trong MongoDB shell. List tất cả indexes hiện tại. Có indexes nào bạn không biết ai tạo?
  • 2Tìm 3 query chậm nhất trong app (dùng MongoDB Compass Performance Advisor hoặc explain("executionStats")). Xem COLLSCAN (full scan) chưa?
  • 3Tạo compound index cho query pattern hay dùng nhất. Apply ESR rule: Equality fields first.
  • 4Chạy lại query với explain(). Verify: IXSCAN thay vì COLLSCAN, totalDocsExamined giảm.
  • 5Thêm TTL index cho session/token collection: expireAfterSeconds: 86400.

Key Takeaways

  • Index = B-tree data structure. Search O(log n) thay vì O(n) full scan.
  • ESR Rule cho compound index: Equality fields → Sort → Range.
  • Index có chi phí: write chậm hơn, tốn disk/RAM. Chỉ index field thực sự query.
  • Dùng explain("executionStats") để verify index được dùng — IXSCAN tốt, COLLSCAN xấu.
  • TTL index = auto-expiry cho ephemeral data (sessions, OTP, caches).
