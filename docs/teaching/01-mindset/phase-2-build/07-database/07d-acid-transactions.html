ACID Transactions

Transfer tiền: trừ account A và cộng account B. Nếu server crash giữa chừng — ai chịu trách nhiệm? ACID đảm bảo data luôn nhất quán dù có lỗi.

4 Tính chất ACID — Bấm để xem chi tiết

A — Atomicity
All or Nothing
Transaction hoặc COMMIT toàn bộ hoặc ROLLBACK toàn bộ. Không có trạng thái "half-done". Ví dụ: transfer $100 gồm 2 ops (trừ A, cộng B) — nếu op 2 fail, op 1 phải được undo.
C — Consistency
Valid State Guarantee
DB chỉ chuyển từ valid state sang valid state. Constraints không bao giờ bị violated: foreign keys, unique constraints, check constraints. Nếu transaction vi phạm constraint → ROLLBACK.
I — Isolation
Concurrent Safety
Transactions chạy concurrent không interfere nhau. Isolation levels: READ_UNCOMMITTED → READ_COMMITTED → REPEATABLE_READ → SERIALIZABLE. Cao hơn = an toàn hơn nhưng chậm hơn.
D — Durability
Survive Crashes
Committed transactions được lưu bền vững — dù server crash ngay sau COMMIT. DB ghi WAL (Write-Ahead Log) trước khi commit để có thể recovery sau crash.

MongoDB Multi-Document Transactions

MongoDB hỗ trợ ACID transactions từ v4.0 (replica sets). Multi-document transactions cho operations cần atomic cross-collection:

// NestJS + Mongoose multi-document transaction async transferMoney(fromId: string, toId: string, amount: number) { const session = await this.connection.startSession(); session.startTransaction(); try { // Both ops in same session → atomic await Account.findByIdAndUpdate( fromId, { $inc: { balance: -amount } }, { session } ); await Account.findByIdAndUpdate( toId, { $inc: { balance: amount } }, { session } ); await session.commitTransaction(); } catch (err) { await session.abortTransaction(); // Rollback! throw err; } finally { session.endSession(); } }

Khi nào cần Transaction?

✅ Cần Transaction

  • 💰 Chuyển tiền, thanh toán
  • 📦 Đặt hàng + trừ tồn kho cùng lúc
  • 📝 Tạo user + assign roles + send email
  • 🔄 Bất kỳ "2+ write ops phải thành công cùng nhau"

⚠️ Không cần Transaction

  • 👁️ Read-only operations
  • ✏️ Cập nhật 1 document đơn lẻ
  • 📊 Analytics/reporting queries
  • 🗑️ Delete không cần rollback

🛠 Bài tập — Implement Transaction

  • 1Tìm trong code chỗ nào có 2+ write operations liên quan nhau mà không có transaction. Đây là bug tiềm ẩn.
  • 2Implement transfer function với MongoDB session. Test với jest.spyOn để simulate crash sau op 1.
  • 3Verify: khi crash, op 1 được rollback và balance không thay đổi.
  • 4Thêm optimistic locking: trước khi update, check version field không thay đổi → tránh concurrent update conflicts.

Key Takeaways

  • ACID: Atomicity (all or nothing), Consistency (valid states), Isolation (concurrent safety), Durability (survive crashes).
  • Transaction = nhóm nhiều operations thành 1 đơn vị atomic. Commit hoặc rollback toàn bộ.
  • MongoDB hỗ trợ multi-document transactions từ v4.0. Cần replica set.
  • Dùng try/catch/finally pattern: commitTransaction trong try, abortTransaction trong catch, endSession trong finally.
  • Transaction có chi phí (locking overhead) — chỉ dùng khi thực sự cần atomicity.
