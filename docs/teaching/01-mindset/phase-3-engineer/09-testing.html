🔬 Unit Test Anatomy: Arrange → Act → Assert

Mọi unit test tốt đều theo pattern AAA. → Bài 3: Clean testable code

1

Arrange

Setup dữ liệu đầu vào, mock dependencies

2

Act

Gọi function/method cần test

3

Assert

Kiểm tra kết quả đúng như mong đợi

// ✅ Ví dụ: Test hàm tính giá sau discount
describe('calculatePrice', () => {
  it('should apply 10% discount correctly', () => {
    // 🔵 Arrange — chuẩn bị dữ liệu
    const price = 100;
    const discountPercent = 10;

    // 🟣 Act — chạy hàm cần test
    const result = calculatePrice(price, discountPercent);

    // 🟢 Assert — kiểm tra kết quả
    expect(result).toBe(90);
  });
});

🎭 Mock vs Stub vs Spy

Khi test, ta cần cô lập unit khỏi dependencies bên ngoài (DB, API, Email...).

🎭
Mock

Thay thế hoàn toàn một object. Kiểm soát cả input và output.

Dùng khi: cần verify object được gọi đúng cách.

jest.mock('./emailService')
🔌
Stub

Trả về giá trị cố định. Không quan tâm cách gọi.

Dùng khi: cần control return value của dependency.

stub.returns({ id: 1 })
🕵️
Spy

Theo dõi real function — vẫn chạy thật nhưng ghi lại calls.

Dùng khi: muốn verify function được gọi, không thay thế.

jest.spyOn(obj, 'method')

✅ Test cái gì? Không test cái gì?

✅ NÊN test

  • Business logic (tính giá, validate rules)
  • Edge cases (số âm, chuỗi rỗng, null)
  • Error handling paths
  • Public API / interface
  • Regression (bug đã fix trước đây)

❌ KHÔNG test

  • Third-party library internals
  • Framework boilerplate
  • Private implementation details
  • Database migrations (test riêng)
  • Simple getter/setter không có logic

📊 Code Coverage — Hiểu đúng

⚠️ 80% coverage ≠ bug-free!

Coverage chỉ đo dòng code nào được chạy — không đo logic có đúng không.

// 100% coverage nhưng vẫn sai:
function add(a, b) { return a - b; } // Bug: trừ thay vì cộng!

test('add', () => {
  expect(add(5, 3)).toBe(8); // ❌ Assertion sai → test pass!
});

Ex 1 🟢 Dễ Viết 3 unit tests cho hàm calculateDiscount(price, membership)

Cho hàm: calculateDiscount(price: number, membership: 'basic' | 'premium' | 'vip'): number — trả về giá sau discount. Basic=5%, Premium=15%, VIP=30%.

Viết 3 test cases: 1 cho mỗi membership tier. Dùng Arrange-Act-Assert pattern.

👁️ Xem solution gợi ý 
describe('calculateDiscount', () => {
  it('applies 5% discount for basic membership', () => {
    // Arrange
    const price = 100;
    // Act
    const result = calculateDiscount(price, 'basic');
    // Assert
    expect(result).toBe(95);
  });

  it('applies 15% discount for premium membership', () => {
    expect(calculateDiscount(200, 'premium')).toBe(170);
  });

  it('applies 30% discount for VIP membership', () => {
    expect(calculateDiscount(100, 'vip')).toBe(70);
  });
});
Ex 2 🟢 Dễ Identify: function nào cần mock, function nào test thật?

Phân loại từng function sau — cần mock hay test thật?

function calculateTotal(items: Item[]): number  // tính tổng giỏ hàng
function sendEmail(to: string, body: string): Promise<void>
function getUserFromDB(id: string): Promise<User>
function validateEmail(email: string): boolean
function uploadToS3(file: Buffer): Promise<string>
👁️ Xem phân tích

Test thật (no mock):

  • calculateTotal — pure function, không side effect
  • validateEmail — pure function, không dependency

Cần mock:

  • sendEmail — mock EmailService, không muốn gửi email thật khi test
  • getUserFromDB — mock Repository, test DB là integration test riêng
  • uploadToS3 — mock AWS SDK, không muốn tốn tiền / rate limit
Ex 3 🟡 Trung bình Integration test: test API POST /users với database thật

Viết integration test cho endpoint POST /users sử dụng Supertest + TestContainers (MongoDB thật). Test phải verify: user được tạo trong DB, response trả về đúng schema. → Bài 8: API endpoint design

👁️ Xem structure gợi ý 
import * as request from 'supertest';

describe('POST /users (Integration)', () => {
  let app: INestApplication;
  let usersModel: Model<User>;

  beforeAll(async () => {
    // Setup: NestJS test module với MongoDB memory server
    const module = await Test.createTestingModule({
      imports: [AppModule],
    }).compile();
    app = module.createNestApplication();
    await app.init();
    usersModel = module.get(getModelToken('User'));
  });

  afterEach(async () => {
    await usersModel.deleteMany({}); // cleanup sau mỗi test
  });

  it('creates user and returns 201 with correct schema', async () => {
    const res = await request(app.getHttpServer())
      .post('/users')
      .send({ name: 'Alice', email: 'alice@example.com' })
      .expect(201);

    expect(res.body).toMatchObject({
      id: expect.any(String),
      name: 'Alice',
      email: 'alice@example.com',
    });

    // Verify in DB
    const inDb = await usersModel.findById(res.body.id);
    expect(inDb).toBeTruthy();
  });
});
Ex 4 🟡 Trung bình Edge cases: liệt kê 8 test cases cho hàm parseDate(input)

Hàm parseDate(input: string): Date nhận string, trả về Date. Liệt kê 8 test cases bao gồm happy path và edge cases. Nghĩ như QA engineer.

👁️ Xem 8 test cases
  1. Happy: "2024-01-15" → Date(2024, 0, 15)
  2. Happy: "15/01/2024" (DD/MM/YYYY format)
  3. Edge: "2024-02-29" — leap year, valid
  4. Edge: "2023-02-29" — not leap year, should throw
  5. Error: "" (empty string) → throw InvalidDateError
  6. Error: null / undefined → throw
  7. Error: "not-a-date" → throw
  8. Edge: "2024-12-31" (last day of year) → correct
Ex 5 🔴 Khó TDD: implement hàm validatePassword() theo Red→Green→Refactor

Dùng TDD để implement validatePassword(password: string): { valid: boolean; errors: string[] }. Rules: ≥8 ký tự, 1 hoa, 1 thường, 1 số, 1 ký tự đặc biệt. Viết test trước, code sau.

👁️ Xem TDD walkthrough 
// 🔴 RED: Viết tests trước
describe('validatePassword', () => {
  it('rejects passwords shorter than 8 chars', () => {
    const result = validatePassword('abc');
    expect(result.valid).toBe(false);
    expect(result.errors).toContain('Minimum 8 characters');
  });

  it('accepts valid strong password', () => {
    const result = validatePassword('Secure@123');
    expect(result.valid).toBe(true);
    expect(result.errors).toHaveLength(0);
  });
  // ... more tests
});

// 🟢 GREEN: Implement minimum để pass
function validatePassword(password: string) {
  const errors: string[] = [];
  if (password.length < 8) errors.push('Minimum 8 characters');
  if (!/[A-Z]/.test(password)) errors.push('Need uppercase');
  if (!/[a-z]/.test(password)) errors.push('Need lowercase');
  if (!/[0-9]/.test(password)) errors.push('Need digit');
  if (!/[!@#$%^&*]/.test(password)) errors.push('Need special char');
  return { valid: errors.length === 0, errors };
}
// 🔵 REFACTOR: Extract rules array, cleaner code
