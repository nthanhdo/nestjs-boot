09b · Testing

The Test Pyramid

Unit tests nhiều → Integration tests vừa → E2E tests ít. Hình tam giác này là optimal ratio — không phải ngẫu nhiên mà là kinh tế học của testing.

Interactive Pyramid — Bấm từng tầng

🌐 E2E Tests~10 tests · chậm nhất
🔗 Integration Tests~100 tests · vừa
⚡ Unit Tests~1000 tests · nhanh nhất
E2E Tests — Test toàn bộ flow từ browser đến DB và back. Dùng Playwright, Cypress.

Test gì: "User đăng ký → login → đặt hàng → nhận email xác nhận" — real browser, real DB.
Chậm vì: Spin up browser + server + DB. 1 test = 5-30 giây.
Chạy khi: CI trước deploy. Không chạy local mỗi save.
Integration Tests — Test 2+ components working together. Thường dùng test DB hoặc mocked external services.

Test gì: Controller + Service + Repository → DB. API contract (request → response shape).
Dùng: Jest + Supertest cho HTTP endpoints. In-memory MongoDB với mongodb-memory-server.
Chạy khi: CI và local khi thay đổi API/service layer.
Unit Tests — Test 1 function/class trong isolation. Tất cả dependencies được mock.

Test gì: Business logic, calculations, transformations, error handling. Pure functions.
Nhanh vì: Không có I/O. 1000 unit tests chạy <10 giây.
Chạy khi: Mỗi file save trong watch mode. Fast feedback loop.

Distribution Rule — 70/20/10

70%
Unit Tests

Nhiều nhất, nhanh nhất, isolate nhất

20%
Integration

Test component collaboration

10%
E2E

Critical paths only — login, checkout

Anti-pattern "Testing Ice Cream Cone": nhiều E2E, ít unit → CI chậm, flaky tests, hard to debug.

Mock vs Stub vs Spy

🎭 Mock

Fake hoàn toàn — thay thế dependency với object giả. Có thể assert calls.
jest.fn() / jest.mock()

🔧 Stub

Trả về data cụ thể khi được gọi. Không assert calls — chỉ control return value.
mockReturnValue('data')

👁️ Spy

Wrap real implementation — theo dõi được gọi không, với args gì, nhưng vẫn chạy thật.
jest.spyOn(obj, 'method')

Integration Test — NestJS + Supertest

// products.e2e-spec.ts describe('ProductController (e2e)', () => { let app: INestApplication; beforeAll(async () => { const module = await Test.createTestingModule({ imports: [AppModule], }).compile(); app = module.createNestApplication(); await app.init(); }); it('GET /products → returns paginated list', () => { return request(app.getHttpServer()) .get('/products?page=1&limit=10') .expect(200) .expect(res => { expect(res.body.data).toBeInstanceOf(Array); expect(res.body.meta.page).toBe(1); }); }); });

🛠 Bài tập — Identify Test Types

  • 1Review project hiện tại. Đang có bao nhiêu unit / integration / E2E tests? Tính tỷ lệ. So với 70/20/10 rule.
  • 2Chọn 1 Service method phức tạp nhất. Viết 3 unit tests: success case, edge case, error case.
  • 3Viết 1 integration test cho API endpoint hay dùng nhất dùng Supertest.
  • 4Đo CI runtime trước và sau khi add tests. Đặt mục tiêu: unit test suite chạy <30s.

Key Takeaways

  • Pyramid: Unit (70%) → Integration (20%) → E2E (10%). Bottom = nhiều, nhanh, rẻ.
  • Ice Cream Cone (ngược pyramid) = CI chậm, flaky, khó debug. Tránh.
  • Mock = fake hoàn toàn. Stub = control return value. Spy = wrap real + observe.
  • Unit test chạy <10ms/test. Integration chạy <1s/test. E2E chạy <30s/test.
  • E2E chỉ cho critical paths: login, checkout, payment. Không phải mọi feature.
