09d · Testing

Test-Driven Development

Viết test trước khi viết code. Red → Green → Refactor. Nghe điên, nhưng cho ra code design tốt hơn, coverage cao hơn, và confidence tuyệt đối khi refactor.

Red → Green → Refactor — Bấm từng pha

🔴
RED
Viết test fail
→
🟢
GREEN

🔵
REFACTOR
Clean code
🔴 RED — Viết test MÀ KHÔNG viết code implementation trước.
Test phải fail (đỏ) — nếu pass ngay, có gì sai.
Test = specification. Bạn đang định nghĩa "behavior expected" trước.
🟢 GREEN — Viết code đơn giản nhất để test pass.
Không cần clean, không cần optimal — chỉ cần test xanh.
"Make it work, then make it right." Đừng premature optimize.
🔵 REFACTOR — Cải thiện code structure mà không đổi behavior.
Extract methods, rename, simplify. Test vẫn xanh = behavior không đổi.
Đây là giai đoạn code thực sự trở nên clean.

TDD Walkthrough — Tính Discount

🔴 Step 1: Write failing test▾
it('should apply 10% discount when order >= $100', () => { const result = applyDiscount(100); expect(result).toBe(90); // ❌ FAIL — function không tồn tại });
🟢 Step 2: Minimal code to pass▾
function applyDiscount(amount: number): number { if (amount >= 100) return amount * 0.9; return amount; // ✅ PASS }
🔴 Step 3: Add more test cases▾
it('should apply 20% when order >= $500', () => { expect(applyDiscount(500)).toBe(400); // ❌ FAIL }); it('should not discount orders < $100', () => { expect(applyDiscount(50)).toBe(50); // ✅ already passes });
🟢 Step 4: Green + Refactor▾
const DISCOUNT_TIERS = [ { min: 500, rate: 0.8 }, { min: 100, rate: 0.9 }, { min: 0, rate: 1.0 }, ]; function applyDiscount(amount: number): number { const tier = DISCOUNT_TIERS.find(t => amount >= t.min)!; return amount * tier.rate; // ✅ ALL TESTS PASS + EXTENSIBLE }

TDD Benefits — Thực tế

✅ TDD cho bạn

  • • 100% coverage tự nhiên — không cần chase sau
  • • Buộc thiết kế testable API trước khi code
  • • Refactor confidence — test xanh = ok
  • • Ít bugs hơn vì edge cases được nghĩ trước

⚠️ TDD không phải cho

  • • Exploratory/prototype code
  • • UI layout/CSS (dùng visual test)
  • • Glue code đơn giản (1-line functions)
  • • Third-party integration setup

Tiếp theo: 10 — Debugging

Tests không bắt hết bugs. Khi bug xảy ra — bạn debug như thế nào có hệ thống?

10a: Debug Process →

🛠 Bài tập — TDD Kata

  • 1Bài toán: implement calculateShipping(weight, country). Trước khi code, viết 5 tests cho 5 cases khác nhau.
  • 2Chạy tests → tất cả fail (red). Verify đúng tests đang fail vì reason đúng.
  • 3Implement minimal code để pass từng test một. Commit sau mỗi green.
  • 4Refactor: extract constants, rename for clarity. Verify tests vẫn xanh sau refactor.
  • 5Retrospective: so sánh design sau TDD vs design bạn sẽ viết nếu code trước.

Key Takeaways

  • Red → Green → Refactor. Không skip bước nào. Refactor chỉ khi tests xanh.
  • TDD không phải "viết tests rồi code". Mà là tests định nghĩa design.
  • Kết quả: 100% coverage tự nhiên, code testable by design, confident refactor.
  • Không phải cho mọi thứ — prototype, UI, glue code thì skip.
  • Bắt đầu nhỏ: 1 function, 1 feature. Không TDD toàn bộ app ngay ngày 1.
