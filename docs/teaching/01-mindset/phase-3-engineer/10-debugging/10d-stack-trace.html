Reading Strategy

1. Read the error type first

TypeError, ReferenceError, ValidationError — the type tells you the category before you look at code.

2. Find YOUR code in the trace

Ignore node_modules. Your code is the first line without it. That's where to start.

3. Read top-to-bottom = last-to-first

Top = where it crashed. Bottom = where the call started. Work upward to find the root.

4. Check one frame above the crash

If line 42 crashes, often line 18 (the caller) passed bad data. Look at both.

  2. What file and line should you open first?
  3. What are you looking for on that line?
  4. If auth.service.ts:31 is return user.id; — what's the bug?
  5. What's the fix? What guard/check would prevent this?

Key Takeaways

  • Error type is a category — learn the 6 common JS error types
  • Skip node_modules frames — your bug isn't there
  • Top of trace = crash site, but root cause is often one frame up
  • Line:column is your GPS coordinate — open it immediately
  • Async stacks are truncated — use async_hooks or structured logging for full context
