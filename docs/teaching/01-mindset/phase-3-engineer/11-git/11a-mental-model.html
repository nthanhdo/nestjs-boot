Working Directory

This is your filesystem — the files you actually edit. Git sees them as "tracked" (previously committed) or "untracked" (new files).

Changes here are not saved by git yet. They're just edits on disk. If you git checkout ., all changes here disappear.

Use git status to see what's modified here vs what's staged.

Staging Area (Index)

A prep zone between your edits and your commit. You explicitly choose which changes to include: git add src/orders/order.service.ts

This lets you make 3 changes in 1 work session but commit them as 2 separate logical units — one clean commit per concern.

git diff --staged shows what's in staging, not just what's modified.

Local Repository (.git/)

Every commit you make goes here. This is a full graph database of all commits, branches, and tags — stored in .git/objects/.

Completely local. No network needed. You can commit, branch, merge, and bisect offline. Only push and fetch need the network.

git log --oneline --graph visualizes the full local history.

Remote Repository

A copy of the repo on a server (GitHub, GitLab, self-hosted). Called "origin" by default.

git push = local commits → remote. git fetch = remote commits → local (without merging). git pull = fetch + merge.

Your local and remote can diverge. git status tells you: "Your branch is 3 commits ahead of origin/main."

git add src/file.ts          # Working Dir → Staging
git add -p                   # Interactive: stage chunks, not whole files
git restore --staged file.ts # Staging → Working Dir (unstage)
git restore file.ts          # Working Dir → last committed (DESTRUCTIVE)

git commit -m "feat: ..."    # Staging → Local Repo
git push origin main         # Local Repo → Remote
git fetch origin             # Remote → Local (refs only, safe)
git pull origin main         # fetch + merge (can conflict)

Common Mistakes

❌ "I committed wrong file"

Used git add . without checking — staged and committed secrets or build artifacts.

✅ Fix

Always git status before git add. Use git add -p to review each chunk. Use .gitignore.

❌ "My changes disappeared"

Ran git checkout branch or git restore file with uncommitted changes — Working Dir wiped.

✅ Fix

Commit or git stash before switching context. git stash pop restores. Check git status first.

Key Takeaways

  • 4 areas: Working Dir → Staging → Local → Remote
  • Staging lets you craft clean, logical commits from messy work sessions
  • Local repo is full history — works offline, no network needed
  • git restore (no --staged) is destructive — it overwrites Working Dir
  • When confused: git status first, always. It tells you exactly where things are.
