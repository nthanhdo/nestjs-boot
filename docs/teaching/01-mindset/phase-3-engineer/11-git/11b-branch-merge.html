Branch & Merge

Branches isolate work. Merge and rebase integrate it. Knowing which to use — and when — is a key engineering skill.

Branch Visualization

Blue = main, Purple = feature branch, Green = merge commit. Branch at C2, work in isolation, merge back.

Merge vs Rebase

Merge
Rebase
Comparison
# Merge: creates a merge commit joining two histories
git checkout main
git merge feature/auth

# Result: both branch histories preserved
# C1 ← C2 ← C5 ← M (merge commit)
#              ↑
#         C3 ← C4 ← C5f

# Fast-forward merge (no divergence)
git merge --ff-only feature/auth
# Only works if main hasn't moved since branch point

# No-ff (always create merge commit)
git merge --no-ff feature/auth -m "Merge feature/auth"

✅ Pros: preserves full history, non-destructive, safe for shared branches
⚠️ Cons: can clutter log with many merge commits

# Rebase: replay your commits on top of target
git checkout feature/auth
git rebase main

# Result: linear history, no merge commit
# C1 ← C2 ← C5 ← C3' ← C4' ← C5f'
# (commits rewritten — new hashes)

# Interactive rebase: squash, reorder, edit commits
git rebase -i HEAD~3
# Opens editor: pick / squash / reword / drop

# 🚨 NEVER rebase shared/public branches
# Rebase rewrites history — force push needed
# Everyone else's branch diverges

✅ Pros: clean linear history, easier to bisect/read log
🚨 Cons: rewrites commits — ONLY use on your local/private branches

Rule of thumb: Rebase your own branch to stay current. Merge to integrate into shared branches. Never rebase after push — unless you own the branch alone.

🔬 Exercise — Branch Workflow

Simulate this workflow with commands:

  1. Create and switch to feature/add-product-filter from main
  2. Make 3 commits (write the commit messages)
  3. Main has moved — bring your feature branch up to date
  4. Squash your 3 commits into 1 before PR
  5. Create the final merge commit into main (no fast-forward)
  6. Delete the feature branch locally and remotely

Key Takeaways

  • Branches are cheap pointers — create one for every task
  • Merge = preserve history, safe for shared branches
  • Rebase = linear history, only on private branches
  • git rebase -i = power tool for commit cleanup before PR
  • Never force-push to main/shared branches — you'll rewrite teammates' history
