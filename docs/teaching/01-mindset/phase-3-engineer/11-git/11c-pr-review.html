PR & Code Review

Pull Requests are not bureaucracy — they're the highest-leverage quality gate in your workflow.

PR Flow — 6 Steps

Create feature branch + commits

One branch per task. Small, focused commits with clear messages. Reference the issue: git commit -m "feat(auth): add JWT refresh endpoint #123"

Push branch + open PR

Write a clear PR description: What changed? Why? How to test? Screenshots for UI. Link the issue. Assign reviewers.

CI runs automatically

Tests, lint, type-check, build. Never ask for review on a red CI. Fix it first — reviewer's time is expensive.

Reviewer provides feedback

Reviewer looks at: correctness, security, performance, readability, tests. Comments categorized by severity.

Author addresses feedback

Fix blocking issues. Reply to nitpicks. Mark conversations resolved. Push new commits — don't amend/force-push unless agreed.

Approved → Merge → Delete branch

Squash or merge. Delete the feature branch. Close the linked issue. Celebrate the shipped feature.

Review Checklist

As Reviewer — check these before approving:

Review Comment Types

src/auth/auth.service.ts
41const user = await this.userRepo.findOne(userId);
42return user.email;
Rreviewer BLOCKING

If findOne returns null (user deleted/not found), line 42 will throw TypeError: Cannot read property 'email' of null. Add a null check: if (!user) throw new NotFoundException();

src/orders/order.controller.ts
18async createOrder(@Body() body: any) {
Rreviewer BLOCKING

Never type body as any — defeats TypeScript's purpose. Create a CreateOrderDto with class-validator decorators and use ValidationPipe.

src/products/product.service.ts
55const name = product.productName;
Rreviewer NITPICK

Minor: per our naming convention, the field is name not productName (redundant prefix). Your call — blocking is overkill here.

🔬 Exercise — Write Review Comments

Review this code snippet and write 2-3 comments with severity tags:

@Post('/login')
async login(@Body() body) {
  const user = await this.db.query(
    `SELECT * FROM users WHERE email='${body.email}'`
  );
  if (user && user.password === body.password) {
    return { token: 'abc123', user };
  }
  return { error: 'Invalid credentials' };
}
  1. Identify the SQL injection vulnerability — write a BLOCKING comment
  2. Identify the password comparison issue — write a BLOCKING comment
  3. Identify the hardcoded token issue — write a BLOCKING comment
  4. What's the correct implementation? Sketch it.

Key Takeaways

  • PRs are quality gates — never ask for review on red CI
  • BLOCKING comments must be fixed before merge. NITPICK = author's call.
  • Good review comments suggest a fix — not just flag the problem
  • Reviewers: be kind but honest. "This will crash when X" is helpful, not harsh.
  • Authors: feedback is about the code, not you. Don't take it personally.
