🔬 Exercise — Version Classification

Current version: 2.3.1. For each change, determine the new version number:

  1. Add a new optional field to the POST /products response
  2. Fix a bug where DELETE /orders/:id returns 404 incorrectly
  3. Change the authentication method from API key to JWT (existing clients break)
  4. Add a new endpoint GET /products/trending
  5. Remove the GET /v1/products endpoint (deprecated 6 months ago)

Key Takeaways

  • MAJOR = breaking change (callers must update), MINOR = new feature, PATCH = bug fix
  • Conventional Commits make version bumps automatic and auditable
  • Start at 0.x.x — SemVer allows breaking changes freely. 1.0.0 = public stability promise.
  • Tags are permanent version markers: git tag -a v2.0.0 -m "Release 2.0.0"
  • Never modify a published release tag — create a new one
