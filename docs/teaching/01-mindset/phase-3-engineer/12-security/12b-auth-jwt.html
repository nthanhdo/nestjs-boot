Auth & JWT Security

Passwords, tokens, and the exact mistakes that get production systems compromised.

Password Storage — A Brief History

1990s
Plaintext passwords
Any DB breach = all passwords exposed. RockYou breach: 32M plaintext passwords.
2000s
MD5 / SHA1 hashing
Fast = bad for passwords. Rainbow tables crack MD5 in seconds. LinkedIn 2012: 6.5M MD5 hashes cracked.
2000s–2010s
Salted SHA-256
Better, but still fast. GPU can try 10B SHA-256/second. Brute force viable.
Now
bcrypt / Argon2 — slow by design
Cost factor makes it 100ms per hash. GPU has same problem. bcrypt with cost=12 = correct answer.
// ❌ Never do this
const stored = sha256(password);  // Fast, crackable
const stored = md5(password);     // Broken
const stored = password;          // Criminal

// ✅ bcrypt (NestJS example)
import * as bcrypt from 'bcrypt';
const hashed = await bcrypt.hash(password, 12);       // Store this
const valid  = await bcrypt.compare(input, hashed);   // Verify

Auth Security Checklist

🚨
Never store JWT in localStorage — XSS can steal it. Use httpOnly cookies for refresh tokens.
🚨
Short access token expiry — 15 minutes max. Long-lived tokens that can't be revoked = stolen token = persistent breach.
✅
Rate limit auth endpoints — /login, /register, /forgot-password. Max 5 attempts/minute per IP.
✅
Timing-safe comparison — Use crypto.timingSafeEqual() not === for token comparison (prevents timing attacks).
✅
Rotate secrets on breach — JWT secret rotation invalidates all tokens. Have a plan for emergency rotation.

Key Takeaways

  • Passwords: bcrypt(cost=12) minimum — never MD5/SHA1/plaintext
  • JWT payload is BASE64, not encrypted — anyone can read it
  • Access tokens: 15 min expiry. Refresh tokens: httpOnly cookie only.
  • Rate limit all auth endpoints — prevent brute force and credential stuffing
  • Never hardcode JWT secrets — use environment variables, rotate on breach
