🔬 Exercise — Design a Notification System

Apply all 10 steps to: "Design a push notification system for a social app with 10M users."

  1. Clarify scope: what types of notifications? SMS, push, email?
  2. Estimate: if 1% trigger notifications/hour, what's the QPS?
  3. Define core API: what endpoints? What does the payload look like?
  4. Draw the high-level components (ingest → queue → dispatcher → delivery)
  5. Identify the single biggest bottleneck — where would it break first at scale?
  6. How do you handle delivery failures and retries?

Key Takeaways

  • Never jump to solutions — clarify requirements first. 10 min of clarification saves hours of wrong design.
  • Estimate before designing — numbers determine which architecture is needed
  • Start with a working monolith design, then add complexity only where justified
  • Identify bottlenecks explicitly — "this DB will hit its limit at X QPS, so..."
  • There is no single right answer — trade-offs are the answer
