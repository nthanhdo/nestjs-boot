1. DevOps là gì?

DevOps = Development + Operations. Không chỉ là tool, mà là văn hóa và quy trình — phá bỏ bức tường giữa team viết code và team vận hành. Đây là kỹ năng thiết yếu để đưa code từ máy local đến system production đã thiết kế ở Bài 13.

Tại sao cần DevOps? Trước đây: Dev viết code → đưa qua cho Ops → Ops than phiền "code này không chạy được trên server". DevOps xóa bỏ câu "works on my machine" bằng cách tự động hóa toàn bộ pipeline.

4. Dockerfile — Multi-stage Build

Key Takeaway: DevOps không phải về tools — mà về culture of automation. Bất cứ thứ gì làm tay nhiều hơn 2 lần → tự động hóa nó.
🎯 Bài Tập Thực Hành
🟢 Dễ Bài 1
Viết Dockerfile multi-stage cho Node.js app
Tạo một Dockerfile với 2 stage: builder (compile TypeScript) và runner (chỉ chứa dist + node_modules). Verify image size nhỏ hơn single-stage.
Gợi ý:
1. Stage 1 AS builder: FROM node:20-alpine, COPY package*.json, RUN npm ci, COPY . ., RUN npm run build
2. Stage 2 AS runner: FROM node:20-alpine, COPY --from=builder /app/dist, COPY --from=builder /app/node_modules
3. Kiểm tra: docker build -t myapp . && docker images myapp — so sánh size
4. Single-stage thường ~400MB, multi-stage ~80–120MB
🟢 Dễ Bài 2
Viết docker-compose.yml: app + MongoDB + Redis
Tạo file compose cho NestJS app với MongoDB và Redis. App phải kết nối được cả hai service. Chạy docker-compose up và verify app healthy.
Gợi ý:
1. services: app (build: .), mongo (image: mongo:7), redis (image: redis:7-alpine)
2. app depends_on: [mongo, redis]
3. Env vars: MONGO_URI=mongodb://mongo:27017/db, REDIS_URL=redis://redis:6379
4. volumes: mongo_data:/data/db để persist data
5. Test: docker-compose up -d && curl localhost:3000/health
🟡 Trung bình Bài 3
GitHub Actions: CI pipeline (install → lint → test → build)
Tạo .github/workflows/ci.yml trigger khi push vào bất kỳ branch. Pipeline: checkout → setup node → npm ci → lint → test → build. Pipeline phải green.
Gợi ý:
on: push: branches: ['**'] — trigger mọi branch
steps: actions/checkout@v4 → actions/setup-node@v4 (node-version: '20') → npm ci → npm run lint → npm test → npm run build
Thêm cache: actions/cache@v3 với key: node-modules-${{ hashFiles('package-lock.json') }}
Verify: Push lên GitHub → Actions tab → xem pipeline chạy
🟡 Trung bình Bài 4
Debugging deploy: container crash → đọc logs → fix
Cố tình tạo lỗi trong app (ví dụ: sai MONGO_URI). Build Docker image, chạy container, quan sát crash. Dùng docker logs để tìm nguyên nhân và fix.
Workflow debug:
1. docker-compose up -d → app exit
2. docker-compose ps → xem status
3. docker-compose logs app → đọc error message
4. Common errors: MongoServerError (sai URI), ECONNREFUSED (service chưa ready → thêm healthcheck + depends_on condition)
5. Fix → docker-compose down && docker-compose up -d --build
🔴 Khó Bài 5
Full pipeline: push code → CI green → Docker build → deploy → health check
Xây dựng pipeline đầu đủ: code thay đổi → CI chạy tests → build Docker image → push lên registry → SSH vào server (hoặc dùng Railway/Render) → pull image mới → verify /health trả 200.
Các bước chính:
1. Tạo account Docker Hub (free), lưu credentials vào GitHub Secrets
2. Workflow: test job → nếu pass → build-push job (docker/login-action + docker/build-push-action)
3. Deploy step: ssh-action để chạy docker pull + docker-compose up -d trên VPS, hoặc dùng Render/Railway webhook
4. Verify: curl https://your-app.com/health → phải trả {"status":"ok"}
5. Bonus: thêm Slack/Discord notification khi deploy fail

📌 Tóm Tắt Bài 14

  • DevOps = culture + automation, không chỉ tools
  • Docker = đóng gói app nhất quán (không còn "works on my machine")
  • Multi-stage build = image nhỏ hơn, bảo mật hơn, deploy nhanh hơn
  • Docker Compose = orchestrate multi-service local stack
  • CI/CD = tự động hóa toàn bộ pipeline từ push đến production
  • Environment management = secrets trong env vars, không trong code
  • Monitoring = /health endpoint + metrics là must-have của production app
