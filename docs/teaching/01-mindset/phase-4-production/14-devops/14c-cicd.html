CI/CD Pipeline

Continuous Integration + Continuous Deployment với GitHub Actions — từ git push đến production tự động, không sai, không quên.

1. CI vs CD — Khái Niệm

CI — Continuous Integration

Merge code thường xuyên (ít nhất 1 lần/ngày). Mỗi merge → tự động build + test. Phát hiện conflict và bug sớm, trước khi vào main branch.

Trigger: mọi push, mọi PR

CD — Continuous Deployment

Sau khi CI pass → tự động deploy lên environment (staging hoặc production). Không cần manual step. Code review approved → live trong vài phút.

Trigger: merge vào main branch

3. GitHub Actions — CI Workflow

File .github/workflows/ci.yml — chạy trên mọi push và PR.

name: CI on: push: branches: ['**'] # trigger mọi branch pull_request: branches: [main] jobs: ci: runs-on: ubuntu-latest steps: # Step 1: Checkout code - uses: actions/checkout@v4 # Step 2: Setup Node with cache - uses: actions/setup-node@v4 with: node-version: '20' cache: 'npm' # cache node_modules # Step 3: Install deps - name: Install dependencies run: npm ci # Step 4: Lint - name: Lint run: npm run lint # Step 5: Type check - name: Type check run: npx tsc --noEmit # Step 6: Test - name: Run tests run: npm test -- --coverage # Step 7: Build - name: Build run: npm run build

4. CD Workflow — Deploy Sau Khi CI Pass

File .github/workflows/deploy.yml — chỉ chạy khi push vào main và CI đã green.

name: Deploy on: push: branches: [main] jobs: deploy: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 # Build & push Docker image - name: Login to Docker Hub uses: docker/login-action@v3 with: username: ${{ secrets.DOCKER_USERNAME }} password: ${{ secrets.DOCKER_TOKEN }} - name: Build and push uses: docker/build-push-action@v5 with: push: true tags: myuser/myapp:${{ github.sha }},myuser/myapp:latest # Deploy to server via SSH - name: Deploy to VPS uses: appleboy/ssh-action@v1 with: host: ${{ secrets.VPS_HOST }} username: ${{ secrets.VPS_USER }} key: ${{ secrets.VPS_SSH_KEY }} script: | docker pull myuser/myapp:${{ github.sha }} docker compose up -d --no-deps app docker image prune -f

5. Secrets Management

Secrets KHÔNG bao giờ hardcode vào workflow files. GitHub Secrets là nơi lưu trữ an toàn.

Cách thêm secret vào GitHub

Settings → Secrets and variables → Actions → New repository secret

Secret cần có:
  • DOCKER_USERNAME
  • DOCKER_TOKEN (access token)
  • VPS_HOST (IP hoặc domain)
  • VPS_USER
  • VPS_SSH_KEY (private key)
Dùng trong workflow:
${{ secrets.DOCKER_USERNAME }} ${{ secrets.VPS_HOST }} # Never in logs!
Pro tip: Dùng github.sha làm image tag thay vì latest — mỗi commit có image riêng, dễ rollback về commit cụ thể.
Bài Tập Thực Hành
Dễ Bài 1
Tạo CI workflow: install → lint → test → build
Tạo .github/workflows/ci.yml trigger khi push vào bất kỳ branch. Pipeline phải green trên GitHub Actions.
on: push: branches: ['**']
steps: checkout → setup-node (cache: npm) → npm ci → npm run lint → npm test → npm run build
Thêm cache để build nhanh hơn
Verify: Push lên GitHub → Actions tab → xem pipeline
Trung bình Bài 2
Thêm test coverage report vào CI
Modify CI workflow để upload coverage report sau khi test. Sử dụng actions/upload-artifact để save coverage HTML report. Verify có thể download từ Actions run.
Thêm sau step test:
- uses: actions/upload-artifact@v4
with: { name: coverage, path: coverage/ }

Jest config: --coverage --coverageReporters=html,text
Verify: Run → Summary → Artifacts → download coverage.zip
Khó Bài 3
Full pipeline: CI → Docker build/push → deploy → health check
Xây dựng pipeline đầy đủ: code push → CI test → Docker build → push Docker Hub → deploy lên Railway/Render (hoặc VPS) → verify /health trả 200.
1. CI job (test + build)
2. deploy job: needs: [ci] — chỉ chạy nếu CI pass
3. Docker Hub: docker/login-action + docker/build-push-action
4. Railway: webhook URL trong secret → curl -X POST ${{ secrets.RAILWAY_WEBHOOK }}
5. Verify step: curl https://your-app.up.railway.app/health → expect 200

Nếu dùng VPS: appleboy/ssh-action → docker pull + docker compose up -d

Key Takeaway — 14c

CI = test sớm, fail nhanh. CD = deploy tự động khi code tốt. GitHub Actions: event triggers → jobs → steps. Secrets = không bao giờ hardcode. github.sha = versioning đúng cách cho Docker images.
