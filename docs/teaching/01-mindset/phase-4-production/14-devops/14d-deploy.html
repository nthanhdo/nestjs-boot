Deploy Strategies

Rolling, Blue-Green, Canary — mỗi strategy phù hợp với risk profile khác nhau. Chọn đúng = zero downtime, rollback nhanh, user không biết gì xảy ra.

3. Environment Pipeline

Code không bao giờ đi thẳng từ local lên production. Phải qua staging để validate trước.

Dev
localhost:3000
Hot reload, debug mode, local MongoDB/Redis. Chỉ developer thấy.
Staging
staging.app.com — Mirror production
Giống production 99%: cùng Docker image, cùng config (với test data). QA team test ở đây trước khi approve production deploy.
Prod
app.com — Real users
Chỉ deploy khi staging pass. Monitor 24h sau deploy. On-call nếu error rate tăng.

Bài Tập Thực Hành
Dễ Bài 1
Implement /health endpoint với DB connectivity check
Tạo GET /health endpoint trong NestJS. Response phải include: status, db connection status, timestamp, version, uptime. Return 503 nếu DB down.
Dùng @nestjs/terminus (official health check library)
npm install @nestjs/terminus
HealthModule: MongooseHealthIndicator, MemoryHealthIndicator
Trả HttpStatus.SERVICE_UNAVAILABLE nếu any check fail
Test: docker compose stop mongo && curl localhost:3000/health → phải 503
Trung bình Bài 2
Simulate Blue-Green deploy với Docker
Chạy v1 trên port 3000. Build v2. Chạy v2 trên port 3001. Kiểm tra v2 healthy. "Switch" bằng cách update nginx upstream config. Verify zero-downtime bằng cách loop curl trong khi switch.
1. docker run -d -p 3000:3000 myapp:v1 --name blue
2. docker run -d -p 3001:3000 myapp:v2 --name green
3. Test green: curl localhost:3001/health
4. Loop test: while true; do curl -s localhost:80/health | jq .version; sleep 0.5; done
5. Update nginx: upstream port 3000 → 3001 + nginx -s reload
6. Verify: version changes trong loop, không có error
Khó Bài 3
Viết Rollback plan cho production deploy
Cho một NestJS app đang chạy version 1.5.0. Viết rollback plan đầy đủ cho deploy v1.6.0: trigger conditions, rollback steps (commands), time estimate, verification sau rollback, communication plan.
Trigger conditions: error rate > 1%, P95 latency > 2s, health check 503

Rollback steps:
1. docker pull myapp:1.5.0 (pre-pulled trước deploy)
2. docker compose stop app
3. docker compose up -d --no-deps --build app (với image cũ)
4. curl /health → verify 200
5. Check error rate về baseline
Time estimate: 3-5 phút

Post-rollback: announce trong team channel, create incident ticket, root cause analysis

Key Takeaway — 14d

Rolling = đơn giản, Blue-Green = safe rollback, Canary = risk-minimal. Staging environment là bắt buộc. /health endpoint = litmus test của production. Rollback plan phải viết trước khi deploy, không phải sau khi có incident.
