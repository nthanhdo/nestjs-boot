3. Prompting for Code — Good vs Bad

Chất lượng prompt quyết định chất lượng output. Prompt tốt = áp dụng tư duy Clean Code vào communication với AI.

❌ Prompt tệ
Write a function to handle users
→ AI đoán mò, tạo ra code generic, không fit codebase.
✓ Prompt tốt
I'm using NestJS + TypeORM + PostgreSQL. Create a UserService method: - Input: CreateUserDto { email, name, role } - Check email duplicate → throw ConflictException - Hash password with bcrypt (10 rounds) - Return UserEntity (exclude password field) - Add JSDoc comments
→ AI có đủ context để tạo code chính xác, fit stack.

5. Hallucination — AI Tự Tin Sai

AI có thể generate code trông đúng nhưng sai. Đây là lý do testing không thể skip.

// AI generates this confidently... ❌ import { validateEmail } from '@nestjs/common/utils/email'; ✗ không tồn tại await collection.insert(doc); ✗ deprecated từ MongoDB 4 throw new HttpException('Not found', 401); ✗ nên là 404 // Developer catches it, fixes it ✅ import { isEmail } from 'class-validator'; ✓ correct await collection.insertOne(doc); ✓ current API throw new NotFoundException('Resource'); ✓ 404
Hallucination phổ biến nhất: Package names không tồn tại, deprecated API, wrong method signatures, outdated syntax, logic bugs trong edge cases.

6. AI-generated Security Risks

AI có thể suggest code chạy được nhưng không secure. Kỹ năng từ Clean Code giúp nhận ra code smells.

❌ AI suggests — SQL Injection
// "Works" but dangerous! const query = `SELECT * FROM users WHERE email = '${email}'`; // Attacker: email = "' OR '1'='1" → dumps entire DB
✓ Correct — Parameterized
// Safe! Parameters escaped const result = await db.query( 'SELECT * FROM users WHERE email = $1', [email] );

Security checklist khi dùng AI-generated code

  • 🔍SQL/NoSQL queries — dùng parameterized hay ORM, không string concat
  • 🔍Password — bcrypt/argon2, không MD5/SHA1 plain
  • 🔍JWT secret — environment variable, không hardcoded
  • 🔍Input validation — validate mọi user input trước khi process
  • 🔍Error messages — không expose internal details cho user
  • 🔍Dependencies — check CVE của package được suggest

7. Context Engineering

// ✓ Đủ context — AI tạo code fit "I'm building a NestJS microservice. Existing code uses MongoDB + Mongoose, CQRS pattern, class-validator DTOs. Create OrderCommandService.createOrder(dto: CreateOrderDto): - Validate items array non-empty - Emit OrderCreatedEvent after save - Return OrderDocument"
Pro tip: Paste đoạn code hiện có vào prompt làm reference pattern — AI sẽ copy style, naming, error handling của bạn.

8. The Verification Loop

Never Trust, Always Verify. Viết test (Bài 9) là cách verify hiệu quả nhất.

  • ①Understand: Đọc và hiểu từng dòng code AI generate
  • ②Test: Chạy với input thực, test edge cases, check logs
  • ③Verify: Kết quả có đúng với requirements không?
  • ④Review: Security, performance, maintainability

9. The Right Mindset

✅ "Productivity tool with guardrails"

  • Dùng AI để accelerate — tạo boilerplate, explain concepts, suggest patterns
  • Luôn review và adapt code vào codebase của mình
  • Test kỹ trước khi commit — Bài 9
  • Chịu trách nhiệm 100% với code mình commit, dù AI viết

❌ Anti-pattern: Blindly Accept AI Output

  • Copy-paste AI code mà không đọc → bugs vào production
  • Dùng AI giải quyết bug mà không hiểu root cause → bug tái phát
  • Để AI quyết định architecture → technical debt khổng lồ
  • Nói "AI generate" khi bị hỏi về code → không chuyên nghiệp
Key Takeaway: Kỹ sư dùng AI giỏi nhất = người biết khi nào dùng, khi nào không, và luôn verify output.
🎯 Bài Tập Thực Hành
🟢 DễBài 1
Viết 3 prompts tốt vs 3 prompts tệ cho cùng 1 task
Chọn task "tạo endpoint reset password". Viết 3 prompt vague và 3 prompt đầy đủ context. So sánh chất lượng output từ Claude/GPT và ghi lại sự khác biệt.
Prompts tệ: "Add reset password", "Handle forgot password", "Email user"

Prompt tốt mẫu: "NestJS + Nodemailer. Create POST /auth/forgot-password: input {email}, find user by email, generate 6-digit OTP, store in Redis TTL 15min, send via nodemailer, return {message: 'OTP sent'}. Throw NotFoundException if email not found."

Kết quả: prompt tốt → code fit stack, ít sửa, naming match pattern codebase
🟢 DễBài 2
Review AI-generated code: tìm 3 vấn đề trong output
Prompt AI tạo một UserService (createUser, findAll, deleteUser). Review output và liệt kê ít nhất 3 vấn đề: security holes, missing validation, no error handling, v.v.
Vấn đề thường gặp:
1. Password không được hash (plain text lưu DB)
2. findAll() không có pagination → memory leak
3. deleteUser không check ownership
4. Không throw NotFoundException đúng loại
5. Missing @IsEmail() validation trong DTO
🟡 Trung bìnhBài 3
Dùng AI generate function → viết test verify → fix nếu sai
Prompt AI tạo function tính discount (VIP -20%, weekend +10%, min price $5). Viết unit tests bao phủ các cases. Nếu test fail → AI code sai → fix và re-run.
Test cases cần viết:
- VIP weekday → -20%
- Regular weekend → +10%
- VIP weekend → ưu tiên rule nào? (AI có thể đoán sai)
- Price sau discount < $5 → return $5
- Input = 0 hoặc negative → edge case

AI thường fail case "VIP + weekend" và "min price floor"
🟡 Trung bìnhBài 4
Refactor with AI: cho code messy, prompt AI refactor, review output
Viết code messy (vars a/b/c, no validation, deeply nested ifs). Prompt AI refactor theo Clean Code. Review: AI có thực sự improve hay chỉ rename?
Prompt tốt: "Refactor theo Clean Code: meaningful names, single responsibility, early return, no magic numbers. Giữ nguyên logic."

Checklist review:
✓ Variable names descriptive?
✓ Nested ifs → guard clauses?
✓ Magic numbers → constants?
✗ AI thường quên extract helper functions, giữ lại dead code
🔴 KhóBài 5
AI security audit: phát hiện SQL injection trong AI-generated code
Prompt AI tạo search endpoint GET /products?q=laptop với raw SQL. Tìm SQL injection vulnerability. Viết exploit proof-of-concept. Fix bằng parameterized query. Verify fix bằng test.
Bước 1: AI generate WHERE name LIKE '%${q}%' → vulnerable
Bước 2 exploit: q = "' OR '1'='1' --" → return all rows
Bước 3 fix: WHERE name LIKE $1 với param [`%${q}%`]
Bước 4 test: Unit test verify special chars không return extra rows

Bonus: tìm thêm NoSQL injection nếu dùng MongoDB

📌 Tóm Tắt Bài 15

  • AI = tool, không phải replacement. Engineer giỏi = biết dùng AI đúng cách
  • Prompt quality quyết định output quality. Stack + input/output + constraints = formula
  • Hallucination là thật. Verify mọi package, API, logic trước khi dùng
  • Security risks — AI code "chạy được" ≠ "secure". Luôn review security checklist
  • Verification loop: Understand → Test → Verify → Review — không bao giờ skip
  • Code ownership — bạn chịu 100% trách nhiệm dù AI viết
