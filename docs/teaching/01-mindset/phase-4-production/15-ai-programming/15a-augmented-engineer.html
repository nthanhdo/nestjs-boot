Phase 4 15a

AI = Tool, Không Phải Replacement

Engineer + AI = 10x output. Nhưng chỉ khi engineer hiểu AI làm được gì, không làm được gì, và luôn verify output.

1. The Augmented Engineer

AI không thay thế kỹ sư — nó amplify kỹ năng của kỹ sư. Nền tảng thinking và judgment của bạn quyết định bạn có review được AI output hay không.

Core insight: Người dùng AI tốt nhất là người biết khi nào dùng, khi nào không, và luôn verify output. AI giỏi thật ra cần engineer giỏi hơn, không ít hơn.

3. Code Generation Workflow

AI generate → Developer là người sở hữu và chịu trách nhiệm. Không bao giờ skip bước verify.

1
AI Generates Draft
Cung cấp context đầy đủ (stack, types, constraints) → AI tạo draft code
🤖 AI làm
2
Developer Reads & Understands
Đọc từng dòng — hiểu logic, không chỉ "nó chạy được"
👨‍💻 Dev làm
3
Code Review
Kiểm tra: security, edge cases, performance, style fit codebase
🔍 Dev + AI iterate
4
Adapt to Codebase
Sửa naming, integrate với existing patterns, conventions
👨‍💻 Dev làm
5
Test Thoroughly
Unit tests, edge cases, integration — AI code phải pass cùng test bar như human code
👨‍💻 Dev chịu trách nhiệm
6
Own the Code
Commit, document, maintain. "AI generated" không là lý do để không hiểu code
👨‍💻 Dev owns 100%

4. Mindset Check

✅ Engineer Mindset (đúng)

  • "AI accelerate tôi, không replace judgment của tôi"
  • "Tôi review mọi dòng code AI generate trước khi commit"
  • "Nếu tôi không hiểu code này, tôi không commit nó"
  • "AI là starting point, không phải final answer"

❌ Anti-patterns (tránh)

  • Copy-paste AI code mà không đọc → bugs vào production
  • Dùng AI giải quyết bug mà không hiểu root cause → bug tái phát
  • Để AI quyết định architecture → technical debt khổng lồ
  • Nói "AI generate" khi bị hỏi về code → không chuyên nghiệp
Bài Tập Thực Hành
Dễ Bài 1
Phân tích: AI làm được / không làm được gì trong project của bạn
List 5 tasks trong project hiện tại. Classify mỗi task: AI tốt / AI trung bình / AI không phù hợp. Giải thích lý do cho mỗi classification.
Framework:
AI tốt: task rõ ràng, patterns đã biết, không cần domain context (CRUD, regex, boilerplate)
AI trung bình: cần review kỹ, có thể miss edge cases (refactoring, explain complex code)
AI không phù hợp: cần business context, security-critical, architecture decisions

Lý do quan trọng hơn classification — "tại sao" mới giúp bạn dùng AI đúng cách
Trung bình Bài 2
Follow the 6-step workflow với một real task
Chọn một task thực (ví dụ: tạo UserService method). Follow đúng 6 bước. Document mỗi bước: AI output là gì, bạn thay đổi gì, tại sao. Measure: % code cuối cùng giữ nguyên từ AI.
Typical result: ~60-70% code AI generate được giữ lại sau review
Thay đổi phổ biến: naming theo codebase conventions, thêm validation, fix error codes, thêm logging
Điều quan trọng: bạn phải hiểu 100% code cuối cùng, kể cả phần AI viết không thay đổi

Key Takeaway — 15a

AI = công cụ amplify, không replace. Engineer giỏi = biết dùng AI đúng chỗ + verify mọi output. 6-step workflow: Generate → Read → Review → Adapt → Test → Own. Code ownership là của developer, không phải AI.
