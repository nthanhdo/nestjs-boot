Prompting for Code

Chất lượng prompt = chất lượng output. Một prompt tốt tiết kiệm 80% thời gian review và fix. Một prompt tệ tạo ra code rác trông có vẻ đúng.

1. Good vs Bad Prompts

Cùng một task — prompt khác nhau → kết quả khác nhau hoàn toàn.

❌ Prompt tệ
Write a function to handle users
→ AI đoán mò về stack, naming, logic. Output generic, không fit codebase.
✓ Prompt tốt
I'm using NestJS + Mongoose + MongoDB. Create UserService.createUser method: - Input: CreateUserDto { email, name, role } - Check email duplicate → throw ConflictException - Hash password with bcrypt (10 rounds) - Return UserEntity (exclude password field) - Add JSDoc comments - Follow existing pattern in OrderService
→ AI có đủ context để tạo code fit stack, error handling đúng, naming match conventions.
❌ Prompt tệ — Fix bug
Fix this bug
→ AI không biết bug là gì, context gì.
✓ Prompt tốt — Fix bug
NestJS + Mongoose. This code throws: "MongoError: E11000 duplicate key" when user tries to register with existing email. Current code: [paste OrderService.create here] Expected: throw ConflictException with message "Email already exists" Not expected: crash 500
→ AI fix đúng loại lỗi, đúng exception type, không over-engineer.

2. Formula của Prompt Code Tốt

5 layers context — critical first, helpful last.

🏗️
Stack / Framework
NestJS, TypeScript, Mongoose, MongoDB. Version nếu quan trọng.
Critical
📥
Input / Output
Interface types cụ thể, return type, error scenarios.
Critical
⚙️
Constraints
Error handling expectations, performance requirements, security rules.
Critical
🎨
Style / Pattern
Naming conventions, code style. Reference existing code của codebase.
Helpful
📝
Examples
Paste existing code làm reference. AI sẽ copy style, pattern của bạn.
Helpful

3. Context Engineering — Paste Code Cũ

Pro tip: đừng chỉ mô tả bằng lời — paste code hiện có làm reference pattern.

"I'm building a NestJS microservice. Existing code uses MongoDB + Mongoose, CQRS pattern, class-validator DTOs. Here's existing ProductService.create for reference: [paste ProductService.create here] Create OrderCommandService.createOrder(dto: CreateOrderDto): - Same patterns as ProductService.create above - Validate items array non-empty (throw BadRequestException) - Calculate total from items - Emit OrderCreatedEvent after save - Return OrderDocument"
Pro technique: Paste đoạn code hiện có vào prompt làm reference — AI sẽ copy style, naming, error handling của bạn. Kết quả: code AI tạo ra trông như chính bạn viết.

4. Iterative Prompting — Khi Output Chưa Đúng

Không phải lúc nào prompt đầu tiên cũng đủ. Iterate conversation thay vì start-over.

Iterative pattern

Round 1 prompt:
Create UserService.updateProfile [basic context]
AI output — gần đúng nhưng thiếu:
Thiếu validation cho phone number format, không log update event
Round 2 — refine:
"Good start. Two additions: (1) validate phone with regex /^\+[1-9]\d{7,14}$/, throw BadRequestException if invalid. (2) After save, emit UserUpdatedEvent via EventEmitter2"
Bài Tập Thực Hành
Dễ Bài 1
Viết 3 prompts tốt vs 3 prompts tệ cho cùng 1 task
Chọn task "tạo endpoint reset password". Viết 3 prompt vague và 3 prompt đầy đủ context. So sánh chất lượng AI output và ghi lại sự khác biệt.
Prompts tệ: "Add reset password", "Handle forgot password", "Email user"

Prompt tốt mẫu:
"NestJS + Nodemailer. Create POST /auth/forgot-password:
- Input: { email: string }
- Find user by email → NotFoundException if not found
- Generate 6-digit OTP
- Store in Redis key=reset:${email}, TTL=15min
- Send via nodemailer to email
- Return { message: 'OTP sent' }"

Kết quả: prompt tốt → code fit stack, ít sửa, naming match pattern codebase
Trung bình Bài 2
Iterate prompt: từ generic output đến codebase-fit output
Bắt đầu với prompt ngắn. Nhận output. Identify 3+ điểm không fit codebase (naming, error types, patterns). Viết round 2 prompt. Measure improvement.
Điểm thường không fit:
1. Error types: generic Error() thay vì NotFoundException, ConflictException
2. Naming: camelCase đôi khi nhất quán, snake_case xuất hiện
3. Patterns: return raw data thay vì transformed DTO
4. Missing: logging, event emission theo codebase pattern

Round 2: "Good but fix: (1) use NotFoundException not Error, (2) rename x → y to match naming convention, (3) return via toResponseDto() like other methods"

Key Takeaway — 15b

Prompt = communication skill. Stack + Input/Output + Constraints = minimum context. Paste existing code làm reference = AI copy style của bạn. Iterate, đừng start-over. Chất lượng output phụ thuộc 80% vào prompt quality, 20% vào AI model.
