🔐 AI-Generated Security Risks

AI code "chạy được" ≠ "secure". Phần này teach bạn nhận diện và fix 6 loại lỗ hổng phổ biến nhất trong AI-generated code.

⚠️ Reality check: Khảo sát GitHub Copilot 2023 — 40% code AI generate trong security-sensitive contexts chứa ít nhất 1 vulnerability. AI được train trên internet code — bao gồm cả code xấu.

🎯 6 Risk Categories

1. SQL / NoSQL Injection
String concatenation thay vì parameterized queries. Attacker kiểm soát được query logic.
2. Plain-text Passwords
AI thường skip bcrypt/argon2. Lưu raw password hoặc dùng MD5/SHA1 không salted.
3. JWT Vulnerabilities
Không verify signature, alg=none bypass, weak secret, không set expiry.
4. Missing Input Validation
No DTO validation, no sanitization. XSS, path traversal, type confusion attacks.
5. Hardcoded Secrets
API keys, passwords, tokens hardcoded trong source. Leaked khi push lên GitHub.
6. Dependency CVEs
AI suggest outdated versions. Package có CVEs đã biết không được update.

🔍 Risk 1: SQL Injection

❌ AI generates — VULNERABLE

// Raw string concat — DANGER
async searchProducts(q: string) {
  return this.db.query(
    `SELECT * FROM products
     WHERE name LIKE '%${q}%'`
  );
}

// Exploit: q = "' OR '1'='1' --"
// Returns ALL rows regardless of name

✅ Fix — parameterized query

// Parameterized — SAFE
async searchProducts(q: string) {
  return this.db.query(
    `SELECT * FROM products
     WHERE name LIKE $1`,
    [`%${q}%`]  // param, never concat
  );
}

// TypeORM: .where('name LIKE :q', {q: `%${q}%`})
// Mongoose: .find({name: /pattern/}) — safe

❌ NoSQL Injection — MongoDB

// Never trust req.body directly
async login(body: any) {
  return this.User.findOne({
    email: body.email,
    password: body.password
    // body = {email: {$gt: ""}, password: {$gt: ""}}
    // → login without credentials!
  });
}

✅ Fix — DTO + type enforcement

// Typed DTO prevents object injection
class LoginDto {
  @IsEmail() email: string;
  @IsString() @MinLength(8) password: string;
}

async login(dto: LoginDto) {
  const user = await this.User.findOne({
    email: dto.email  // typed string, safe
  });
  // compare hash, not raw password
}

🔍 Risk 2: Plain-text Passwords

❌ AI generates — VULNERABLE

// AI often skips hashing!
async createUser(dto: CreateUserDto) {
  return this.User.create({
    email: dto.email,
    password: dto.password,  // raw!
  });
}

// Also bad: MD5, SHA1 without salt
// crypto.createHash('md5').update(pw).digest('hex')

✅ Fix — bcrypt hash

import * as bcrypt from 'bcrypt';

async createUser(dto: CreateUserDto) {
  const saltRounds = 12; // cost factor
  const hash = await bcrypt.hash(
    dto.password, saltRounds
  );
  return this.User.create({
    email: dto.email,
    password: hash,  // never raw
  });
}

// verify: bcrypt.compare(plain, hash)

🔍 Risk 3: JWT Vulnerabilities

❌ AI generates — VULNERABLE

// 3 mistakes in 1 snippet
const token = jwt.sign(
  { userId: user.id },
  'secret',       // hardcoded weak secret
  { algorithm: 'none' }  // CRITICAL: no sig!
  // missing: expiresIn
);

// Verify also broken:
jwt.verify(token, '')  // accepts anything

✅ Fix — proper JWT config

// NestJS: use @nestjs/jwt module
JwtModule.register({
  secret: process.env.JWT_SECRET,  // env
  signOptions: {
    expiresIn: '15m',  // short-lived
    algorithm: 'HS256',  // explicit
  },
});

// Refresh token: 7d, stored in httpOnly cookie
// Rotate on each use to detect theft

🔍 Risk 4: Missing Input Validation

❌ No validation — XSS + overflow

@Post('/comments')
async create(@Body() body: any) {
  // body.content could be:
  // "<script>alert(document.cookie)</script>"
  // or a 50MB string to exhaust memory
  return this.Comment.create(body);
}

✅ DTO + whitelist validation

class CreateCommentDto {
  @IsString()
  @MinLength(1)
  @MaxLength(2000)
  @Transform(({value}) => sanitizeHtml(value))
  content: string;
}

// main.ts
app.useGlobalPipes(new ValidationPipe({
  whitelist: true,     // strip unknown props
  forbidNonWhitelisted: true,
}));

🔍 Risk 5: Hardcoded Secrets

❌ Secrets in source code

// AI often puts real-looking placeholders
const stripe = new Stripe('sk_live_abc123xyz');
const redis = createClient({ password: 'redis123' });
const sendgrid = sgMail.setApiKey('SG.xxx');

// Once pushed to GitHub → leaked forever
// Even after deletion: git history exposes it

✅ Environment variables only

// Always from process.env
const stripe = new Stripe(process.env.STRIPE_SECRET_KEY);
const redis = createClient({
  password: process.env.REDIS_PASSWORD
});

// .env (gitignored) for local dev
// GitHub Secrets / Vault for production
// ConfigModule validates at startup

🔍 Risk 6: Outdated Dependencies

AI suggests packages — verify versions

AI training data có cutoff → suggest versions cũ có CVE đã biết

# Check vulnerabilities in current project
npm audit

# Check specific package
npm audit --audit-level=high

# Auto-fix safe updates
npm audit fix

# Research before adding new package:
# https://snyk.io/vuln/npm:{package-name}
# https://security.snyk.io/
Habit: Khi AI suggest npm install X → search "X npm CVE" trước. Ưu tiên packages ít dependencies, high weekly downloads, active maintenance.

✅ AI Security Review Checklist

□SQL/NoSQL queries dùng parameterized / ORM methods — không string concat
□Passwords hash với bcrypt/argon2 (saltRounds ≥ 12) — không raw, không MD5
□JWT có secret từ env, algorithm explicit (HS256/RS256), expiresIn set
□Tất cả endpoints có DTO + ValidationPipe(whitelist: true)
□Không có string literal nào trông như secret/key/password trong source
□npm audit clean hoặc chấp nhận được (chỉ low/info)
□File upload có validate MIME type + max size — không trust extension
□Error messages không leak stack trace / DB schema ra user
Pro tip: Dùng AI để review security! Prompt: "Review code này cho các security vulnerabilities: SQL injection, authentication bypass, input validation gaps, hardcoded secrets. List tất cả issues tìm thấy."
🎯 Bài Tập Thực Hành
🟢 DễBài 1
Chạy npm audit trên project hiện tại
Mở một NestJS project bất kỳ. Chạy npm audit. Đọc output, phân loại severity (critical/high/medium/low). Fix ít nhất 1 vulnerability bằng npm audit fix.
Severity levels:
• Critical → fix ngay, block deploy
• High → fix trong sprint hiện tại
• Medium → backlog P2
• Low/Info → acknowledge, next refactor

npm audit fix --force có thể break breaking changes — test sau khi chạy
🟢 DễBài 2
Review một AI-generated UserService cho security issues
Prompt AI: "Write a NestJS UserService with createUser (email + password) and login (return JWT)." Copy output. Không chạy — chỉ đọc và tìm tất cả security issues theo checklist trên.
Thường tìm được:
1. Password lưu raw (missing bcrypt)
2. JWT secret hardcoded ('secret' hoặc 'jwt-secret')
3. Không set JWT expiresIn
4. Không có input validation DTO
5. Trả về full user object (kể cả password field) trong response

Fix tất cả trước khi dùng bất kỳ đoạn code nào
🟡 Trung bìnhBài 3
Viết unit test expose SQL injection vulnerability
Tạo function searchByName(q: string) dùng raw SQL concat. Viết test với input "' OR '1'='1' --". Verify nó return unexpected rows. Sau đó fix bằng parameterized query và verify test pass safely.
Test pattern:
it('should not return all rows on injection', async () => {
  const result = await service.search("' OR '1'='1' --");
  // Before fix: result.length === ALL_ROWS (FAIL expected behavior)
  // After fix: result.length === 0 (no match for injection string)
  expect(result.length).toBe(0);
});
Cách dễ test không cần real DB: mock this.db.query, kiểm tra query string KHÔNG chứa raw input.
🔴 KhóBài 4
Implement full auth: bcrypt + JWT + DTO — tự mình verify security
Build auth module từ đầu: register (hash password), login (verify hash, return JWT 15min), guard (verify JWT). Sau đó self-audit bằng checklist 8 điểm ở trên — tick tất cả trước khi nộp.
Checklist self-audit:
✓ bcrypt.hash() với saltRounds=12
✓ bcrypt.compare() — không so sánh raw
✓ JWT_SECRET từ process.env
✓ expiresIn: '15m'
✓ JwtAuthGuard trên protected routes
✓ RegisterDto + LoginDto với @IsEmail, @MinLength(8)
✓ Response loại bỏ password field (@Exclude())
✓ 401 message generic: "Invalid credentials" (không reveal "email not found" vs "wrong password")

📌 Tóm Tắt — AI Security Risks

  • SQL/NoSQL injection — parameterized queries, typed DTOs. Không bao giờ concat user input
  • Password hashing — bcrypt/argon2 mandatory. MD5/SHA1 không dùng cho auth
  • JWT — secret từ env, algorithm explicit, expiry set, rotate refresh tokens
  • Input validation — DTO + ValidationPipe(whitelist) mọi endpoint. Sanitize output
  • Secrets — chỉ trong env vars. Scan .git history nếu lỡ commit
  • Dependencies — npm audit mỗi sprint. Không thêm package không verify
