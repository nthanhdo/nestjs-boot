⏱️ Task Breakdown & Estimation

Estimation không phải đoán mò — có formula, có pattern, có cách cải thiện theo thời gian. Đây là skill phân biệt senior khỏi junior.

🧩 Task Breakdown — Chia Nhỏ Vấn Đề

Rule: task tốt nhất = hoàn thành trong 2-4 giờ, mô tả được trong 1 câu, deploy độc lập được.

👕 T-shirt Sizing

Quick relative sizing — đủ để plan sprint, không cần chính xác đến từng giờ.

XS
< 2 giờ
Config change, typo fix, add a field
S
2–4 giờ
Simple endpoint, single feature with validation
M
1–2 ngày
Feature với logic + tests, simple integration
L
3–5 ngày
Complex feature, multi-service, cần design trước
XL
> 1 tuần
System redesign → chia nhỏ thành L tasks
XL rule: Nếu estimate là XL → team chưa đủ info để implement. Phải research/design trước. Chia thành L tasks có thể estimate riêng lẻ.

🧮 Estimation Formula

Base (nếu mọi thứ suôn sẻ)4h
Buffer 50% (unknowns, integration, debugging)+2h
Risk 20% (unclear spec, dependencies)+1h
TOTAL ESTIMATE7h → "1 ngày"

Khi nào dùng buffer bao nhiêu?

Buffer thấp (20-30%)

  • Đã làm task tương tự trước
  • Spec rõ ràng, không ambiguous
  • Không có external dependencies

Buffer cao (50-100%)

  • Tech stack mới, chưa dùng bao giờ
  • Spec còn nhiều unknowns
  • Phải integrate với 3rd-party API

📊 Improving Estimates Over Time

Track actual vs estimate

Sau mỗi sprint, compare actual với estimate. Tìm pattern để calibrate.

# Sprint log (ghi trong spreadsheet hoặc doc)

Task                    | Estimate | Actual | Ratio
------------------------|----------|--------|-------
JWT setup               | 2h       | 4h     | 2.0x
Register endpoint       | 2h       | 3h     | 1.5x
Email integration       | 4h       | 8h     | 2.0x
------------------------|----------|--------|-------
Average ratio: ~1.8x

# Next sprint: multiply estimates by 1.8x
Nếu ratio luôn >1.5x → đang underestimate. Adjust formula. Nếu ratio luôn <0.8x → đang overestimate và đang under-deliver (khác vấn đề).

💬 Communicate Estimates Đúng Cách

❌ Estimate sai

  • "Dễ thôi, 1 tiếng" — không có basis
  • "Không biết, tùy" — không helpful
  • "Xong sớm nhất có thể" — không commit

✅ Estimate đúng

  • "Tôi estimate M (2 ngày) với assumption là spec không đổi."
  • "Cần thêm info về X trước khi estimate được."
  • "Base 4h + buffer 50% = 6h → commit 1 ngày."

🟡 Trung bìnhBài 2
Breakdown "Order tracking system" thành 6-8 subtasks với size
Feature: User có thể xem real-time status của order (placed → processing → shipped → delivered). Breakdown thành subtasks, estimate từng task, tính total và add buffer 30%.
1. Order status enum + schema update (XS — 1h)
2. PATCH /orders/:id/status endpoint với role guard (S — 2h)
3. GET /orders/:id/tracking với history log (S — 2h)
4. Status transition validation (prevent invalid state: delivered→processing) (S — 2h)
5. WebSocket event khi status thay đổi (M — 4h)
6. Email notification mỗi status change (M — 3h)
7. FE status timeline component (M — 4h nếu có FE team)
8. Integration tests end-to-end flow (S — 3h)

Total: ~21h base → +30% buffer = 27h ≈ 3.5 ngày → estimate "1 sprint" (cùng với tasks khác)

Key insight: Step 5 (WebSocket) là M highest risk → có thể cần L nếu infra chưa có
🔴 KhóBài 3
Track actual vs estimate trong 1 tuần — tính calibration ratio
Làm 5-10 coding tasks trong tuần tới. Trước mỗi task: estimate bằng T-shirt size + giờ cụ thể. Sau khi xong: ghi actual time. Cuối tuần: tính average ratio, phân tích tại sao underestimate hoặc overestimate.
Tracking template:
Date | Task | Estimate | Actual | Ratio | Notes
-----|------|----------|--------|-------|------
Mon  | JWT setup | 2h | 3.5h | 1.75x | Forgot refresh token edge cases
Mon  | DTO validation | 1h | 1h | 1.0x | Simple, similar to past
Tue  | Email integration | 4h | 7h | 1.75x | Nodemailer config took 2h

Common patterns:
- Integration với external service luôn x2
- "Simple" tasks có hidden edge cases
- Debug time không được estimate
- "Just a config change" thường là 3h

Target: ratio 1.0-1.3x sau 3 sprints (continuous improvement)

📌 Tóm Tắt — Estimation

  • Task breakdown = chia đến khi mỗi task ≤ 2-4h và mô tả được trong 1 câu
  • T-shirt sizing = XS/S/M/L/XL. XL → cần research/design trước, không implement ngay
  • Formula = Base + Buffer (20-100% tùy risk) + Risk. Commit sau khi tính xong
  • Track và calibrate = ghi actual vs estimate, tính ratio, adjust cho sprint sau
  • Communicate = state assumptions khi estimate. "Estimate này assume X và Y"
