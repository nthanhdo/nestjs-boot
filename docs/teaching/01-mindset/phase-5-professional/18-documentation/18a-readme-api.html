📝 README & API Documentation

Doc tốt = explain cho engineer khác mà không cần ngồi cạnh. Không doc = technical debt không nhìn thấy được.

❌ Không có Doc

  • Onboard member mới mất 2-3 tuần
  • Debug phải đọc toàn bộ code
  • PM không biết API có gì
  • 6 tháng sau chính mình không nhớ

✅ Có Doc tốt

  • Onboard trong 2-3 ngày
  • Debug bắt đầu từ troubleshooting guide
  • PM tự query API docs khi cần
  • 6 tháng sau extend feature dễ dàng

📄 README Anatomy

README là "front door" của project. Developer clone repo → cần biết ngay: đây là gì, cách chạy, cách contribute.

📄 README.md — Anatomy
🏷️ Project Title + One-liner MUST
Tên và giải thích trong 1 câu. Ai đọc 10 giây biết đây là gì.
# OrderService — REST API quản lý orders cho e-commerce platform
🚀 Quick Start MUST
Copy-paste commands để chạy lần đầu. Không assume prior knowledge.
git clone → npm install → cp .env.example .env → npm run dev
📋 Prerequisites MUST
Node v20+, Docker 24+, MongoDB 7. Version cụ thể — không viết "latest".
🏗️ Architecture Overview SHOULD
Diagram hoặc mô tả ngắn: folder layout, key modules, data flow.
📖 API Reference SHOULD
Link tới Swagger UI hoặc Postman collection. Không viết inline — quá dài.
Swagger: http://localhost:3000/api-docs
🧪 Running Tests SHOULD
npm test, npm run test:e2e. Expected result là gì.
🤝 Contributing Guide MAY
Branch naming, commit convention, PR process — cho OSS projects.
📄 License MAY
MIT, Apache 2.0, proprietary — quan trọng cho open-source.
README anti-pattern: Viết README một lần rồi không update. README outdated = worse than no README (misleads people). Treat README như code — update khi thay đổi setup.

🔍 API Documentation — Swagger / OpenAPI

Viết API docs bằng tay = luôn outdated. Code-first: decorators trong code → auto-generate docs.

NestJS Swagger Setup

// main.ts
import { SwaggerModule, DocumentBuilder } from '@nestjs/swagger';

const config = new DocumentBuilder()
  .setTitle('OrderService API')
  .setVersion('1.0')
  .addBearerAuth()
  .build();

const document = SwaggerModule.createDocument(app, config);
SwaggerModule.setup('api-docs', app, document);

// Controller
@ApiOperation({ summary: 'Create order' })
@ApiResponse({ status: 201, type: OrderDto })
@Post()
create(@Body() dto: CreateOrderDto) { ... }
Habit: Mỗi endpoint phải có: @ApiOperation (what it does), @ApiResponse (all possible responses including 400/401/404), @ApiBody (request schema). Run Swagger UI → verify mỗi endpoint hiện đúng.
🎯 Bài Tập Thực Hành
🟢 DễBài 1
Viết README cho một project đang có
Chọn một NestJS project bất kỳ (hoặc tạo mới). Viết README hoàn chỉnh theo anatomy: Title, Quick Start, Prerequisites, Architecture Overview, API Reference link, Test instructions. Kiểm tra: fresh clone và follow README có chạy được không?
Test checklist cho README:
☐ Clone repo mới (không dùng setup đang có)
☐ Follow prerequisites section — có đủ không?
☐ Quick Start commands — copy-paste, không typing
☐ npm run dev — app start?
☐ API reference link accessible?
☐ npm test — pass?

Nếu có bất kỳ step nào cần "đoán" hay tìm thêm info → README chưa đủ, update lại

Pro tip: nhờ người chưa biết project follow README — họ sẽ tìm ra gaps bạn không thấy
🟡 Trung bìnhBài 2
Setup Swagger cho UserService — annotate 4 endpoints
Implement UserService với 4 endpoints (GET /users, POST /users, GET /users/:id, DELETE /users/:id). Setup @nestjs/swagger trong main.ts. Annotate mỗi endpoint với ApiOperation, ApiResponse (200/201/400/401/404), ApiBody. Verify Swagger UI hiện đúng.
Checklist per endpoint:
✓ @ApiOperation({ summary: '...' }) — mô tả trong 1 dòng
✓ @ApiResponse({ status: 200, type: UserDto }) — success
✓ @ApiResponse({ status: 404, description: 'User not found' }) — not found
✓ @ApiResponse({ status: 401, description: 'Unauthorized' }) — khi cần auth
✓ @ApiBody({ type: CreateUserDto }) — cho POST/PUT
✓ @ApiParam({ name: 'id', type: String }) — cho :id params

Sau khi annotate: mở /api-docs, verify mỗi endpoint có thể "Try it out" thành công
🔴 KhóBài 3
Viết Troubleshooting Guide cho common errors
Collect 5 common errors từ project của bạn (hoặc research online cho NestJS). Với mỗi error: symptom (log message), likely causes (3+), checklist verify, fix commands/code. Format: searchable document — developer có thể copy error và tìm thấy ngay.
Template mỗi error:
Symptom: `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017`
Causes:
1. MongoDB không chạy locally
2. Wrong MONGODB_URI trong .env
3. Docker container chưa start
Check:
- `docker ps | grep mongo` — container running?
- `cat .env | grep MONGODB_URI` — correct URL?
- `telnet localhost 27017` — connection possible?
Fix:
- `docker compose up -d mongodb`
- Update .env với correct URI

Format này làm cho troubleshoot guide searchable và actionable

📌 Tóm Tắt — README & API Docs

  • README = front door. MUST: Title + Quick Start + Prerequisites. SHOULD: Architecture + API link + Tests
  • Test README = fresh clone + follow steps. Nếu phải đoán → chưa xong
  • Swagger = code-first. Decorators → auto-generate. Không viết tay
  • Annotate mọi endpoint = ApiOperation + ApiResponse (tất cả cases) + ApiBody
  • Update khi thay đổi — outdated doc = worse than no doc
