🗂️ C4 + Sequence + ERD Diagrams

Diagram đúng loại cho đúng audience — đây là communication skill quan trọng không kém code skill.

📐 C4 Model — 4 Levels of Abstraction

C4 = Context, Container, Component, Code. Mỗi level = một audience khác nhau với mức độ detail khác nhau.

L1
System Context (Big Picture)
Audience: non-technical stakeholders, PM. System của bạn interact với ai, với gì. External actors và systems.
User → OrderService → [Stripe, Email, Inventory]. Boxes + arrows, không có tech detail.
L2
Container Diagram
Audience: technical leads, architects. Services, databases, deployment units. Công nghệ nào, chạy ở đâu.
API Server (NestJS/Node) → MongoDB → Redis → S3 → Worker (Bull Queue)
L3
Component Diagram
Audience: developers. Modules, services, controllers trong một container. Cụ thể hơn L2.
OrderModule → OrderService → OrderRepo + InventoryService + PaymentService
L4
Code Level
Audience: developers. Class diagram, UML. Thường auto-generate từ code — không vẽ tay.
Class diagrams, method signatures — chỉ khi complex algorithm cần document
Rule: L1 + L2 = mandatory cho mọi project. L3 = cho complex modules. L4 = rarely needed. Tools: draw.io, Mermaid (code-based), Structurizr DSL.

⏩ Sequence Diagram — Request Flow

Sequence diagram = ai call ai, theo thứ tự, với data gì. Dùng khi explain authentication flows, payment processing, complex multi-service calls.

Mermaid — Code-based Sequence

```mermaid
sequenceDiagram
  Client->>API: POST /login {email, password}
  API->>AuthService: verify(email, password)
  AuthService->>DB: findUser(email)
  DB-->>AuthService: User{passwordHash}
  AuthService-->>API: verified: true
  API-->>Client: {access_token, refresh_token}
```
Mermaid code = version-controllable diagram. Commit cùng với code. Update khi flow thay đổi. Render trực tiếp trong GitHub README/docs.

🎯 Bài Tập Thực Hành
🟢 DễBài 1
Vẽ C4 Level 1+2 cho project hiện tại
Chọn project đang có. Vẽ L1 (System Context) và L2 (Container) bằng draw.io hoặc Mermaid. L1: system của bạn + actors (user, admin) + external systems (DB, 3rd party). L2: các services/databases với tech stack.
L1 checklist:
☐ System box ở giữa (tên + tech stack)
☐ User actors bên ngoài (User, Admin)
☐ External systems (MongoDB, Redis, Stripe, SendGrid)
☐ Arrows với description ("uses", "sends to")
☐ No internal detail — just boundaries

L2 checklist:
☐ API Server với tech (NestJS + Node 20)
☐ Each database/cache (MongoDB, Redis)
☐ Background workers nếu có (Bull Queue)
☐ Frontend nếu có (Next.js)
☐ Arrows với protocol (HTTP, TCP, AMQP)

Tool nhanh: Mermaid C4 syntax hoặc draw.io C4 template
🟡 Trung bìnhBài 2
Viết Mermaid sequence diagram cho checkout flow
Checkout flow: User → API → InventoryService (check stock) → PaymentService (Stripe) → OrderService (create order) → EmailService (send confirmation) → User. Viết Mermaid code, render và verify flow logic đúng.
sequenceDiagram
  User->>API: POST /checkout {items, payment}
  API->>InventoryService: checkStock(items)
  alt Out of stock
    InventoryService-->>API: Error: OUT_OF_STOCK
    API-->>User: 409 Conflict
  else In stock
    InventoryService-->>API: stockAvailable
    API->>PaymentService: charge(amount, card)
    PaymentService-->>API: {paymentId, success}
    API->>OrderService: createOrder({items, paymentId})
    OrderService-->>API: {orderId}
    API->>EmailService: sendConfirmation(email, orderId)
    API-->>User: 201 {orderId}
  end
Key: alt/else = conditional flows. Dashes (-->) = response. Solid (->>) = request.
🔴 KhóBài 3
Design ERD cho e-learning platform (4+ entities)
Platform có: Users, Courses, Lessons, Enrollments, Progress tracking, Reviews. Design ERD với ít nhất 5 entities. Mỗi entity: fields + types + PK/FK. Include cardinality (1-1, 1-N, N-N). Identify nơi cần indexes.
Entities:
- users: _id, email, password, role
- courses: _id, title, instructorId(FK→users), price
- lessons: _id, courseId(FK→courses), title, videoUrl, order
- enrollments: _id, userId(FK), courseId(FK), enrolledAt, completed — N-N bridge
- progress: _id, enrollmentId(FK), lessonId(FK), completedAt — N-N bridge
- reviews: _id, userId(FK), courseId(FK), rating(1-5), comment

Cardinality:
users 1—∞ courses (instructor)
courses 1—∞ lessons
users N—N courses (via enrollments)
enrollments 1—∞ progress

Indexes:
enrollments: compound(userId, courseId) unique
progress: compound(enrollmentId, lessonId) unique
courses: instructorId (frequent query)
reviews: compound(userId, courseId) unique (one review per course)

📌 Tóm Tắt — Diagrams

  • C4 Model = 4 levels. L1+L2 mandatory. L3 cho complex modules. L4 rarely needed
  • Sequence diagram = request flow với thứ tự calls. Dùng Mermaid cho version control
  • ERD = database schema visual. Mandatory cho mọi backend project
  • Audience rule = L1 cho non-technical, L2-L3 cho engineers, ERD cho developers
  • Update khi thay đổi — diagram là doc, treat như code
