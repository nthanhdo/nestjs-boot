📋 ADR & Troubleshooting Guide

Architecture Decision Records = lý do tại sao code ở đây lại như vậy. Troubleshooting guides = first line of defense khi things go wrong.

📜 ADR — Architecture Decision Record

ADR = document một architectural decision, bao gồm context, options xem xét, và lý do chọn. Tránh câu "Tại sao code lại như vậy?" sau 6 tháng.

Khi nào viết ADR? Khi decision: (1) hard to reverse, (2) affects multiple teams, (3) has significant trade-offs. Format: đơn giản, trong kho repo (docs/adr/), commit cùng code.
ADR-001 Use JWT over Server-Side Sessions ACCEPTED
Context
Mobile app requires stateless auth. Current session-based auth adds Redis latency (~20ms/request) and complicates horizontal scaling. 3 teams need auth: web, mobile, partner API.
Decision
Use JWT access tokens (15min) + refresh tokens (7 days). Refresh tokens stored in Redis for revocation. Implement using @nestjs/jwt with RS256 signing (asymmetric, supports microservices).
Consequences
+ Stateless: scales horizontally without sticky sessions
+ Mobile-compatible: Bearer token pattern standard
– Access token not immediately revocable (must wait expire)
– Revocation logic complex (Redis blacklist for logout)
Alternatives Rejected
1. Server-side sessions — rejected: Redis dependency, not mobile-friendly
2. Opaque tokens — rejected: database lookup per request, performance issue at scale
Date & Status
2026-08-14 — ACCEPTED by: Lead Architect + Backend Lead

🔧 Troubleshooting Guide

Format: searchable bằng error message. Developer copy error → find guide → fix. Không phải essay.

MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017 ▼
🔍 Check
  • docker ps | grep mongo — running?
  • cat .env | grep MONGODB_URI — correct?
  • docker-compose.yml — mongo service defined?
✅ Fix
  • docker compose up -d mongodb
  • Update .env với correct URI
  • Check firewall nếu remote MongoDB
JsonWebTokenError: invalid signature ▼
🔍 Check
  • JWT_SECRET trong .env correct?
  • Token generated với same secret?
  • Algorithm mismatch (HS256 vs RS256)?
✅ Fix
  • Verify JWT_SECRET identical across envs
  • Clear cookies/localStorage, re-login
  • Match algorithm in sign + verify
ValidationPipe: property X should not exist ▼
🔍 Check
  • DTO whitelist: true + forbidNonWhitelisted?
  • Request body có extra fields không?
  • DTO có decorator cho field đó không?
✅ Fix
  • Add missing field với @IsString() etc.
  • Or remove extra field từ request
  • Or add @IsOptional() nếu field optional
🎯 Bài Tập Thực Hành
🟢 DễBài 1
Viết ADR cho technology choice trong project của bạn
Chọn 1 tech decision đã làm (MongoDB vs PostgreSQL, REST vs GraphQL, JWT vs Sessions, v.v.). Viết ADR hoàn chỉnh: Context, Decision, Consequences (+/-), Alternatives Rejected, Date.
ADR quality checklist:
☐ Context mô tả vấn đề cụ thể, không abstract
☐ Decision rõ ràng — ai đọc biết ngay chọn gì
☐ Consequences có cả pros và cons (honest)
☐ Alternatives: giải thích tại sao KHÔNG chọn (không chỉ list)
☐ Date + Approvers (ai đã accept decision)

Anti-pattern: "We chose MongoDB because it's good" → không có context, không có alternatives, không có consequences. ADR phải answer "tại sao không chọn X?"
🔴 KhóBài 2
Build troubleshooting guide: 5 errors từ project thực
Collect 5 real errors bạn đã gặp trong NestJS development. Với mỗi error: (1) exact error message (copy từ logs), (2) 3+ possible causes, (3) verification commands/steps, (4) fix commands/code. Format: searchable, developer có thể copy error → find guide.
Common NestJS errors để document:
1. "Nest can't resolve dependencies of..." — missing provider/import
2. "Cannot read property of undefined" — service not initialized
3. "CORS error" — missing CORS config
4. "Class transformer error" — missing class-transformer package
5. "Cannot find module..." — wrong path, missing npm install

Format chuẩn:
Title = exact error substring (searchable)
Symptom = full log output
Quick diagnosis = 2-3 commands để identify cause
Fix = specific code/command changes
Prevention = how to avoid in future

Commit troubleshooting guide vào repo — nó có giá trị như code

📌 Tóm Tắt — ADR & Troubleshooting

  • ADR = document architectural decisions. Context → Decision → Consequences → Alternatives
  • ADR khi nào = hard to reverse, affects multiple teams, significant trade-offs
  • ADR storage = docs/adr/ trong repo. Commit với code. Không delete — mark deprecated
  • Troubleshooting guide = searchable by error message. Symptom + Check + Fix format
  • Both = living docs — update khi decisions change hoặc new errors discovered
