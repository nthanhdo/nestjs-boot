7. System Design Interview — RESHADED Framework

Phỏng vấn system design = design một large-scale system trong 45-60 phút. RESHADED = checklist để không quên bước nào.

R
Requirements
Clarify functional + non-functional. Never assume.
E
Estimation
Scale: DAU, storage, bandwidth, QPS
S
Storage
SQL vs NoSQL, schema design, sharding
H
High-level Design
Block diagram: clients, LB, services, DB
A
APIs
Key endpoints, request/response format
D
Detailed Design
Deep dive vào 2-3 components interviewer care
E
Edge Cases
Failure modes, race conditions, retries
D
Deliver
Summarize, trade-offs, what you'd do differently

🎯 Bài Tập Capstone
🟢 DễBài 1
Chọn project topic → viết 1-paragraph description
Chọn một trong 4 project topics gợi ý (E-commerce, Blog, Task Manager, Chat) hoặc tự đề xuất. Viết 1 đoạn văn mô tả project: problem nó giải quyết, target users, core value proposition, và 3 tính năng chính.
Template description:
"[Project Name] là một [type of app] giúp [target users] giải quyết vấn đề [problem]. Thay vì [current painful solution], [Project Name] cung cấp [core value]. 3 tính năng chính: (1) [feature 1], (2) [feature 2], (3) [feature 3]."

Ví dụ Task Manager:
"TaskFlow là một project management app giúp small teams (2-10 người) tránh việc quản lý tasks qua chat groups. Thay vì nhắn tin trong Slack và quên mất tasks, TaskFlow cung cấp một nguồn sự thật duy nhất với accountability rõ ràng. 3 tính năng chính: (1) Task với assignee + deadline, (2) Real-time updates khi status thay đổi, (3) Daily digest email."

Đánh giá tốt nếu: đọc xong biết ngay đây là gì, ai dùng, tại sao dùng
🟢 DễBài 2
Vẽ architecture diagram cho project đã chọn
Vẽ C4 Level 1 (System Context) và Level 2 (Container) cho project của bạn. Phải identify: external users, external systems (payment, email, storage), và tất cả internal containers (web app, API, DB, cache, queue, v.v.).
E-commerce example:
C1 Context: Customer → [E-commerce System] → Stripe (payment), SendGrid (email), AWS S3 (images)
Admin → [E-commerce System]

C2 Container:
- React Frontend (SPA)
- NestJS API Server
- MongoDB (products, orders, users)
- Redis (cart, sessions, cache)
- BullMQ (email queue, order processing)
- S3 Bucket (product images)

Tools: draw.io C4 template hoặc structurizr.com (code-based)
🟡 Trung bìnhBài 3
Thiết kế ERD (ít nhất 5 entities)
Thiết kế ERD cho project của bạn với ít nhất 5 entities. Mỗi entity phải có: tên, fields (với data type), PK, và relationships với entities khác (1:1, 1:N, M:N). Identify indexes cần thiết.
E-commerce ERD (6 entities):
Users (_id, email[unique], name, role, passwordHash, createdAt)
Products (_id, name, price, stock, categoryId[FK], images[])
Categories (_id, name, slug[unique], parentId[FK])
Orders (_id, userId[FK], status, total, createdAt)
OrderItems (_id, orderId[FK], productId[FK], qty, priceAtTime)
Reviews (_id, userId[FK], productId[FK], rating, comment)

Relationships:
User 1→N Orders
Order 1→N OrderItems
OrderItem N→1 Product
Product N→1 Category
User 1→N Reviews, Product 1→N Reviews

Indexes: email (unique), productId+orderId (compound), userId, categoryId
🟡 Trung bìnhBài 4
Thiết kế API endpoints (ít nhất 15 endpoints)
Thiết kế RESTful API cho project của bạn: ít nhất 15 endpoints với HTTP method, path, description, request/response schema, và auth requirement. Group theo resource.
E-commerce API (16 endpoints):
Auth: POST /auth/register, POST /auth/login, POST /auth/refresh, POST /auth/logout
Users: GET /users/me, PATCH /users/me, DELETE /users/me
Products: GET /products, GET /products/:id, POST /products [Admin], PATCH /products/:id [Admin], DELETE /products/:id [Admin]
Orders: POST /orders, GET /orders, GET /orders/:id, PATCH /orders/:id/status [Admin]
Reviews: POST /products/:id/reviews, GET /products/:id/reviews

Cho mỗi endpoint ghi:
- Method + Path
- Auth: public / user / admin
- Request: params, query, body schema
- Response: 200 schema + error codes
🔴 KhóBài 5
Setup project: Git repo + CI + Docker + README — chạy được
Setup đầy đủ infrastructure cho capstone project: (1) GitHub repo với README, (2) .github/workflows/ci.yml green, (3) Dockerfile multi-stage build, (4) docker-compose.yml với app + DB, (5) curl localhost:3000/health trả 200. Đây là foundation thực sự của production-ready project.
Step-by-step checklist:
1. npx @nestjs/cli new project-name → push GitHub
2. README: title + quick start (3 commands) + prerequisites
3. Dockerfile: multi-stage (builder + runner, node:20-alpine)
4. docker-compose.yml: app + mongodb + redis
5. docker-compose up -d → verify app healthy
6. GET /health endpoint → return {status: "ok", timestamp}
7. .github/workflows/ci.yml: checkout → setup-node → npm ci → lint → test → build
8. Push → GitHub Actions → CI green ✅
9. Commit message: "feat: initial project setup with CI/CD and Docker"

Definition of Done: CI green, docker-compose up works, /health returns 200. Không có hardcoded credentials.
