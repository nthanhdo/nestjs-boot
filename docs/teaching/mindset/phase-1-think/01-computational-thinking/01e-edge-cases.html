⚡ Edge Cases

Code chạy đúng với dữ liệu bình thường chưa đủ. Phải test với những trường hợp bất thường — đây là nơi bug thực sự ẩn náu.

← Quay lại 01d: Algorithmic Thinking
⚠️ Tại sao edge cases quan trọng?
80% code xử lý happy path — dữ liệu bình thường, user hành động như mong đợi.
80% bugs đến từ edge cases — dữ liệu bất thường mà developer không nghĩ đến.
❌ Chỉ test happy path
average([80, 90, 70]) → 80 ✓
average([]) → NaN (crash!)
average(null) → TypeError (crash!)
Shipped to production → user complaint
✅ Test edge cases
average([]) → null/0 (defined)
average(null) → throw InvalidInput
average([1e308, 1e308]) → Infinity check
All cases handled before ship
📊 Bài toán: Tính điểm trung bình
Với hàm average(scores: number[]), những gì có thể xảy ra?
  • ⚡
    Mảng rỗng [] → chia cho 0 → NaN hoặc ExceptionCRASH
  • ⚡
    Có null hoặc undefined trong mảng → sum = NaNWRONG
  • ⚡
    Số rất lớn → floating point overflow: 1e308 + 1e308 = InfinityOVERFLOW
  • ⚡
    Chỉ 1 phần tử: [95] → average phải là 95CHECK
  • ⚡
    String thay vì number: ["a", "b"] → sum = "ab0" (type coercion!)TYPE ERROR
  • ⚡
    Số âm: [-100, 200] → kết quả âm, có hợp lệ không?BOUNDARY

💻 Code xử lý edge cases cho average()
function average(scores: number[]): number | null {
  // EMPTY: mảng rỗng
  if (!Array.isArray(scores) || scores.length === 0) return null

  // TYPE: lọc null/undefined/NaN
  const valid = scores.filter(s => typeof s === 'number' && !isNaN(s))
  if (valid.length === 0) return null

  // OVERFLOW: dùng reduce với trung gian
  const sum = valid.reduce((a, b) => a + b, 0)
  if (!isFinite(sum)) throw new Error('Overflow detected')

  return sum / valid.length
}
🎯 Key Takeaway
  • Bug trong production thường đến từ edge cases bị bỏ qua — không phải logic chính
  • Dùng checklist EMPTY · ONE · NULL · BOUNDARY · OVERFLOW · TYPE trước khi commit
  • Viết unit test cho edge cases — không chỉ happy path

🏋️ Mini Exercises

Ex 1 Liệt kê 10 edge cases cho form đăng ký tài khoản 🟡 Trung bình ▶
Form đăng ký có: email, password, username, date of birth. Hãy liệt kê ít nhất 10 edge cases, với mỗi case: loại lỗi và cách xử lý.
💡 Dùng checklist: EMPTY · BOUNDARY · NULL · FORMAT · DUPLICATE · SECURITY · LOGICAL · OVERFLOW
10 edge cases cần xử lý:
  1. Email không có @ — FORMAT → "Email không hợp lệ"
  2. Email đã tồn tại — DUPLICATE → "Email này đã được đăng ký"
  3. Password < 8 ký tự — BOUNDARY → "Tối thiểu 8 ký tự"
  4. Password toàn số hoặc toàn chữ — WEAK → "Cần mix chữ + số + ký tự"
  5. Username có khoảng trắng — FORMAT → trim hoặc báo lỗi
  6. Username SQL injection — SECURITY → sanitize input
  7. Date of birth tương lai — LOGICAL → "Ngày sinh không hợp lệ"
  8. Tuổi dưới 13 — BUSINESS RULE → "Cần đồng ý của phụ huynh"
  9. Email > 254 ký tự — OVERFLOW → "Email quá dài"
  10. Tất cả fields trống — EMPTY → "Vui lòng điền đầy đủ"
