🏛️ SOLID Principles

5 nguyên tắc OOP giúp code linh hoạt, dễ mở rộng, ít bug. Bắt đầu với S và D — 80% benefit từ 2 nguyên tắc này. Click từng card để xem chi tiết.

🎯 5 Nguyên Tắc SOLID

S
Single Responsibility
Mỗi class chỉ có 1 lý do để thay đổi
// ❌ UserService làm quá nhiều
class UserService {
  getUser() { ... }
  sendEmail() { ... }    ← sai chỗ
  generatePDF() { ... }  ← sai chỗ
}
// ✅ Mỗi service 1 việc
UserService, MailService, PdfService
O
Open/Closed
Mở để mở rộng, đóng để sửa đổi
// Thêm shape mới không cần sửa code cũ
interface Shape {
  area(): number
}
class Circle implements Shape {
  area() { return Math.PI * this.r ** 2 }
}
class Square implements Shape { ... }
// Thêm Triangle: không sửa Circle/Square
L
Liskov Substitution
Subclass thay thế được parent class
// Code dùng Bird phải hoạt động
// với mọi subclass của Bird
function makeFly(bird: Bird) {
  bird.fly() // phải work
}
// ❌ Penguin extends Bird → fly() throws!
// Fix: Penguin extends NonFlyingBird
// hoặc dùng IFlyable interface
I
Interface Segregation
Nhiều interface nhỏ hơn 1 interface lớn
// ❌ 1 interface quá rộng
interface Worker {
  work(): void
  eat(): void
  sleep(): void
}
// ✅ Tách nhỏ
interface Workable { work(): void }
interface Feedable { eat(): void }
// Robot implements Workable, không cần eat()
D
Dependency Inversion
Depend on abstractions, not concretions. High-level không phụ thuộc low-level.
// ❌ Tight coupling — gắn với MySQL
class OrderService {
  private db = new MySQLDatabase()  ← bad
}

// ✅ Inject dependency — dùng interface
class OrderService {
  constructor(private db: IDatabase) {}
  // Test: inject MockDatabase ✓
  // Prod: inject MongoDatabase ✓
  // Swap DB: không sửa OrderService ✓
}

⭐ Học Theo Thứ Tự Ưu Tiên

S + D
Bắt đầu từ đây — 80% benefit
SRP: mỗi class 1 trách nhiệm. DIP: inject dependency qua interface.
P0
O + I
Khi hệ thống cần mở rộng
OCP: plugin-style extension. ISP: interface nhỏ, focused.
P1
L
Khi dùng inheritance
LSP: subclass phải behave như parent. Ưu tiên composition over inheritance.
P2
💡 Key Takeaway

SOLID không phải rules phải follow mọi lúc — đây là guidelines. Áp dụng khi thấy code khó test, khó thay đổi, hay break. Bắt đầu với S và D — 80% giá trị. Khi thấy new MySQLDatabase() trong service → DIP violation → inject interface thay thế.

🏋️ Bài Tập

Áp dụng SRP cho UserService vi phạm
class UserService {
  createUser(data) { ... }    // DB operation
  deleteUser(id) { ... }      // DB operation
  sendWelcomeEmail(user) { ... } // Email
  sendResetEmail(email) { ... }  // Email
  hashPassword(pw) { ... }    // Security
  generateToken(user) { ... } // Auth
  exportToPDF(users) { ... }  // Report
}

Yêu cầu: (1) Phân nhóm theo responsibility, (2) Đặt tên các service mới, (3) Viết interface cho mỗi service.
