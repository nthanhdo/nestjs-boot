🏭 Factory Pattern

Thay vì new Dog() hay new Cat(), bạn gọi AnimalFactory.create(type). Factory quyết định tạo loại nào — caller không cần biết.

🎯 Tại Sao Cần Factory?

❌ Không có Factory
function notify(type) {
  if (type === 'email') {
    const n = new EmailNotifier()
    n.send(msg)
  } else if (type === 'sms') {
    const n = new SmsNotifier()
    n.send(msg)
  }
  // Thêm 'push' → sửa hàm này
}
✅ Với Factory
function notify(type) {
  const n = NotificationFactory
    .create(type)
  n.send(msg)
  // Thêm 'push' → chỉ sửa Factory
  // notify() không thay đổi ✓ OCP
}

🔧 Implement Factory Trong TypeScript

// Step 1: Define interface
interface INotifier {
  send(to: string, msg: string): Promise<void>
}

// Step 2: Concrete implementations
class EmailNotifier implements INotifier {
  async send(to, msg) { /* SendGrid... */ }
}
class SmsNotifier implements INotifier {
  async send(to, msg) { /* Twilio... */ }
}

// Step 3: Factory — object map (not if/else)
class NotificationFactory {
  private static registry = {
    email: EmailNotifier,
    sms: SmsNotifier,
    push: PushNotifier,
  }

  static create(type: string): INotifier {
    const Cls = this.registry[type]
    if (!Cls) throw new Error(`Unknown notifier: ${type}`)
    return new Cls()
  }
}
// Thêm type mới: chỉ thêm vào registry — OCP ✓

✅ Khi Nào Dùng Factory?

✅ Dùng khi
  • Không biết trước sẽ tạo type nào
  • Type phụ thuộc vào runtime data
  • Muốn ẩn logic khởi tạo phức tạp
  • Nhiều types implement cùng interface
❌ Không dùng khi
  • Chỉ có 1 loại object duy nhất
  • Logic tạo object đơn giản
  • Factory thêm complexity không cần thiết
💡 Key Takeaway

Factory = nhà máy sản xuất objects. Caller không cần biết implementation cụ thể. Dùng object map (không dùng if/else chain) để dễ mở rộng. Thêm loại mới → chỉ thêm vào map, không sửa caller. Đây là OCP trong thực tế.
