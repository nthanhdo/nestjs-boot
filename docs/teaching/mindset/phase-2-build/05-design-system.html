Khái niệm 01
Design System là gì?
Không phải chỉ là "UI đẹp". Design System là ngôn ngữ thiết kế nhất quán giúp scale ứng dụng.
💡 Design System vs "Chỉ là UI"
❌ Không có Design System
  • • 5 developer → 5 kiểu button khác nhau
  • • Đổi màu brand → sửa 200 file
  • • Spacing không nhất quán
  • • Component tương tự nhau × 10 bản
✅ Có Design System
  • • 1 Button component dùng khắp app
  • • Đổi màu brand → sửa 1 token
  • • Spacing 4px grid xuyên suốt
  • • Team nói cùng ngôn ngữ design
🎨
Design Tokens
Colors, spacing, typography, shadows
🧩
Components
Button, Input, Card, Modal...
📖
Guidelines
Khi nào dùng cái gì, tại sao
🎯 Key Takeaway
  • Design System = Single Source of Truth cho UI
  • Đầu tư ban đầu cao, nhưng tiết kiệm 10× về sau
  • Lớn hay nhỏ đều cần — chỉ khác về mức độ phức tạp
Khái niệm 02
Design Tokens
Tokens là các "biến thiết kế" — thay đổi 1 token → toàn bộ app cập nhật.
🔄 Demo tương tác — Đổi theme bằng cách đổi tokens
Thẻ sản phẩm
Thay đổi token → cả card thay đổi
🎯 Key Takeaway
  • Tokens = CSS variables, JS constants, hoặc JSON config
  • Thay đổi token ở 1 nơi → propagate khắp app tự động
  • Naming: --color-primary, --spacing-4, --font-size-lg

Contrast Ratio — WCAG AA Standard
Text trên nền phải có contrast ratio ≥ 4.5:1 (normal text) hoặc ≥ 3:1 (large text). Dùng công cụ: WebAIM Contrast Checker. Accessibility không phải optional.
🎯 Key Takeaway
  • Mỗi màu có semantic meaning — không dùng màu bừa
  • Primary palette: 10 shades (50-900), dùng 500 làm base
  • Semantic colors (success/warning/error) phải nhất quán xuyên app

🎯 Key Takeaway
  • Atoms → không thể chia nhỏ hơn và vẫn có ý nghĩa

  • Organisms → section của UI (Header, Footer, ProductGrid)
