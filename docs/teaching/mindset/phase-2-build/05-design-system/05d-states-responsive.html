States & Responsive

Component không tồn tại trong trạng thái tĩnh — chúng loading, error, empty, disabled. Responsive không phải "thu nhỏ", mà là thiết kế lại cho context.

7 States mọi Component cần

Thiếu state = bug UX. Mỗi button/form/card phải handle đủ 7 trạng thái:

Default
Hover
Focus
Active
Disabled
Loading
Success

Loading States — Skeleton vs Spinner

Skeleton loader cho content dạng list/card — giữ layout, giảm layout shift. Spinner cho action ngắn (<2s).

Rule: breakpoint khi content bị vỡ, không phải theo device size cứng. Mở browser → drag resize → stop khi thấy ugly.

Touch Targets — 44×44px Minimum

Apple HIG và Material Design đều yêu cầu 44px (iOS) / 48dp (Android) touch target. Nhỏ hơn = miss-tap = frustrated users.

🛠 Bài tập — States & Responsive Audit

  • 1Audit: Mở app, list tất cả buttons/forms. Check: có loading state không? Error state không? Disabled state không? Tạo checklist.
  • 2Implement skeleton loader cho 1 list component. Dùng animation: shimmer CSS — không dùng thư viện.
  • 3Resize browser từ 320px → 1280px. Ghi lại chính xác px khi layout bị vỡ → set breakpoints tại các điểm đó.
  • 4Inspect tất cả icon buttons: có min-width/height 44px không? Nếu không, add padding để đạt 44px hit area.
  • 5Test trên real device (hoặc Chrome DevTools Device Mode). List 3 điều trông khác trên mobile so với desktop simulator.

Key Takeaways

  • 7 states: default, hover, focus, active, disabled, loading, success/error — thiếu 1 là bug UX.
  • Skeleton loader cho content dạng list/card — giữ layout, giảm layout shift. Spinner cho action ngắn.
  • Mobile-first: design mobile trước → progressive enhance lên larger viewport.
  • Breakpoint khi content bị vỡ, không phải theo device size cứng.
  • Touch target minimum 44px × 44px — dùng padding để enlarge hit area mà không thay đổi visual.
