ERD Modeling

Entity Relationship Diagram — vẽ trước khi code. Một ERD tốt ngăn chặn 80% data architecture bugs trước khi chúng xảy ra.

Vì sao cần model trước?

😱
Không model: 3 tháng sau, order table có 50 cột, product_name lưu cả trong order lẫn product, giá thay đổi thì order cũ sai, query JOIN phức tạp không ai hiểu.
✅
Có model: ERD 30 phút ở đầu → relationships rõ ràng, data không duplicate, schema thay đổi dễ dàng, team mới đọc được ngay.

Cardinality — Quan hệ giữa Entities

Ký hiệuNghĩaVí dụ
1:1Một-MộtUser — UserProfile (mỗi user có 1 profile)
1:NMột-NhiềuUser — Orders (1 user có nhiều orders)
N:1Nhiều-MộtOrders — User (nhiều orders của 1 user)
M:NNhiều-NhiềuProducts — Tags (1 product nhiều tags, 1 tag nhiều products)

M:N luôn cần junction table (bảng trung gian): ProductTags(productId, tagId).

From ERD → Mongoose Schema

// ERD entity → Mongoose Schema @Schema({ timestamps: true }) export class Order { // FK → ref: 'User' (lazy loading via populate) @Prop({ type: Types.ObjectId, ref: 'User', required: true }) userId: Types.ObjectId; @Prop({ enum: ['pending', 'paid', 'shipped', 'done'], default: 'pending' }) status: string; @Prop({ required: true }) totalAmount: number; } @Schema() export class OrderItem { @Prop({ type: Types.ObjectId, ref: 'Order', required: true }) orderId: Types.ObjectId; @Prop({ required: true }) priceAtTime: number; // snapshot giá lúc mua! }

🛠 Bài tập — Vẽ ERD

  • 1Cho project hiện tại: list tất cả "nouns" (danh từ) trong domain — đây là candidate entities.
  • 2Với mỗi entity: xác định attributes (fields) và primary key.
  • 3Vẽ relationships: entity nào "có" entity nào? Cardinality là 1:1, 1:N, hay M:N?
  • 4Identify M:N relationships → tạo junction table với composite PK hoặc FK pair.
  • 5Review: có chỗ nào lưu snapshot không? (như priceAtTime). Data nào cần snapshot khi thay đổi theo thời gian?

Key Takeaways

  • ERD = vẽ data model trước khi code. 30 phút vẽ ngăn 3 tháng refactor.
  • Entities = danh từ domain. Attributes = properties. Relationships = verbs (User "places" Order).
  • 4 cardinalities: 1:1, 1:N, N:1, M:N. M:N luôn cần junction table.
  • Snapshot pattern: lưu giá trị tại thời điểm (priceAtTime) khi data gốc thay đổi theo thời gian.
  • FK trong DB → ref trong Mongoose → JOIN/populate khi query.
