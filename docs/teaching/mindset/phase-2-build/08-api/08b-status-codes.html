HTTP Status Codes

Status code là ngôn ngữ của API. Client biết phải làm gì dựa vào code — không phải body message. Dùng sai code = client xử lý sai, frontend bug, retry storm.

5 Nhóm Status Code

2xx

Success — Request thành công

200
OK
GET/PATCH/PUT success. Body có data.
201
Created
POST tạo resource mới. Location header.
204
No Content
DELETE thành công. Không có body.
202
Accepted
Request nhận, xử lý async (background job).
3xx

Redirect — Tìm ở chỗ khác

301
Moved Permanently
URL đã đổi vĩnh viễn. SEO safe.
302
Found (Temp)
Redirect tạm thời.
304
Not Modified
Cache vẫn còn valid. Không trả body.
4xx

Client Error — Lỗi từ phía client

400
Bad Request
Request format sai, validation fail.
401
Unauthorized
Chưa authen. Token missing/expired.
403
Forbidden
Đã authen, không có permission.
404
Not Found
Resource không tồn tại.
409
Conflict
Duplicate: email đã tồn tại.
422
Unprocessable
Format ok, nhưng semantic fail.
429
Too Many Requests
Rate limit hit. Retry-After header.
5xx

Server Error — Lỗi phía server

500
Internal Server Error
Unexpected error. Log ngay.
502
Bad Gateway
Upstream service trả response xấu.
503
Service Unavailable
Server overload / maintenance.
504
Gateway Timeout
Upstream không response kịp.

Common Mistakes — Sai code phổ biến

200
Return 200 cho tất cả, kể cả lỗi: {"success": false, "error": "Not found"}. Client không biết phải retry hay show error.
404
Return 404 khi resource không tồn tại. 401 khi thiếu token. 403 khi không có quyền.
401
Dùng 401 cho "no permission" — sai! 401 = unauthenticated (chưa login). 403 = unauthorized (đã login, không có quyền).
403
Đã login nhưng muốn xem data của user khác → 403 Forbidden. Chưa login → 401 Unauthorized.
400
Return 400 cho "email đã tồn tại" — 400 cho format error, không phải business conflict.
409
409 Conflict cho duplicate resource (email, username đã tồn tại).

Quick Quiz — Chọn đúng status code

User DELETE /posts/999 nhưng post không tồn tại. Server trả gì?
User gửi POST /orders nhưng không có Authorization header. Trả gì?
POST /products tạo thành công sản phẩm mới. Trả gì?

🛠 Bài tập — Status Code Audit

  • 1Grep toàn bộ codebase: tìm tất cả chỗ return 200 với error message trong body. List những chỗ cần fix.
  • 2Tạo global exception filter trong NestJS. Map domain exceptions → đúng HTTP status codes.
  • 3Test edge cases: gửi request với JWT expired → verify 401. Gửi JWT của user A để xem data user B → verify 403.
  • 4Implement rate limiter (NestJS throttler). Gửi >X requests/minute → verify 429 với Retry-After header.
  • 5Review: DELETE endpoint của bạn có trả 204 No Content không? Nếu trả 200 với empty body → fix.

Key Takeaways

  • 2xx = success, 3xx = redirect, 4xx = client error, 5xx = server error.
  • Quan trọng: 401 (unauthenticated) vs 403 (unauthorized) — hai khái niệm khác nhau.
  • DELETE → 204 No Content. POST create → 201 Created + Location header.
  • Không bao giờ return 200 với error trong body — client không thể distinguish.
  • 429 Too Many Requests phải có Retry-After header để client biết đợi bao lâu.
