Auth & JWT

Authentication = "Anh là ai?" — JWT. Authorization = "Anh được phép làm gì?" — RBAC/ABAC. Hiểu rõ sự khác biệt trước khi code bất kỳ feature bảo mật nào.

Authentication vs Authorization

🔐 Authentication (AuthN)

Xác minh danh tính: "Bạn là ai?"

  • • Login: email + password
  • • Token: JWT, session cookie
  • • MFA: OTP, biometric
  • • OAuth: "Login với Google"
Status: 401 Unauthorized khi fail

🛡️ Authorization (AuthZ)

Kiểm tra quyền: "Bạn được làm gì?"

  • • RBAC: role-based (admin, user)
  • • ABAC: attribute-based
  • • Resource ownership check
  • • Feature flags, scopes
Status: 403 Forbidden khi fail

JWT — Bấm vào từng phần để decode

JWT = 3 phần nối bằng dấu chấm: Header.Payload.Signature. Base64URL encoded — không phải encrypted (không lưu secret ở đây!):

.
SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
📋 Header (algorithm + type)
{
  "alg": "HS256", // HMAC SHA-256
  "typ": "JWT"
}
📦 Payload (claims — đọc được, không secret!)
{
  "userId": "usr_123",
  "email": "do@astools.app",
  "role": "user",
  "iat": 1724000000, // issued at
  "exp": 1724086400 // expires at (24h)
}
🔏 Signature (không thể fake nếu không có secret)
HMACSHA256(
  base64(header) + "." + base64(payload),
  SECRET_KEY ← chỉ server biết
)

Thay đổi payload → signature không match → token invalid. Không thể forge.

JWT Auth Flow — Login đến Protected Resource

1 → Client POST /auth/login { email, password }
2 ⚙️ Server Verify password → hash compare. Generate JWT với userId, role. Sign với SECRET_KEY.
3 ← Response { accessToken: "eyJ...", refreshToken: "..." }
4 → Client GET /api/orders — Authorization: Bearer eyJ...
5 ⚙️ Guard Verify signature với SECRET_KEY. Check exp. Extract payload → req.user.
6 ← Response 200 + orders data (scoped to req.user.userId)

JWT Guard — NestJS

// auth.guard.ts @Injectable() export class JwtAuthGuard extends AuthGuard('jwt') {} // JWT Strategy @Injectable() export class JwtStrategy extends PassportStrategy(Strategy) { constructor() { super({ secretOrKey: process.env.JWT_SECRET, jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken() }); } validate(payload: JwtPayload) { return { userId: payload.userId, role: payload.role }; } } // Protected Controller @UseGuards(JwtAuthGuard) @Get('profile') getProfile(@CurrentUser() user: User) { return this.service.getProfile(user.userId); }

JWT Security Best Practices

✅ Access token ngắn (15-60 phút) + Refresh token dài (7-30 ngày) để giảm exposure window
✅ Lưu token an toàn: HttpOnly cookie (web) hoặc SecureStorage (mobile). Không localStorage!
✅ JWT payload chỉ chứa non-sensitive data: userId, role. Không password, không PII.
❌ Không để SECRET_KEY trong code — chỉ environment variable. Rotate định kỳ.
❌ Không tin payload trước khi verify signature — attacker có thể modify payload nếu dùng algorithm=none.

🛠 Bài tập — Implement JWT Auth

  • 1Cài @nestjs/jwt, @nestjs/passport, passport-jwt. Configure JwtModule với SECRET từ env.
  • 2Implement login endpoint: verify password (bcrypt.compare) → sign JWT với {userId, role, exp: '1h'}.
  • 3Tạo JwtAuthGuard và @CurrentUser() decorator. Apply guard lên 1 protected route.
  • 4Test: gửi request với expired token → verify 401. Với valid token của user A để xem data user B → verify 403.
  • 5Bonus: implement refresh token rotation. Khi access token expire → use refresh token để lấy access token mới.

Key Takeaways

  • Authentication (401) = xác minh danh tính. Authorization (403) = kiểm tra quyền. Hai khái niệm độc lập.
  • JWT = Header.Payload.Signature. Payload đọc được (không secret), Signature đảm bảo integrity.
  • Access token ngắn (1h) + Refresh token dài (7d). Lưu trong HttpOnly cookie, không localStorage.
  • Payload chỉ chứa non-sensitive data — không password, không card numbers.
  • Verify signature TRƯỚC KHI trust payload. Không bao giờ dùng algorithm=none.
