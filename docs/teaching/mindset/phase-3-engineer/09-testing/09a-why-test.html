09a · Testing

Why Test?

Không phải để chứng minh code đúng. Mà để nhận biết ngay khi code bị sai — trước khi user nhận ra. Tests là safety net, không phải overhead.

Tests làm được gì cho bạn?

  • 🛡️
    Safety Net khi Refactor
    Thay đổi implementation → test vẫn xanh → confident. Không test → mỗi refactor là roulette.
  • 📚
    Living Documentation
    Test code mô tả "how it should behave" tốt hơn comment. Test không bao giờ lỗi thời như docs.
  • 🎯
    Instant Bug Detection
    CI chạy tests mỗi commit → bug bị phát hiện trong vài phút, không phải vài tuần.
  • 🏗️
    Force Better Design
    Code khó test = code kết hợp quá chặt. Tests buộc bạn phân tách concerns đúng.
  • 💬
    Confident Code Review
    PR có tests → reviewer biết behavior đã được verify. PR không có tests → reviewer phải guess.

Test đầu tiên — 10 dòng

// order.service.spec.ts — Jest describe('OrderService', () => { it('should calculate total correctly', () => { // Arrange const items = [ { name: 'Laptop', price: 500, qty: 1 }, { name: 'Mouse', price: 25, qty: 2 }, ]; // Act const total = calculateOrderTotal(items); // Assert expect(total).toBe(550); // 500 + 25*2 }); it('should return 0 for empty order', () => { expect(calculateOrderTotal([])).toBe(0); }); });

AAA pattern: Arrange (setup) → Act (execute) → Assert (verify). Mỗi test chỉ test 1 thing.

🛠 Bài tập — First Tests

  • 1Tìm 1 pure function trong codebase (input → output, không side effect). Ví dụ: price calculation, discount logic.
  • 2Tạo .spec.ts file. Viết 3 test cases: happy path, edge case (0/null/empty), error case.
  • 3Chạy npx jest --watch. Thay đổi implementation → xem test fail ngay lập tức.
  • 4Tính: bao nhiêu thời gian bạn đã dành để debug bug mà một test đơn giản đã bắt được?
  • 5Commit với message "test: add unit tests for X function". PR review bước tiếp theo.

Key Takeaways

  • Bug tìm ở Production = 100× đắt hơn ở Development. Tests là investment.
  • Tests không chứng minh code đúng — chúng giúp phát hiện khi code bị sai.
  • Tests = safety net cho refactor, living documentation, và CI gate.
  • Code khó test = design problem. Testability forces better separation of concerns.
  • Bắt đầu với pure functions — input/output, không side effects. 10 dòng test = 10 dòng insurance.
