09c · Testing

Unit Testing

Unit test = test 1 unit logic trong isolation. AAA pattern: Arrange → Act → Assert. Test behavior, không phải implementation.

AAA Pattern — Cấu trúc mọi unit test

A
Arrange

Setup: tạo input data, mock dependencies, initialize SUT

A
Act

Execute: gọi function/method cần test với prepared input

A
Assert

Verify: kết quả đúng với expectation? Error đúng type?

Complete Unit Test — Service with Mock

// product.service.spec.ts describe('ProductService', () => { let service: ProductService; let mockRepo: jest.Mocked<ProductRepository>; beforeEach(async () => { // Arrange: setup module with mock repo const module = await Test.createTestingModule({ providers: [ ProductService, { provide: ProductRepository, useValue: { findById: jest.fn() } } ], }).compile(); service = module.get(ProductService); mockRepo = module.get(ProductRepository); }); describe('findById', () => { it('should return product when found', async () => { // Arrange const mockProduct = { id: 'p1', name: 'Laptop', price: 500 }; mockRepo.findById.mockResolvedValue(mockProduct); // Act const result = await service.findById('p1'); // Assert expect(result).toEqual(mockProduct); expect(mockRepo.findById).toHaveBeenCalledWith('p1'); }); it('should throw NotFoundException when not found', async () => { mockRepo.findById.mockResolvedValue(null); await expect(service.findById('unknown')) .rejects.toThrow(NotFoundException); }); }); });

What to Test — và Không Test

✅ Nên test

  • ✓ Business logic, calculations
  • ✓ Edge cases (null, 0, empty array)
  • ✓ Error conditions (not found, unauthorized)
  • ✓ Transformations/mappings
  • ✓ Complex conditional logic
  • ✓ Validation rules

⚠️ Không cần test

  • ✗ Getters/setters trivial
  • ✗ Constructor chỉ assign fields
  • ✗ Framework magic (decorators)
  • ✗ Third-party library internals
  • ✗ Implementation details (private)
  • ✗ Type definitions

Test Coverage — Mục tiêu thực tế

75%
coverage
✅ Good coverage. Focus on critical paths.
Target: 80% cho business logic.
100% = overkill. Test logic, không test code paths vô nghĩa.

🛠 Bài tập — Write Real Unit Tests

  • 1Chọn OrderService.calculateTotal(). Viết tests: empty array → 0, 1 item, multiple items, negative price (should throw).
  • 2Mock ProductRepository. Test Service.findById(): found case, not-found → NotFoundException, DB error → rethrow.
  • 3Chạy npx jest --coverage. Xem report. List 3 uncovered paths quan trọng nhất → add tests.
  • 4Refactor 1 test đang test implementation (checking internal state) → test behavior (checking output/exception).

Key Takeaways

  • AAA: Arrange (setup) → Act (execute) → Assert (verify). Mỗi test 1 thing.
  • Test behavior, không test implementation. Refactor implementation → tests vẫn xanh.
  • Mock dependencies (repo, external services) để isolate unit logic.
  • Target 80% coverage cho business logic. 100% = thường là over-testing.
  • expect(...).rejects.toThrow() cho async error cases — đừng quên await.
