🗺️ Debugging Process

Click từng bước để xem chi tiết.

🐛 Bug Reported
Bước đầu: Đừng panic. Thu thập thông tin: ai báo, khi nào, platform nào, error message gì?
↓
🔁 Reproduce
Quan trọng nhất! Nếu không reproduce được → không fix được. Hỏi: môi trường, bước thực hiện, tần suất xảy ra?
↓
🔎 Gather Evidence
Đọc logs, stack traces, network requests. Ghi lại tất cả. Đừng assume — observe.
↓
💡 Form Hypothesis
Đặt giả thuyết: "Tôi nghĩ bug xảy ra vì X." Chỉ một giả thuyết mỗi lần — đừng test nhiều cùng lúc.
↓
🧪 Experiment
Test giả thuyết bằng cách thay đổi một điều và quan sát. Console.log, breakpoint, hoặc viết test.
↓
🎯 Root Cause
Tìm được root cause — không phải symptom. "Server crash" là symptom, "null pointer vì API không validate" là root cause.
↓
✅ Fix + Regression Test
Fix rồi viết test cho case đó — để bug không quay lại. → Bài 9: Regression test

🔀 Git Bisect — Binary Search qua commits

"Bug xuất hiện lúc nào?" — Bisect chia đôi history để tìm commit gây ra bug. → Bài 11: Git workflow chi tiết

🐞 Common Bug Patterns

SymptomLikely CauseHow to Verify
Works locally, fails productionEnvironment difference (DB, env vars, OS)So sánh .env, check Docker logs
Intermittent failureRace condition / timing issueAdd delays, check async/await missing
Only fails under loadResource leak hoặc concurrency bugLoad test + memory/CPU monitoring
First request OK, subsequent failShared state / cache pollutionCheck static variables, connection pool
Works with one user, fails with multipleRace condition / missing mutexLog timestamps, trace request IDs
"It was working yesterday"Recent deployment / dependency updategit log --oneline -20, check package-lock

⚠️ Debugging Anti-patterns

❌ "Nó chạy rồi!" (không hiểu tại sao)

Xóa một dòng random → hết lỗi → commit. Tuần sau bug quay lại dưới dạng khác.

Fix: Luôn hiểu root cause trước khi merge.

❌ "Thử restart xem sao"

Restart hide bug — memory leak tạm biến mất, nhưng nguyên nhân vẫn còn.

Fix: Reproduce bug, đừng mask nó.

❌ "Đổi random thứ và test"

Thay đổi nhiều thứ cùng lúc → không biết cái nào fix bug.

Fix: Một thay đổi, một test — scientific method.

❌ "Chắc là cache" (không verify)

Cache invalidation là excuse phổ biến — thường là logic bug thật sự.

Fix: Verify hypothesis với evidence.

🏋️ Exercises — Bài 10: Debugging
Ex 1 🟢 Dễ Đọc stack trace → xác định file và dòng gây lỗi

Cho stack trace sau, xác định: (1) Error type là gì? (2) Bug nằm ở file nào, dòng bao nhiêu? (3) Function nào gọi function bị lỗi?

ReferenceError: orderId is not defined
    at PaymentService.processPayment (payment.service.ts:89:15)
    at CheckoutController.checkout (checkout.controller.ts:34:10)
    at /node_modules/@nestjs/core/router/router-proxy.js:9:17
    at processTicksAndRejections (node:internal:99:5)
👁️ Xem phân tích

Error type: ReferenceError — biến orderId được dùng nhưng chưa được khai báo.

Bug location: payment.service.ts dòng 89, cột 15.

Caller: CheckoutController.checkout tại checkout.controller.ts:34. Kiểm tra xem controller có truyền orderId đúng vào service không.

Fix direction: Mở payment.service.ts dòng 89, kiểm tra xem orderId được đến từ đâu — parameter? destructuring? scoping issue?

Ex 2 🟢 Dễ 5 Whys: "API trả về 500" → drill down tìm root cause

Symptom: "POST /api/orders luôn trả về 500 Internal Server Error sau 14:00 mỗi ngày." Áp dụng 5 Whys để tìm root cause. Viết 5 cặp Why → Because.

👁️ Xem một luồng phân tích mẫu

Why 1: API trả 500 → Vì unhandled exception trong OrderService

Why 2: Unhandled exception → Vì DB query throw khi connection pool exhausted

Why 3: Connection pool exhausted → Vì connections không được release sau query

Why 4: Connections không release → Vì dev dùng raw query trong try block mà thiếu finally { conn.release() }

Why 5 (Root): Thiếu finally → Vì không có lint rule / code review checklist về resource cleanup

→ Fix: Thêm ESLint plugin database rules + update PR template với DB connection checklist

Ex 3 🟡 Trung bình Network debugging: request trả về 200 nhưng data sai → tìm nguyên nhân

API GET /api/products?category=electronics trả về HTTP 200 nhưng response body chứa ALL products (không filter). Liệt kê ít nhất 5 nguyên nhân có thể và cách kiểm tra từng nguyên nhân.

👁️ Xem checklist debug
  1. Query param không được đọc: log req.query — có nhận được { category: 'electronics' } không?
  2. Filter logic bị skip: Check if/else condition trong service — có case nào bypass filter?
  3. DB query sai: Log raw query được tạo ra — WHERE clause có category filter không?
  4. Cache hit: Redis cache đang serve cached response không có filter. Purge cache và retry.
  5. Field name mismatch: DB column là categoryId nhưng query filter category → no match → return all.
Ex 4 🟡 Trung bình Performance debugging: API response 3s → profile tìm bottleneck

GET /api/dashboard mất 3 giây. Sử dụng systematic approach để tìm bottleneck. Gợi ý: đo từng layer (network, app logic, DB, external APIs).

👁️ Xem profiling approach 
// Step 1: Add timing logs
async getDashboard() {
  const t0 = Date.now();
  const users = await this.userRepo.count();
  console.log('users count:', Date.now() - t0); // 2800ms! ← bottleneck

  const t1 = Date.now();
  const orders = await this.orderRepo.findRecent();
  console.log('orders:', Date.now() - t1); // 50ms
}

// Step 2: EXPLAIN ANALYZE the slow query
// SELECT COUNT(*) FROM users → missing index on status field
// Fix: CREATE INDEX idx_users_status ON users(status);
// Result: 2800ms → 12ms
Ex 5 🔴 Khó Production incident: chỉ có error log, tìm bug và fix

Chỉ có log này từ production lúc 3am. Không có reproduce. Phân tích và đề xuất fix + monitoring improvement.

ERROR [2026-08-14 03:17:42] Unhandled Promise Rejection
Error: connect ECONNREFUSED 127.0.0.1:5432
    at TCPConnectWrap.afterConnect [as oncomplete] (net.js:1141:16)

--- 30 seconds later ---
ERROR [03:17:72] PaymentService.processPayment: Database unavailable
--- requests timing out ---
ERROR [03:18:01] Request timeout after 30000ms: POST /api/payments
ERROR [03:18:01] Request timeout after 30000ms: GET /api/orders
--- ALL requests failing now ---
👁️ Xem phân tích + action plan

Root cause: PostgreSQL database ở localhost:5432 không connect được. ECONNREFUSED = DB service đã down.

Immediate fix: Kiểm tra DB service status → systemctl status postgresql hoặc docker ps. Restart DB.

Long-term fix:

  • Health check endpoint GET /health → kiểm tra DB connection
  • Connection retry với exponential backoff
  • Circuit breaker cho DB calls
  • Monitoring alert khi DB connection pool < 20%

5 Whys next step: DB down → tại sao? Disk full? Out of memory? Scheduled maintenance? → Dig deeper.

🎯 Key Takeaways

  • ✅ Reproduce trước, fix sau. Không reproduce được = không fix được đúng chỗ
  • ✅ 5 Whys: luôn đào đến root cause, không dừng ở symptom
  • ✅ Stack trace: tìm dòng đầu tiên thuộc project của bạn
  • ✅ Một giả thuyết, một thay đổi, một test — scientific debugging
  • ✅ "It works now" mà không hiểu tại sao = bug chưa được fix, chỉ bị ẩn
  • ✅ Sau mỗi bug fix → viết regression test để không tái phát
