Debug Process

A systematic 7-step approach that finds bugs faster than random printf()ing.

The 7-Step Debug Flow

Click each step to see details and common mistakes.

1
Reproduce the bug reliably
▶
Before anything else — can you make it happen again? A bug you can't reproduce is a bug you can't fix.

Ask: What's the exact input? What's the environment? What version? What user state?

Write a failing test that triggers it: it('should fail', () => expect(fn(badInput)).toThrow())
2
Understand the expected vs actual
▶
Write it down explicitly: "I expected X, but got Y." Sounds obvious — but doing it forces clarity.

"The button should show 'Saved' but shows 'Error' after clicking with valid data."

This one sentence eliminates half the confusion about what you're actually fixing.
3
Isolate — narrow the blast radius
▶
Binary search your codebase. Comment out half. Does the bug remain? It's in the other half.

Use git bisect for regressions. Strip down to the minimal reproducing case.

Each step should cut the possible locations in half.
4
Form a hypothesis
▶
Make a specific, falsifiable guess: "I think the userId is undefined because the JWT middleware runs after the route handler."

NOT: "Something is wrong with auth." (too vague)

A good hypothesis tells you exactly what evidence would prove it wrong.
5
Test the hypothesis
▶
Add a log, a breakpoint, or a unit test that either confirms or refutes your guess.

console.log('[debug] userId at handler entry:', req.user?.id)

If the log shows userId IS defined → hypothesis wrong → go back to step 4 with new info.
6
Fix and verify
▶
Apply the minimal fix. Run the failing test from step 1 — it must now pass.

Check: does anything else break? Run the full test suite. Don't just verify the symptom — verify the system.

Remove debug logs. Clean up. Commit with a meaningful message.
7
Write the post-mortem
▶
One paragraph: What broke? Why? How was it found? How was it fixed? What prevents recurrence?

This is not punishment — it's institutional memory. The bug that killed your 3am is now in a document that saves the next person 3 hours.

Add to LESSONS.md or a team wiki. Knowledge that stays in one head is a single point of failure.

Common Bug Patterns

Off-by-One

Array index confusion, loop boundary errors. Always ask: should this be < or ≤? 0-indexed or 1-indexed?

Null / Undefined

Property access on undefined. Check: can this be falsy? Use optional chaining obj?.prop defensively.

Race Condition

Two async ops compete. Works on fast machine, fails on slow server. Use locks, queues, or idempotency.

State Mutation

Shared object modified in place. Caller sees unexpected state. Prefer immutable updates: {...obj, field: newVal}

Environment Mismatch

"Works on my machine." Different Node version, OS path sep, env var missing, timezone offset.

Anti: Shotgun Debugging

Randomly changing things hoping one sticks. Dangerous — masks root cause, introduces new bugs.

🔬 Exercise — Apply the 7 Steps

Scenario: Your NestJS endpoint POST /orders returns 500 intermittently in production but never in local dev.

  1. Write the exact reproduce steps you'd ask a user for
  2. State expected vs actual in one sentence
  3. Name 3 places to add isolation logs (middleware, service, repository)
  4. Form one specific falsifiable hypothesis about the cause
  5. What test would confirm or deny it?
  6. After fixing — what goes in the post-mortem?

Key Takeaways

  • Reproduce first — unfalsifiable bugs can't be fixed
  • Write expected vs actual in one sentence before touching code
  • Binary search the codebase — don't read every line
  • Form falsifiable hypotheses, not vibes
  • Always run the full test suite after the fix
  • Post-mortems turn individual pain into team knowledge
