Debug Tools

console.log, the debugger, and network tools — when to use which, and how to use them right.

Tool Comparison

ToolBest forLimitationsSkill
console.log Quick value inspection, tracing flow, production where no debugger Clutters code, easy to forget, no execution control Beginner
Debugger / Breakpoints Complex logic, stepping through, inspecting all variables at once Requires IDE setup, harder in prod, async can jump around Intermediate
Network (DevTools) API calls, headers, payload shape, timing, CORS errors Browser/HTTP only, can't see server internals Intermediate
Logger (Winston/Pino) Production debugging, structured search, log levels Requires log aggregation setup (ELK, Datadog) Advanced

Tool Details

console.log
Debugger
Network

The most-used and most-abused debug tool. Learn to use it well.

// ❌ Bad — tells you nothing useful
console.log('here');
console.log(data);

// ✅ Good — labeled, structured
console.log('[OrderService.create] input:', { userId, items });
console.log('[OrderService.create] db result:', order?.id);

// ✅ Better — use console.table for arrays
console.table(orders.map(o => ({ id: o.id, status: o.status })));

// ✅ Trace — shows call stack
console.trace('How did we get here?');

// ✅ Group related logs
console.group('Processing order');
console.log('Validating...');
console.log('Saving...');
console.groupEnd();

Rule: Always label with [Module.method], always remove before commit. Use a grep before pushing: git diff | grep 'console.log'

Pause execution, inspect state, step through logic line by line.

// In code — trigger programmatic breakpoint
debugger;  // Pauses when DevTools is open

// VS Code launch.json for NestJS debugging
{
  "type": "node",
  "request": "launch",
  "name": "Debug NestJS",
  "runtimeArgs": ["--inspect"],
  "program": "${workspaceFolder}/src/main.ts",

}

Key debugger controls:

ActionShortcutWhat it does
Step OverF10Run current line, go to next
Step IntoF11Enter function call
Step OutShift+F11Finish function, return to caller
ContinueF5Run until next breakpoint

Chrome DevTools → Network tab is your HTTP inspector.

What to check in Network tab

Status code • Request URL • Request method • Request headers (Authorization, Content-Type) • Request body (Payload tab) • Response body • Timing (TTFB, download)

🔬 Exercise — Tool Selection

For each scenario, choose the right tool and explain why:

  1. A function returns wrong value — you don't know which line
  2. An API call returns 401 but you sent the token
  3. A NestJS service crashes but only sometimes in production
  4. You need to inspect a complex object with 50 fields
  5. You want to know the call stack when a value is set

Key Takeaways

  • console.log = quick, dirty, and forgotten in commits — label everything
  • Debugger = powerful for complex logic — learn step over/into/out
  • Network tab = first stop for any API mystery — check status + headers + payload
  • Production = structured logs (Winston/Pino), not console.log
  • Rule of thumb: use the simplest tool that answers the question
