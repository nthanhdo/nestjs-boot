🌿 Branch — Tách nhánh làm việc song song

Branch cho phép nhiều người (hoặc nhiều feature) phát triển song song. → Bài 9: Test trước khi merge

# Làm việc, commit...

# Merge về main sau khi review

📝 Commit Messages — Good vs Bad

Commit message là documentation. → Bài 3: Clean code = clean commits

✅ Good (Conventional Commits)

fix(cart): prevent negative quantity on update
refactor(order): extract price calculation to service
docs(api): add OpenAPI annotations to /orders

Format: type(scope): short description

🔀 Merge vs Rebase

✅ Dùng khi:

  • Merge feature branch vào main
  • PR/MR workflow

⚠️ Trade-off:

  • Tạo thêm merge commit
  • History phức tạp hơn
git merge feature/payment
# → Tạo merge commit

✅ Dùng khi:

  • Cập nhật feature branch với main
  • Muốn linear history

⚠️ Nguy hiểm:

  • NEVER rebase shared branches
  • Rewrite history → force push → chaos
git fetch origin
git rebase origin/main
# ⚠️ Chỉ rebase branch CHỈ BẠN đang dùng!

Ex 2 🟢 Dễ Resolve merge conflict (cho 2 versions, student merge)

Resolve conflict dưới đây và giải thích quyết định giữ phiên bản nào:

<<<<<<< HEAD (your branch)
async calculateTotal(items: Item[]): Promise<number> {
  return items.reduce((sum, item) => sum + item.price * item.qty, 0);
}
=======
async calculateTotal(items: Item[]): Promise<number> {
  const subtotal = items.reduce((sum, item) => sum + item.price * item.qty, 0);
  return subtotal * (1 - this.discountRate);
}
>>>>>>> feature/discount
👁️ Xem resolution

Giữ phiên bản feature/discount — có business value (discount logic):

async calculateTotal(items: Item[]): Promise<number> {
  const subtotal = items.reduce((sum, item) => sum + item.price * item.qty, 0);
  return subtotal * (1 - this.discountRate);
}

Sau đó: git add . && git commit -m "merge: keep discount logic in calculateTotal"

Ex 4 🟡 Trung bình Code review: review PR của "teammate" → đưa 5 feedback comments

Review đoạn code, viết 5 constructive comments (explain tại sao + suggest fix):

async getUser(id: any) {
  const user = await db.query(`SELECT * FROM users WHERE id = ${id}`);
  if (user) {
    sendEmail(user.email, "Welcome back!");
  }
  return user;
}
👁️ Xem 5 review comments
  1. SQL Injection: Template literal trong query = SQL injection risk. Dùng parameterized: WHERE id = $1
  2. Type any: id: any — specify string | number. TypeScript any hides bugs.
  3. Side effect: Sending email trong getter là unexpected. Extract sang caller hoặc separate method.
  4. No error handling: DB có thể throw. Add try/catch hoặc để global exception filter handle.
  5. SELECT *: Specify columns cần thiết, tránh over-fetching và breaks khi schema đổi.
Ex 5 🔴 Khó Release: tag v1.2.0 → hotfix v1.2.1 → continue v1.3.0 development

Simulate release workflow: tag v1.2.0, phát hiện critical security bug, tạo hotfix v1.2.1, rồi tiếp tục v1.3.0.

👁️ Xem release workflow 
# 1. Tag release v1.2.0
git checkout main
git tag -a v1.2.0 -m "Release v1.2.0 — product search"
git push origin v1.2.0

# 2. Critical bug! Hotfix branch từ tag
git checkout -b hotfix/v1.2.1 v1.2.0
git commit -m "fix(auth): prevent JWT token bypass on /admin routes"

# 3. Tag hotfix + merge về main
git tag -a v1.2.1 -m "Hotfix v1.2.1 — security patch"
git checkout main
git merge hotfix/v1.2.1
git push origin main v1.2.1

# 4. Merge hotfix vào develop (không mất fix)
git checkout develop
git merge hotfix/v1.2.1
git branch -d hotfix/v1.2.1

# 5. Continue v1.3.0
git checkout -b feature/notifications origin/develop
