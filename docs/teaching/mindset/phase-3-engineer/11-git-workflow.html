🌿 Branch — Tách nhánh làm việc song song

Branch cho phép nhiều người (hoặc nhiều feature) phát triển song song mà không ảnh hưởng nhau.

# Tạo và switch sang branch mới
git checkout -b feature/user-authentication

# Làm việc, commit...
git add src/auth/
git commit -m "feat(auth): add JWT login endpoint"

# Merge về main sau khi review
git checkout main
git merge feature/user-authentication

📝 Commit Messages — Good vs Bad

Commit message là documentation. Sau 6 tháng, bạn (và đồng đội) sẽ đọc lại nó.

❌ Bad

fix bug
update
wip
asdfgh
đã sửa cái lỗi hôm qua

Sau 3 tháng: không biết commit này làm gì, tại sao, ảnh hưởng gì.

✅ Good (Conventional Commits)

feat(auth): add OAuth2 Google login
fix(cart): prevent negative quantity on update
refactor(order): extract price calculation to service
docs(api): add OpenAPI annotations to /orders
chore(deps): upgrade NestJS to 10.4.1

Format: type(scope): short description. Dễ filter, dễ changelog auto-gen.

🔀 Merge vs Rebase

Cả hai đều combine branches — nhưng khác nhau về history.

✅ Dùng khi:

  • Merge feature branch vào main
  • Muốn giữ đầy đủ branch history
  • PR/MR workflow

⚠️ Trade-off:

  • Tạo thêm merge commit
  • History phức tạp hơn
# Trên main branch:
git merge feature/payment
# → Tạo merge commit: "Merge branch 'feature/payment'"
# → History: A-B-C-D-E-F (M)

✅ Dùng khi:

  • Cập nhật feature branch với main mới nhất
  • Muốn linear history
  • Cleanup commits trước khi PR

⚠️ Nguy hiểm:

  • NEVER rebase shared branches
  • Rewrite history → force push → chaos
# Trên feature branch — cập nhật với main:
git fetch origin
git rebase origin/main
# → Commits của bạn được "replay" lên đầu main
# → Linear history: A-B-C-D'-E' (không có merge commit)
# ⚠️ Chỉ rebase branch mà CHỈ BẠN đang dùng!

⚔️ Conflict Resolution

Bước 1: Detect

CONFLICT (content): Merge conflict in
src/order/order.service.ts

Bước 2: Understand

<<<<<<< HEAD (current)
  return price * 0.9;
=======
  return price * quantity;
>>>>>>> feature/bulk

Bước 3: Resolve + Test

// Giữ cả hai logic:
  return price * quantity * 0.9;
// Xóa markers, chạy test
git add . && git commit

🎯 Key Takeaways

  • ✅ Git = 4 vùng: Working Dir → Staging → Local → Remote. Biết file đang ở vùng nào
  • ✅ Branch sớm, branch thường — mỗi feature/fix một branch riêng
  • ✅ Commit message = documentation. Conventional Commits giúp team đọc hiểu
  • ✅ Merge giữ history đầy đủ. Rebase tạo linear history — NEVER rebase shared branch
  • ✅ PR = code review cơ hội — không chỉ là merge button
  • ✅ SemVer: MAJOR.MINOR.PATCH — breaking/feature/fix
