🛡️ OWASP Top 10 — Click để xem NestJS example

A01:2021
🔓 Broken Access Control
NestJS: API /orders/:id không check ownership → user A xem được order của user B.

Fix: if (order.userId !== req.user.id) throw ForbiddenException
A02:2021
🔐 Cryptographic Failures
NestJS: Lưu password plaintext trong MongoDB.

Fix: bcrypt.hash(password, 12) trước khi save
A03:2021
💉 Injection
NestJS: Raw MongoDB query với user input không sanitized.

Fix: Dùng Mongoose model + class-validator DTO
A04:2021
🏗️ Insecure Design
NestJS: Password reset không rate-limit → brute force OTP.

Fix: throttle 3 attempts/hour, expire OTP 10 phút
A05:2021
⚙️ Security Misconfiguration
NestJS: CORS origin: '*' trên production, debug logs bật.

Fix: whitelist origins, disable stack trace on prod
A06:2021
📦 Vulnerable Components
NestJS: Dùng dependency có CVE đã known.

Fix: npm audit, Dependabot, update regularly
A07:2021
🔑 Auth Failures
NestJS: JWT secret là "secret" hardcoded, không rotate.

Fix: JWT_SECRET từ env, strong random 256-bit
A08:2021
🔧 Software Integrity Failures
NestJS: Download script không verify checksum.

Fix: package-lock.json, verify npm registry
A09:2021
📊 Logging Failures
NestJS: Log toàn bộ request body → log password, token.

Fix: redact sensitive fields trước khi log
A10:2021
🌐 SSRF
NestJS: axios.get(userInputUrl) → attacker fetch internal services.

Fix: Whitelist allowed URLs, block private IP ranges

🪪 Authentication vs Authorization

🪪

Authentication

"Bạn là ai?"

Verify identity. Login với username/password, Google OAuth, biometric.

🎫

Authorization

"Bạn được làm gì?"

Check permissions. Admin role, resource ownership, feature gates.

🔑 Password Security Evolution

Click từng giai đoạn để hiểu tại sao nó bị deprecated.

1990s
💀 Plaintext — password: "abc123"
Lưu nguyên văn trong DB. Nếu DB bị dump → tất cả passwords bị lộ. Vẫn có sites dùng năm 2024 (!). NEVER.
2000s
💀 MD5/SHA1 — hash: "5f4dcc3b..."
Hashing nhưng không có salt. Rainbow table attacks: precomputed hash lookup. MD5 crack trong giây. SHA1 không tốt hơn nhiều.
2010s
⚠️ SHA256 + Salt — hash(password + salt)
Tốt hơn MD5. Nhưng SHA256 quá NHANH — GPU có thể thử 10 tỷ combinations/giây. "Fast hash = bad for passwords."
2015+
✅ bcrypt — bcrypt.hash(password, 12)
Có cost factor — intentionally SLOW (100ms vs microseconds). Adaptive: tăng cost khi phần cứng mạnh hơn. Salt built-in. Vẫn được recommend.
2020+
🏆 Argon2 — Winner of Password Hashing Competition
Memory-hard: cần RAM lớn → GPU attacks kém hiệu quả hơn. 3 variants: argon2i (side-channel safe), argon2d (GPU resistant), argon2id (best of both). Recommendation hiện tại.

💉 Injection Attack — Live Demo

Gõ vào ô tìm kiếm để thấy query bị inject như thế nào.

Query được tạo ra:

❌ Vulnerable code

// Raw string interpolation:
const query = `
  db.products.find({
    name: "${userInput}"
  })`;
// Attacker: input = {"$gt": ""}
// → Trả về TẤT CẢ documents!

✅ Safe code

// Mongoose sanitized query:
const products = await
  Product.find({
    name: new RegExp(
      escapeRegex(input), 'i'
    )
  });
// User input never touches query operator

🛡️ Input Validation — First Line of Defense

❌ No validation

// Controller nhận gì cũng được
async createOrder(body: any) {
  await this.orderService
    .create(body);
  // body có thể chứa:
  // { price: -1000 }
  // { role: "admin" }
  // { __proto__: ... }
}

✅ class-validator DTO

class CreateOrderDto {
  @IsString()
  @MaxLength(100)
  productId: string;

  @IsInt()
  @Min(1) @Max(999)
  quantity: number;
}
// NestJS ValidationPipe reject
// bất kỳ field nào sai schema

📚 Real Case Study: Path Traversal

🚨 1 dòng code = security hole

Từ nestjs-boot codebase — file serve endpoint.

// ❌ VULNERABLE — Path Traversal Attack
async serveFile(filename: string) {
  const path = `./uploads/${filename}`;
  return fs.readFile(path);
  // Attacker: filename = "../../etc/passwd"
  // Đọc được: /etc/passwd (user list trên server)
  // Hoặc: "../.env" → lộ DATABASE_URL, JWT_SECRET
}

// ✅ FIXED — 1 dòng check:
async serveFile(filename: string) {
  const resolvedPath = path.resolve('./uploads', filename);
  if (!resolvedPath.startsWith(path.resolve('./uploads'))) {
    throw new ForbiddenException('Invalid file path');
  }
  return fs.readFile(resolvedPath);
}

Lesson: Mọi user input được dùng trong file system operations đều phải validate. Canonicalize path và check nằm trong allowed directory.

🎯 Key Takeaways

  • ✅ Security = mindset, không phải feature. Build-in từ đầu, không patch cuối
  • ✅ OWASP Top 10: bookmark và review mỗi feature mới
  • ✅ Authentication ("bạn là ai") ≠ Authorization ("bạn được làm gì")
  • ✅ Password: chỉ bcrypt hoặc Argon2. NEVER MD5/SHA1 cho passwords
  • ✅ JWT không encrypt payload — đừng để sensitive data trong đó
  • ✅ Validate mọi input — class-validator DTO trong NestJS là standard
  • ✅ Test negative cases trước: no key, fake key, wrong permission → MUST BLOCK
