Path Traversal

A single ../ sequence in a filename can expose your entire filesystem. A real case study.

The Attack

Imagine a file download endpoint: GET /files/download?name=invoice.pdf

Normal request (safe):

GET /files/download?name=invoice.pdf
Resolved: /var/app/uploads/invoice.pdf
✓ File served from expected directory

Attack request:

GET /files/download?name=../../../etc/passwd
Resolved: /var/app/uploads/../../../etc/passwd
→ /etc/passwd
🚨 System password file served! Attacker now has all usernames + shell info.

What's at Risk

/var/app/uploads/ ← intended directory
  invoice.pdf ← safe
  report.xlsx ← safe

/etc/
  passwd ← user list, shell paths
  shadow ← hashed passwords (if root)
  nginx/nginx.conf ← server config

/var/app/
  .env ← API keys, DB connection strings
  src/config/database.ts ← DB credentials

Attack to Defense — Step by Step

Attack — Attacker's Payload
GET /files/download?name=../../../etc/passwd
Server — Vulnerable Code
const path = '/var/app/uploads/' + req.query.name;
res.sendFile(path); // ❌ No validation
Result
/etc/passwd contents streamed to attacker
Fix Step 1 — Resolve and validate
const resolved = path.resolve(UPLOAD_DIR, name);
if (!resolved.startsWith(UPLOAD_DIR)) throw 403;
Fix Step 2 — Sanitize filename
const safeName = path.basename(name); // strips all directories
Fix Step 3 — Allowlist
const allowed = /^[a-zA-Z0-9_.-]+$/.test(safeName);
if (!allowed) throw 400;
// ✅ Complete fix in Node.js / NestJS
import * as path from 'path';

const UPLOAD_DIR = path.resolve('/var/app/uploads');

async function downloadFile(name: string, res: Response) {
  // Step 1: Strip directory traversal
  const safeName = path.basename(name);

  // Step 2: Resolve full path
  const filePath = path.resolve(UPLOAD_DIR, safeName);

  // Step 3: Verify it stays within UPLOAD_DIR
  if (!filePath.startsWith(UPLOAD_DIR + path.sep)) {
    throw new ForbiddenException('Access denied');
  }

  // Step 4: Validate filename chars (optional belt+suspenders)
  if (!/^[a-zA-Z0-9_.-]+$/.test(safeName)) {
    throw new BadRequestException('Invalid filename');
  }

  res.sendFile(filePath);
}

  2. name = ../../../etc/passwd → what does path.basename() return?
  3. name = %2e%2e%2fetc%2fpasswd (URL-encoded) → what happens if you don't decode first?
  4. name = uploads/../../.env → does the startsWith check catch this?
  5. Write the regex pattern that allows ONLY letters, numbers, hyphens, underscores, and dots

Key Takeaways

  • ../ is the attacker's tool — never trust filename input directly
  • path.basename(name) strips all directory components — always do this first
  • path.resolve(dir, name).startsWith(dir) is the canonical guard
  • URL encoding bypasses naive string checks — Node's req.query auto-decodes, but be aware
  • Defense in depth: basename + startsWith check + allowlist regex — all three
