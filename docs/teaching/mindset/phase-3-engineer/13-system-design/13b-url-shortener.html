# Create short URL
POST /api/v1/urls
{
  "longUrl": "https://example.com/very/long/path",
  "alias": "my-link",      // optional
  "expireAt": 1800000000   // optional unix timestamp
}
→ 201 { "shortUrl": "https://sho.rt/abc1234" }

# Redirect
GET /:shortCode
→ 301 Location: https://original.long/url

# Why 301 not 302?
# 301 = permanent → browser caches, fewer hits to server
# 302 = temporary → every request hits server (needed for analytics)
# Choice depends on requirements — analytics vs performance
// MongoDB schema
{
  _id: ObjectId,
  shortCode: String,  // indexed, unique, 7 chars
  longUrl: String,
  alias: String,      // indexed, sparse (optional)
  createdAt: Date,
  expireAt: Date,     // TTL index — auto-deletes expired
  userId: ObjectId    // null for anonymous
}

// Indexes
{ shortCode: 1 }  // ← the critical one — every redirect hits this
{ alias: 1, sparse: true }
{ expireAt: 1, expireAfterSeconds: 0 }  // TTL auto-delete

// Why NoSQL?
// Simple key-value lookup, no joins, horizontal scale → document DB wins

Read path: Client → LB → API → Redis (hit: 1ms return) → DB (miss: fetch + populate cache) → Client. Redis hit rate target: 80%+ for popular URLs.

Short Code Generation — The Hard Part

ApproachHowProblem
MD5 hash → first 7 charsHash long URL, take prefixCollision: same URL → same code. Different URLs → rare collision possible
Auto-increment ID → Base62DB sequence → encode as [a-zA-Z0-9]Predictable (sequential). Single point for ID generation.
UUID → first 7 charsRandom UUID, take prefixCollision probability low but non-zero. No guarantee of uniqueness.
Snowflake ID → Base62Time+machine+sequence → uniqueComplex to set up. ✅ Globally unique, distributed, ordered

Practical choice for most: auto-increment + Base62 encoding with uniqueness constraint in DB. Retry on collision (extremely rare).

🔬 Exercise — Extend the Design

  1. Add analytics: track clicks per short URL, per country, per day. What changes?
  2. The DB can handle 10K QPS but you have 11,600 read QPS. How do you scale?
  3. A URL expires but the shortCode must never be reused. How do you implement this?
  4. Implement a "premium custom alias" feature. What's the API? What validation?
  5. A user pastes the same long URL twice. Should they get the same short code?

Key Takeaways

  • Read/write ratio dictates caching strategy — 10:1 → aggressive Redis caching
  • 301 vs 302 is a real trade-off: performance vs analytics. Name it explicitly.
  • Short code generation is the trickiest part — collision avoidance requires a strategy
  • TTL indexes (MongoDB) handle expiration automatically — no cron job needed
  • 7 Base62 chars = 3.5 trillion IDs — more than enough for any realistic use case
