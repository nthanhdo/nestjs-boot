Phase 4 14a

Docker Basics

Container vs VM, Dockerfile, và Layer Caching — nền tảng để đưa code chạy nhất quán ở bất cứ đâu.

1. Tại Sao Docker?

Câu cửa miệng của developer trước Docker: "works on my machine". Docker giải quyết vấn đề này bằng cách đóng gói ứng dụng cùng với mọi thứ nó cần — code, runtime, thư viện, config — thành một unit nhất quán chạy ở bất cứ đâu.

Core insight: Docker không virtualize hardware — nó virtualize OS. Kết quả: container nhỏ hơn VM hàng trăm lần, boot trong vài giây thay vì phút.

2. Container vs Virtual Machine

Hiểu sự khác biệt về kiến trúc để chọn đúng tool cho đúng job.

Virtual Machine

Hardware
OS Host (Linux/Windows)
Hypervisor (VMware/KVM)
Guest OS (toàn bộ kernel)
App + Dependencies
Size: 1–10 GB | Boot: 1–5 phút
Isolation: hoàn toàn (kernel riêng)

Docker Container

Hardware
OS Host (chia sẻ kernel)
Docker Engine
Container namespace
App + Dependencies
Size: 50–500 MB | Boot: 1–5 giây
Isolation: process-level (share kernel)

Khi nào dùng gì?

  • Docker: web apps, microservices, CI/CD pipelines, development environments
  • VM: khi cần OS khác (Windows app trên Linux server), full hardware isolation, legacy software

3. Dockerfile — Viết Instructions Tốt

Dockerfile là blueprint để build Docker image. Mỗi instruction tạo một layer. Layer không thay đổi được cache lại — đây là key để build nhanh.

# Dockerfile cho NestJS app # ═══ Stage 1: Builder ═══ FROM node:20-alpine AS builder # Set working directory WORKDIR /app # QUAN TRỌNG: copy package.json TRƯỚC source code # → layer npm install được cache nếu deps không đổi COPY package*.json ./ RUN npm ci --only=production # Copy source và build COPY . . RUN npm run build # ═══ Stage 2: Runner (nhỏ hơn, production only) ═══ FROM node:20-alpine AS runner WORKDIR /app # Chỉ copy những gì cần để chạy COPY --from=builder /app/dist ./dist COPY --from=builder /app/node_modules ./node_modules # Expose port và define entrypoint EXPOSE 3000 CMD ["node", "dist/main.js"]

4. Layer Caching — Tại Sao Quan Trọng

Docker cache mỗi layer. Khi một layer thay đổi, tất cả layers phía sau phải rebuild. Thứ tự COPY quyết định hiệu quả của cache.

FROM
node:20-alpine — base image (stable, ít thay đổi nhất)
✓ cached
WORKDIR
Set /app — không bao giờ thay đổi
✓ cached
COPY pkg
package.json — chỉ thay đổi khi add/remove dependency
✓ cached
RUN npm ci
Install deps — tốn 30-60s nhưng được cache nếu package.json không đổi
✓ cached
COPY . .
Source code — thay đổi thường xuyên → invalidate cache từ đây
✗ rebuild
RUN build
Compile TypeScript → phải rebuild mỗi lần
✗ rebuild
CMD
Entrypoint — phụ thuộc vào build
✗ rebuild
Anti-pattern phổ biến: COPY . . trước RUN npm install — mỗi lần thay đổi bất kỳ file source nào sẽ trigger npm install lại. Với 500+ packages, đây là hàng phút lãng phí mỗi build.

5. Commands Thiết Yếu

# Build image từ Dockerfile hiện tại docker build -t myapp:latest . docker build -t myapp:1.2.0 --no-cache . # bỏ cache # Chạy container docker run -p 3000:3000 myapp:latest docker run -d -p 3000:3000 --name my-api myapp # detached docker run --env-file .env myapp # inject env vars # Inspect và debug docker ps # containers đang chạy docker ps -a # tất cả containers docker logs my-api # xem logs docker logs -f my-api # follow live logs docker exec -it my-api sh # shell vào container # Image management docker images # list images docker image prune # xóa dangling images docker system prune -a # cleanup toàn bộ (cẩn thận!)
Bài Tập Thực Hành
Dễ Bài 1
Viết Dockerfile multi-stage cho Node.js app
Tạo Dockerfile 2-stage: builder (compile TypeScript) và runner. So sánh image size với single-stage. Target: runner image < 150MB.
Checklist:
1. Stage 1 AS builder: node:20-alpine, COPY package*.json, RUN npm ci, COPY . ., RUN npm run build
2. Stage 2 AS runner: node:20-alpine (fresh), COPY --from=builder dist + node_modules
3. So sánh: docker build -t single . && docker build -t multi -f Dockerfile.multi .
4. docker images | grep -E 'single|multi' — multi thường nhỏ hơn 60-70%
5. Verify: docker run -p 3000:3000 multi && curl localhost:3000/health
Trung bình Bài 2
Debug container crash bằng logs
Tạo lỗi có chủ đích (sai MONGO_URI, thiếu env var). Build image, chạy container, quan sát crash. Dùng docker logs để tìm root cause và fix.
Workflow debug:
1. docker run myapp → exit code non-zero
2. docker ps -a → xem Exited status
3. docker logs <container-id> → đọc error message cuối
4. Common: MongoServerError: Authentication failed → sai MONGO_URI
5. ECONNREFUSED 127.0.0.1:27017 → connect tới localhost không work trong container
6. Fix: truyền đúng env vars: docker run -e MONGO_URI=mongodb://host.docker.internal:27017/db myapp

Key Takeaway — 14a

Docker = đóng gói app nhất quán. Container nhỏ hơn VM 10x, boot nhanh hơn 100x. Multi-stage build = image nhỏ + bảo mật + deploy nhanh. Layer caching: thứ tự COPY quyết định tốc độ build.
