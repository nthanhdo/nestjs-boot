Docker Compose

Orchestrate multi-container stack bằng một file YAML — App + MongoDB + Redis + Monitoring chạy cùng nhau với một lệnh.

1. Tại Sao Cần Docker Compose?

Ứng dụng thực tế không chỉ là một container. Bạn cần: API server, database, cache, queue, monitoring... Docker Compose orchestrate tất cả chúng bằng một file docker-compose.yml.

2. docker-compose.yml Đầy Đủ

File compose cho NestJS app production-ready với MongoDB, Redis, và health checks.

services: # ─── Application ─────────────────────────────── app: build: context: . target: runner # multi-stage target ports: ["3000:3000"] environment: - NODE_ENV=production - MONGO_URI=mongodb://mongo:27017/mydb - REDIS_URL=redis://redis:6379 - JWT_SECRET=${JWT_SECRET} # từ .env file depends_on: mongo: condition: service_healthy # chờ mongo sẵn sàng redis: condition: service_started restart: unless-stopped healthcheck: test: ["CMD", "curl", "-f", "http://localhost:3000/health"] interval: 30s timeout: 10s retries: 3 # ─── Database ────────────────────────────────── mongo: image: mongo:7-jammy volumes: - mongo_data:/data/db # persist data healthcheck: test: ["CMD", "mongosh", "--eval", "db.adminCommand('ping')"] interval: 10s timeout: 5s retries: 5 # ─── Cache ───────────────────────────────────── redis: image: redis:7-alpine volumes: - redis_data:/data command: redis-server --appendonly yes # enable AOF persistence # ─── Named Volumes ───────────────────────────── volumes: mongo_data: {} redis_data: {}

3. Environment Files — Secrets Đúng Cách

Không bao giờ hardcode secrets vào docker-compose.yml. Dùng .env file + variable substitution.

# .env.example (commit vào git) JWT_SECRET=change-me-in-production MONGO_ROOT_USER=admin MONGO_ROOT_PASS=change-me # .env (gitignored — secrets thật) JWT_SECRET=super-secret-key-dont-share MONGO_ROOT_USER=admin MONGO_ROOT_PASS=Str0ngP@ssw0rd!
Quan trọng: Thêm .env vào .gitignore. Chỉ commit .env.example với placeholder values. Secret thật → GitHub Secrets hoặc Vault trong production.

4. Essential Commands

# Khởi động stack docker compose up -d # start all services (detached) docker compose up -d --build # rebuild image trước khi start docker compose up app mongo # start specific services only # Kiểm tra status docker compose ps # xem tất cả services docker compose logs app # logs của app service docker compose logs -f app mongo # follow multiple services # Maintenance docker compose down # stop + remove containers docker compose down -v # + remove volumes (xóa data!) docker compose restart app # restart một service docker compose exec app sh # shell vào service docker compose exec mongo mongosh # mongo shell # Scale (đơn giản) docker compose up -d --scale app=3 # chạy 3 instances của app

5. Override Files — Dev vs Production

Dùng override files để có config khác nhau cho từng môi trường mà không duplicate code.

# docker-compose.override.yml (dev) — auto-loaded services: app: volumes: - .:/app # mount source code để hot-reload command: npm run start:dev environment: - NODE_ENV=development # Production: docker compose -f docker-compose.yml up # Development: docker compose up (loads both files automatically)
Bài Tập Thực Hành
Dễ Bài 1
docker-compose.yml: NestJS + MongoDB + Redis
Viết file compose với 3 services. App phải kết nối được MongoDB và Redis. Chạy docker compose up -d và verify /health trả 200.
Checklist:
1. services: app (build: .), mongo (image: mongo:7), redis (image: redis:7-alpine)
2. app.depends_on: [mongo, redis]
3. app.environment: MONGO_URI=mongodb://mongo:27017/db, REDIS_URL=redis://redis:6379
4. volumes: mongo_data:/data/db (persist data qua restart)
5. Test: docker compose up -d && curl localhost:3000/health
Trung bình Bài 2
Thêm health checks + depends_on condition
Extend file compose để app chỉ start khi MongoDB đã healthy. Thêm healthcheck vào mongo service. Verify bằng cách docker compose ps — app phải chờ mongo healthy.
Mongo healthcheck:
test: ["CMD", "mongosh", "--eval", "db.adminCommand('ping')"]
interval: 10s, timeout: 5s, retries: 5

App depends_on:
mongo: condition: service_healthy

Kết quả: docker compose up -d → app container chờ cho đến khi mongo healthy trước khi start
Khó Bài 3
Dev vs Production override setup
Tạo docker-compose.yml (production base) và docker-compose.override.yml (dev additions). Dev mode: source code mounted, hot-reload enabled. Production: no volume mounts, restart policy. Verify behavior khác nhau của 2 modes.
Base (production): image: myapp:latest, restart: unless-stopped, no volumes
Override (dev): build: ., volumes: [.:/app], command: npm run start:dev

Run dev: docker compose up (loads base + override)
Run prod: docker compose -f docker-compose.yml up (loads base only)

Verify dev: thay đổi source code → reload tự động không cần rebuild

Key Takeaway — 14b

Docker Compose = orchestrate multi-service stack bằng một lệnh. Services trong cùng network giao tiếp bằng service name (không phải localhost). Health checks + depends_on = startup order đúng. Override files = DRY config cho nhiều môi trường.
