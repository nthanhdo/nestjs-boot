3. Prompting for Code — Good vs Bad

Chất lượng prompt quyết định chất lượng output. "Garbage in, garbage out."

❌ Prompt tệ
Write a function to handle users
→ AI đoán mò, tạo ra code generic, không fit codebase của bạn. Có thể cần rewrite hoàn toàn.
✓ Prompt tốt
I'm using NestJS + TypeORM + PostgreSQL. Create a UserService method: - Input: CreateUserDto { email, name, role } - Check email duplicate → throw ConflictException - Hash password with bcrypt (10 rounds) - Return UserEntity (exclude password field) - Add JSDoc comments
→ AI có đủ context để tạo code chính xác, fit stack, ít cần sửa.

5. Hallucination — AI Tự Tin Sai

AI có thể generate code trông đúng nhưng sai — package không tồn tại, API đã deprecated, logic sai. Luôn verify.

// AI generates this confidently... ❌ import { validateEmail } from '@nestjs/common/utils/email'; ✗ không tồn tại // Uses deprecated MongoDB method... await collection.insert(doc); ✗ deprecated từ MongoDB 4 // Wrong HTTP status code... throw new HttpException('Not found', 401); ✗ nên là 404 // Developer catches it, fixes it ✅ import { isEmail } from 'class-validator'; ✓ correct await collection.insertOne(doc); ✓ current API throw new NotFoundException('Resource'); ✓ 404
Hallucination phổ biến nhất: Package names không tồn tại, deprecated API, wrong method signatures, outdated syntax (AI training data có cutoff), logic bugs trong edge cases.

6. AI-generated Security Risks

AI có thể suggest code chạy được nhưng không secure. Đây là loại bug nguy hiểm nhất vì không crash ngay.

❌ AI suggests — SQL Injection
// "Works" but dangerous! const query = ` SELECT * FROM users WHERE email = '${email}' `; // Attacker: email = "' OR '1'='1" // → dumps entire DB
✓ Correct — Parameterized
// Safe! Parameters escaped const result = await db.query( 'SELECT * FROM users WHERE email = $1', [email] ); // DB driver handles escaping

Security checklist khi dùng AI-generated code

  • 🔍SQL/NoSQL queries — dùng parameterized hay ORM, không string concat
  • 🔍Password — bcrypt/argon2, không MD5/SHA1 plain
  • 🔍JWT secret — environment variable, không hardcoded
  • 🔍Input validation — validate mọi user input trước khi process
  • 🔍Error messages — không expose internal details cho user
  • 🔍Dependencies — check CVE của package được suggest

7. Context Engineering

AI giỏi hơn khi có context tốt hơn. "Context Engineering" = nghệ thuật cung cấp đúng context cho AI.

// ❌ Thiếu context — AI đoán mò "Create a service to handle orders" // ✓ Đủ context — AI tạo code fit "I'm building a NestJS microservice. Existing code uses: - MongoDB with Mongoose - Event-driven: OrderCreatedEvent - Pattern: CQRS (commands/queries separate) - All DTOs use class-validator Create OrderCommandService with: - createOrder(dto: CreateOrderDto) - Emit OrderCreatedEvent after save - Validate: items array non-empty - Return OrderDocument"
Pro tip: Paste đoạn code hiện có vào prompt. "Here is my existing UserService pattern. Follow the same pattern for OrderService." — AI sẽ copy style, naming, error handling của bạn.

8. The Verification Loop

Never Trust, Always Verify. Với AI-generated code, verification là bước bắt buộc, không phải tùy chọn.

  • ①Understand: Đọc và hiểu từng dòng code AI generate
  • ②Test: Chạy với input thực, test edge cases, check logs
  • ③Verify: Kết quả có đúng với requirements không?
  • ④Review: Security, performance, maintainability

9. The Right Mindset

✅ "Productivity tool with guardrails"

  • Dùng AI để accelerate — tạo boilerplate, explain concepts, suggest patterns
  • Luôn review và adapt code vào codebase của mình
  • Test kỹ trước khi commit
  • Chịu trách nhiệm 100% với code mình commit, dù AI viết

❌ Anti-pattern: Blindly Accept AI Output

  • Copy-paste AI code mà không đọc → bugs vào production
  • Dùng AI giải quyết bug mà không hiểu root cause → bug tái phát
  • Để AI quyết định architecture → technical debt khổng lồ
  • Nói "AI generate" khi bị hỏi về code → không chuyên nghiệp
// ❌ Scenario thực tế // Dev A: "Tại sao function này có bug?" // Dev B: "Tôi không biết, AI generate" // → Dev B không hiểu code mình commit // → Team mất trust

🎯 Exercise: AI-Assisted Code Review

Thực hành identify vấn đề trong AI-generated code

  • ①Dùng AI generate một REST API endpoint (create + get + delete user)
  • ②Review code — tìm ít nhất 3 vấn đề (security, missing validation, style)
  • ③Fix các vấn đề, viết unit test cho edge cases
  • ④Thử prompt xấu vs prompt tốt — so sánh chất lượng output
  • ⑤Document: những gì AI làm tốt, những gì phải sửa
Key Takeaway: Kỹ sư dùng AI giỏi nhất không phải người dùng AI nhiều nhất — mà là người biết khi nào dùng AI, khi nào không, và luôn verify output.
