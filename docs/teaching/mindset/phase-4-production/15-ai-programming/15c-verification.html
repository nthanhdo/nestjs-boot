Phase 4 15c

Verification + Hallucination

AI tự tin sai. Không phải tệ — đây là bản chất của LLM. Biết verify đúng cách = bảo vệ code của bạn khỏi confident-but-wrong AI output.

1. Hallucination Là Gì?

AI generate code trông đúng nhưng sai. Package không tồn tại, API deprecated, method signature sai, logic bug ở edge case. AI không "biết" nó sai — nó generate confident text.

AI generates confidently — nhưng có 3 lỗi:
import { validateEmail } from '@nestjs/common/utils/email'
✗ Không tồn tại
await collection.insert(doc)
✗ Deprecated từ MongoDB 4
throw new HttpException('Not found', 401)
✗ Nên là 404
Developer catches và fixes:
import { isEmail } from 'class-validator'
✓ Đúng
await collection.insertOne(doc)
✓ Current API
throw new NotFoundException('Resource')
✓ 404 đúng
Hallucination phổ biến nhất: Package names không tồn tại, deprecated API methods, wrong method signatures, outdated syntax, logic bugs trong edge cases, wrong HTTP status codes.

2. The Verification Loop — 4 Bước

Never Trust, Always Verify. Áp dụng cho mọi AI output trước khi commit.

①
UNDERSTAND — Đọc từng dòng
Không chỉ "code chạy không?". Hiểu logic của từng bước. Nếu không giải thích được đoạn code → đừng commit nó.
②
TEST — Chạy với real input
Test happy path + edge cases (null, empty, boundary values). Nếu AI tạo ra function → viết unit test cho nó trước khi integrate.
③
VERIFY — Package và API tồn tại không?
Mọi package được import: check npm registry. Mọi method: check official docs. Đừng assume API tồn tại chỉ vì AI dùng nó.
④
REVIEW — Security và logic
Check: input validation, error handling, no hardcoded secrets, no obvious logic bugs. Chi tiết ở bài 15d.

3. Verification Checklist Thực Tế

Trước khi commit bất kỳ AI code nào

  • ①Packages: Mọi import → verify trên npmjs.com
  • ②API methods: Check official docs (không phải AI docs)
  • ③Logic: Trace through manually với 3 input scenarios
  • ④Edge cases: Null, empty, negative, boundary values
  • ⑤Error types: NestJS exception classes đúng (NotFoundException, BadRequestException...)
  • ⑥Tests pass: Unit tests xanh trước khi push

4. Dùng AI để Verify AI

Một trick hữu ích: dùng prompt mới để review code AI vừa generate.

"Review this code for potential issues: [paste generated code] Check for: 1. Package names that might not exist 2. Deprecated APIs (NestJS v10, Mongoose v8, MongoDB Node.js driver v6) 3. Missing error handling 4. Security issues (injection, hardcoded values) 5. Logic bugs in edge cases (null input, empty array, concurrent calls)"
Không hoàn hảo nhưng hữu ích: AI review AI có thể catch một số issues mà bạn miss. Không thay thế human review — bổ sung thêm một layer. Final judgment luôn là của bạn.
Bài Tập Thực Hành
Dễ Bài 1
Review AI-generated UserService: tìm ít nhất 3 vấn đề
Prompt AI tạo UserService với createUser, findAll, deleteUser. Review output và liệt kê ít nhất 3 vấn đề cụ thể với giải thích tại sao mỗi vấn đề là vấn đề.
Vấn đề thường gặp trong AI-generated UserService:
1. Password không được hash (plain text lưu DB) — security risk
2. findAll() không có pagination → memory leak với large dataset
3. deleteUser không check ownership → user A có thể xóa user B
4. Throw Error() thay vì NotFoundException/ConflictException
5. Missing @IsEmail() validation trong DTO
6. No transaction khi cần atomic operation
Trung bình Bài 2
Generate function → viết tests → fix failures
Prompt AI tạo discount calculator (VIP -20%, weekend +10%, min $5). Viết unit tests cho 5+ cases. Khi test fail → AI code có bug → fix và document bug found.
Test cases cần viết:
- VIP weekday: -20% ✓ (thường đúng)
- Regular weekend: +10% ✓ (thường đúng)
- VIP weekend: ưu tiên rule nào? AI thường đoán sai
- Price sau discount < $5 → return $5 (min floor)
- Input = 0 → return 0 hay $5?
- Input = negative → throw hay 0?

AI thường fail: VIP+weekend case và min price floor case.
Khó Bài 3
Verify hallucinated packages trong AI output
Prompt AI tạo complex NestJS service. List mọi package được import. Verify mỗi package: tồn tại trên npmjs.com? Version hiện tại? Method AI dùng có trong API không? Document findings.
Verification workflow:
1. Extract all imports vào list
2. npmjs.com → search package → check weekly downloads (thấp = suspect)
3. GitHub repo → check last commit (abandoned?)
4. Official docs → ctrl+F method name AI used
5. Paste error vào terminal nếu package install fail

Common hallucinations: @nestjs/common/utils/* subpaths, non-existent mongoose methods, outdated package names

Key Takeaway — 15c

Hallucination không phải lỗi của AI — đây là bản chất LLM. Verification loop 4 bước: Understand → Test → Verify → Review. Kiểm tra mọi package, mọi API method. Tests là cách verify hiệu quả nhất. Code ownership = verification responsibility.
