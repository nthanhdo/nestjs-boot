📊 Product Metrics & Funnel

"If you can't measure it, you can't improve it." Engineer cần hiểu metrics để biết feature mình build có tác động thực sự hay không.

🔽 Conversion Funnel

Funnel = hành trình user từ lạ → paying customer. Mỗi bước đều có drop-off. Engineer cần ensure tracking events đúng ở mỗi step.

👁️ Impressions / Reach 10,000 visitors
↓ 30% sign up
📝 Sign-up 3,000 registered
↓ 60% activate
✅ Activation (dùng core feature) 1,800 activated
↓ 40% return D7
🔁 Retention (D7) 720 returned
↓ 5% convert
💰 Paid Conversion 36 paid
Engineer's role: Đảm bảo tracking events được fire đúng ở mỗi step. Sau deploy feature mới → check funnel numbers. Nếu không di chuyển như expect → bug hoặc wrong feature.

📈 Key Metrics — Đo Cái Gì?

Growth Metrics

  • DAU/WAU/MAU — active users mỗi ngày/tuần/tháng
  • Sign-up rate — % visitors đăng ký
  • Activation rate — % users dùng core feature
  • Viral coefficient — mỗi user mang bao nhiêu user mới

Health Metrics

  • Retention D1/D7/D30 — % quay lại sau 1/7/30 ngày
  • Churn rate — % users rời đi mỗi tháng
  • NPS — user satisfaction score
  • Error rate — % requests fail

Revenue Metrics

  • MRR/ARR — Monthly/Annual Recurring Revenue
  • ARPU — Average Revenue Per User
  • Conversion rate — free → paid
  • LTV — Lifetime Value of customer

Technical Metrics

  • P95 latency — 95th percentile response time
  • Uptime % — 99.9% = 8.7h downtime/year
  • Error rate — 5xx responses / total
  • Deploy frequency — cadence of shipping

🌳 Decision Tree — Should We Build This?

❓ Feature: "Thêm dark mode cho app"
✓ Build nếu:
• >30% users đã request
• Accessibility requirement
• Low effort (S/M, CSS vars ready)
• Competitors đã có
→ Add to next sprint backlog
✗ Skip nếu:
• Chỉ 1-2 người mention
• Core problems chưa solved
• High effort (cần CSS refactor)
• No data backing demand
→ Backlog / decline with reason
🎯 Bài Tập Thực Hành
🟢 DễBài 1
Define 5 KPIs cho e-commerce app — tên, cách đo, target
Cho một e-commerce app (catalog + cart + checkout). Define 5 KPIs quan trọng nhất: tên metric, cách đo (công thức), target value, và tại sao metric đó quan trọng với business.
1. Conversion Rate = Orders/Sessions × 100%. Target: ≥2%. Vì: revenue metric cốt lõi
2. Cart Abandonment Rate = (Carts - Orders)/Carts × 100%. Target: <70%. Vì: UX friction indicator
3. Average Order Value = Total Revenue/Total Orders. Target: grow 10%/quarter. Vì: revenue efficiency
4. Page Load Time P95. Target: <2 seconds. Vì: every 100ms slower = -1% conversion
5. Search Zero Results Rate = Searches returning 0/Total searches. Target: <5%. Vì: catalog gap signal

Bonus: track DAILY, review weekly. Alert if any metric deviates >10% from baseline
🟡 Trung bìnhBài 2
ROI analysis: 3 feature requests — priority rank với lý do
Rank theo priority và justify: (A) Fix search showing wrong results (bug, S effort, high user complaint), (B) Add dark mode (M effort, 3 users requested), (C) Add AI product descriptions (XL effort, business thinks it differentiates). Context: conversion rate is dropping this week.
Priority:
1. P0: Fix search bug — Conversion dropping + search showing wrong results = direct causal link. S effort + high impact = ship now
2. P2: AI descriptions — XL effort but could differentiate if done well. Needs research first: "What specific user problem does it solve?" and POC
3. Backlog: Dark mode — 3 users ≠ demand signal. M effort for unclear ROI when conversion is the priority

Key insight: when core metric is hurting → fix core problems first. Nice-to-haves can wait

Communicate: "Dark mode is noted. When search is fixed and conversion stabilizes, we'll revisit with proper demand signal (user survey)."
🔴 KhóBài 3
Build a metrics dashboard — define tracking events cho authentication flow
Design tất cả tracking events cần thiết cho auth flow (register → verify email → first login → complete profile). Mỗi event: tên, khi nào fire, properties cần capture, metric nó feeds vào. Sau đó: identify top 3 metrics cần monitor weekly.
Events:
1. signup_started — when form first touched. Props: source (organic/referral), device
2. signup_completed — on success. Props: method (email/oauth), referral_code
3. email_verification_sent — props: timestamp
4. email_verified — props: time_to_verify (minutes between sent and verified)
5. first_login — props: time_since_signup, method
6. profile_completed — props: fields filled (%)
7. signup_abandoned — if user starts but leaves. Props: last_field_interacted

Top 3 weekly metrics:
1. Email verification rate (signup_completed → email_verified). Target: ≥70%
2. Time to verify (median). Target: <5 minutes
3. Signup abandonment rate by field (tells you which field causes friction)

These three tell you where the funnel is leaking in acquisition

📌 Tóm Tắt — Metrics

  • Funnel = Impressions → Sign-up → Activation → Retention → Paid. Engineer đảm bảo tracking đúng
  • 4 metric categories = Growth + Health + Revenue + Technical
  • ROI thinking = mọi feature = (User Value × Business Value) / Effort. Priority theo đây
  • Decision tree = data-driven build/skip/defer. Không theo feeling hoặc 1 user request
  • Define metrics BEFORE building — nếu không biết thành công là gì, không biết feature có work không
